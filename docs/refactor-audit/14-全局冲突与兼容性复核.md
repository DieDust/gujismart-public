# 14 全局冲突与兼容性复核

## 1. 本章结论

各模块方案可以兼容，但必须按本章裁决实施。最重要的统一点是：全仓只保留一套任务状态与物理 scheduler、一套 canonical page content、一套 stable locator、一套 CredentialVault、一套搜索 snapshot/aggregate/evidence 分层、一套研究 evidence/output lineage、一套文件 capability 与原子产物边界，以及一个本地验收后才能公开的发布门禁。

模块文档中曾保留的选择空间在这里关闭：导入不再单独建立 `import_jobs/import_items`；顶层状态不允许 `failed/cancelled/partial` 平行枚举；阅读器、检索、AI、翻译和导出不能各自计算“当前正文”；SearchSnapshot、ResearchAggregateArtifact、ResearchEvidence 和 ResearchOutput 不能互相代替；renderer 不能把任意路径当成已授权文件；翻译、引用、导出和 TeX 不能直接覆盖人工内容或最终文件；高对比不是第三种文献类型；旧 public 目录不是发布事实来源。

数据库优先兼容，但“零迁移”不是阻止必要正确性结构的理由。CredentialVault、唯一 scheduler、不可变 artifact/version/manifest、必要唯一约束和安全备份属于已证明有显著收益的 additive 迁移候选；它们必须在用户数据库副本上完成预检、备份、幂等、故障注入、回滚和恢复演练后才能进入本地成品。

## 2. 复核方法

本章对模块 01 至 13 逐章重新核对以下内容：

- 同名状态、字段、DTO、设置、IPC、数据库表和文件格式是否含义一致；
- 导入、OCR、校对、阅读、搜索、AI、翻译、引用和导出是否读取同一 active 内容；
- 长任务、短请求、迁移和维护是否重复实现 claim/lease/cancel/retry；
- 人工内容、候选、active、stale、partial、unavailable 和 error 是否被错误混用；
- 性能优化是否引入无界内存、静默截断、长事务或数据丢失；
- 古籍和现代论文 preset 是否改变正确性、隐私或证据门禁；
- 新功能是否重复已有能力、暗示云同步或绕过用户确认；
- 新版验收、数据库兼容、依赖审批和公开门禁是否能同时成立。

冲突裁决优先级固定为：用户明确约束 > 数据/凭据安全 > canonical 正确性和人工保护 > 可恢复性 > 兼容性 > 性能 > 便利性和视觉偏好。

## 4. 冲突裁决

### C14-01 顶层任务状态与 partial

**冲突：** 现有代码和旧脚本混用 pending/processing/failed/cancelled/partial，部分页面又把 stale、permission-required 或 review 当成任务状态。

**裁决：** 顶层只使用模块 01 的闭合 `TaskStatus`。`partial` 表达为 `completed + completionKind='partial'`；credential/budget/review/permission 阻塞表达为 `paused + blockedReason/recoveryAction`；pausing/canceling 是瞬时 commandState；stale/verification/capability 是正交轴。旧值只在 main adapter 兼容读取，不能继续写入新表。

### C14-02 唯一 scheduler 与领域任务表

**冲突：** 模块 02 曾保留 `import_jobs/import_items` 或通用表两种可能，OCR、搜索、AI、翻译和维护也各有旧队列/设置状态。

**裁决：** 物理实现固定为通用 `task_jobs/task_items` 加 lease/attempt/event/artifact 引用；模块 02 拥有调度核心，模块 03 首先接入并验证。领域可有 `ocr_runs`、translation units、research runs 等事实表，但不得保存第二份 claim/lease/status/cursor 真相。旧 IPC 暂时适配同一 job。

### C14-03 设置、provider 与凭据

**冲突：** settings 既保存普通配置又明文保存三类 Key，renderer/getAll/备份能读回；模块 03/07/11 分别提出安全方案。

**裁决：** typed settings service 拥有普通配置和 public profile；CredentialVault 是同一 main-only 服务的受保护子系统，使用 Electron safeStorage 与 versioned sidecar/journal。SQLite 只保存 entry/version/state。模块 07 只定义 request ephemeral lease 和 durable job pin；模块 11 只负责 sidecar 排除、credential-required 恢复状态和历史备份脱敏，不复制 vault。

### C14-04 canonical 正文与人工优先级

**冲突：** pages inline text、外置 payload、OCR versions、人工校对、PDF text、EPUB section、AI layout 和 translation 各有读取路径；部分现有阅读器会让旧 OCR 覆盖人工内容。

**裁决：** 页面正文唯一入口为模块 03 `CanonicalContentProvider.resolvePage(...)`。active confirmed proof 优先，随后 active OCR artifact，再到 source fallback；结构化 IR、blocks 和纯文本是同一 artifact 的投影。翻译不是原文版本，AI layout 不是 canonical text。任何重跑、空结果或导入目录都先生成候选，不直接覆盖 active/人工层。

### C14-05 locator 与 offset

**冲突：** 阅读状态、目录、搜索、摘录、翻译、引用和 AI 使用 page index、virtual page、segment ordinal、字符 offset、首词猜测等近似身份。

**裁决：** 模块 05 的 `StableReaderLocator` 是唯一长期定位基类，保存 source kind、稳定来源 ID、contentVersion/sourceHash、offsetUnit/source ranges、quote/prefix/suffix 等 variant 必填项。搜索匹配信息另存 `SearchMatchMetadata`；translation 指向 unit/source slice；无法验证只返回 page/document precision 或 unresolved，不能伪造 charStart=0/exact。

### C14-06 SearchSnapshot、aggregate、evidence 与 output

**冲突：** 页面缓存、保存检索、facet 统计、证据篮、AI evidence pack、研究 record 和报告 snapshot 都被称为“快照”。

**裁决：** `SearchSnapshot` 是带 TTL/generation 的执行期查询视图；`ResearchAggregateArtifact` 是正式采用的不可变统计；`ResearchEvidence` 是可验证来源证据；record 是用户/AI 提取并复核的结构化解释；output 是带 input coverage/claim manifest 的不可变文本版本。四者分别存储和验收，禁止将 TTL cache、代表片段、pending record 或 renderer payload 冒充正式 provenance。

### C14-07 evidence、note、bookmark 与 project

**冲突：** 阅读摘录、搜索保存、证据篮、问题书签和多个专题可能复制相同 quote，现有 note 去重又可能阻止一个证据服务多个专题。

**裁决：** canonical evidence 本体唯一，项目关系保存独立 kind/tags/comment/outline/review；问题书签的 workflow metadata 放旁路 relation，不塞进 locator 或未知 note kind。解除一个项目关系不删 evidence；永久删除必须列出全部引用项目并进入回收站。

### C14-08 active、candidate、history 与人工内容

**冲突：** OCR、目录、标签归一化、AI 记录、翻译和报告都有自动结果，部分路径用“最新”或空结果直接覆盖 active。

**裁决：** 自动结果默认 candidate；人工确认创建/切换 active version。人工校对、目录、标签、实体和研究判断优先。失败/空结果不改变 active；回滚切指针，不删除历史。可变 title/status 与不可变内容版本分离。

### C14-09 scope、筛选与集合语义

**冲突：** folder/tag/project/search scope 在不同模块有 AND/OR、后代、前 1000 条和当前页二次过滤差异。

**裁决：** scope/criteria 使用版本化 shared AST 和 execution-time generation；标签多选、文件夹后代、排除、原文/译文语义由模块 04/06 定义。renderer 不把已加载页当全部；AI/导出消费冻结 scope snapshot，不重算近似 ID 集合。

### C14-10 无限总量与有界资源

**冲突：** 用户要求文献/任务逻辑上无限，现有代码又有 20/60/200/1000 等静默阈值；部分方案可能误解为所有单次请求也无限。

**裁决：** 产品不限制可接收文献、文件、页、命中、任务、record、output 或 workspace/tab descriptor 总量；每次 SQL/IPC、renderer window、worker batch、active concurrency、prefetch、cache，以及启动时同时激活/暖恢复的标签数量必须有界。全部 descriptor 仍须通过 cursor/搜索可达；任何 top K 必须返回 total/truncated/continuation 或提供搜索/分页，不能声称完整。

### C14-11 保存、冲突、破坏性操作与 undo

**冲突：** 多个页面先显示成功再等待 IPC，或只在 renderer 保存临时 undo；同名文件夹合并、删除研究节点、恢复备份等缺少权威影响预览。

**裁决：** main command 校验 expected revision/content hash，返回 committed result 或 typed conflict。破坏性操作先取得 main 生成的 OperationPreview，确认时提交 previewId/contextHash；完成返回 operationId/undoUntil。toast/本地 state 不能冒充已提交或可撤销。

### C14-12 内容 preset、主题和阅读偏好

**冲突：** “古籍/论文/高对比三 preset”会把内容类型、色彩和 accessibility 混成互斥选项；workspace 主题也可能覆盖单篇阅读偏好。

**裁决：** 内容 preset（古籍/论文/自定义）、color scheme（system/light/dark）、contrast、density、UI font、reader theme/font、OCR recipe、privacy policy 正交。preset 只给默认值，用户覆盖优先；旧用户默认沿用当前行为。任何组合都不能降低证据、人工保护或隐私门禁。

### C14-13 导入格式与“支持”定义

**冲突：** 选择器列出 MOBI/AZW/AZW3，但导入固定失败；欢迎页又只提 PDF/图片/扫描件。

**裁决：** “支持格式”只指可直接解析并完成持久化的格式；待转换格式进入单独转换说明/候选流程，不进入必失败队列。格式能力由模块 02 shared capability 返回，欢迎页、选择器、教程和测试共同消费。

### C14-14 数据库迁移与大库

**冲突：** 多章提出新表/索引，也强调尽量零迁移；现有启动维护对大库会永久 skip，部分旧数据清理又先删后验。

**裁决：** 可由 typed settings/adapter 表达的 MVP 默认零迁移；安全、正确性、唯一 scheduler、immutable lineage 和关键索引允许 additive 迁移。每项必须有 owner、migration ID、预检、空间估算、自动备份、短事务/小批 cursor、heartbeat、apply twice、foreign_key_check、row/hash 校验、故障注入、失败回滚和旧版兼容。大库只能降低批次/优先级，不能永久跳过。

### C14-15 测试、截图与公开资产

**冲突：** 大量现有回归只匹配源码字符串，教程截图已漂移；自动更新 snapshot 又可能固化错误或泄露用户材料。

**裁决：** 源码合同测试只保留分层/禁止项；正确性使用纯函数、main/SQLite、Electron renderer、故障注入、固定机器性能和 Windows 人工验收分层。审阅证据、视觉 golden、公开教程图分开；公开资产只使用合成或许可证清晰 fixture，CI 只上传 diff，不自动接受新 golden。

### C14-16 事实来源与公开门禁

**冲突：** 仓库中存在旧 public 历史目录概念，CI/Release 当前顺序也可能先构建/打包再完整验收。

**裁决：** 当前仓库根目录是开发、打包和公开的唯一事实来源；旧的历史目录不参与基线。发布候选必须先在同一 commit 完成新版验收、build、smoke、Windows 包和用户本地测试；维护者明确批准公开后，才允许 push、PR、Actions、tag 或 Release。

### C14-17 新依赖、模型与服务审批

**冲突：** 各章分别建议 watcher、diff、字库、embedding、NER、图表、axe、云同步等，容易把一项批准扩张为整类授权。

**裁决：** 每个候选独立审批，材料必须包含收益、现有替代、许可证、维护、Windows/原生模块、包体、CPU/GPU/RAM、网络/隐私、离线、数据格式、升级/卸载、失败回退和开源 NOTICE。用户确认只覆盖该候选和说明范围。第一阶段不以新增依赖为正确性前提。

### C14-18 文件 capability、规则输入与 TeX 隔离

**冲突：** 导入、引用规则分析、导出、排版和研究交换都接收路径；现有文献/页面更新与 PDF 仓库接口可让 renderer 自行授权任意路径，删除文献还会递归删除未证明属于托管区的外部路径；规则文件入口可让 main 读取 renderer 提供的任意路径，TeX 的 `docId`/源码又参与目录和外部编译。普通文件选择、已授权读取、托管资产 ownership、破坏性清理和可执行文档被混成同一权限。

**裁决：** 模块 01 的 main-only file-access service 唯一签发 opaque `FileCapability`，绑定规范化路径、用途、读/写方向、TTL、大小/类型预算和用户手势；每次消费重新校验 realpath、symlink 与目录边界。模块 11 统一记录 `managed|external|repository` ownership；只有 canonical realpath 严格位于 `data/storage/<docId>/` 的 managed 资产允许递归删除，外部路径永远只解除引用。模块 10 的 TeX 每 attempt 使用不可预测的受管目录，docId 不进入路径；禁用 shell escape/网络和越界读写，编译结果以 exit code、fresh hash 和 manifest 校验。选择文件不等于允许上传，外传仍需模块 07 的内容预览与确认。

### C14-19 翻译、引用、导出和写作版本身份

**冲突：** 翻译 cache/unit、引用字符串、导出格式、排版 artifact 和写作 output 各自冻结不同字段；provider 迟到结果可能覆盖人工译文，缺字段引用仍可看似完整，多数导出直接写最终路径，摘录正文变化后还能继承旧 source hash/locator。

**裁决：** 翻译写入必须 CAS `unitRevision + canonical contentVersion/sourceHash + contextHash`，人工译文优先；`CitationResolver` 返回字段 provenance/diagnostics 和版本化 `CitationSnapshot`；所有导出先冻结 `ExportSnapshot`，经唯一 `AtomicExportWriter` 写 attempt 临时文件、flush、解析/计数/hash 校验后原子替换，失败保留旧目标。摘录正文或页码变化创建新 revision 并重新验证 locator，不能继承旧 verified 身份；写作只引用冻结 evidence/citation/output lineage。

### C14-20 当前发布冻结、公开图片与许可证闭包

**冲突：** 模块 12 逐图确认 9 张 README 截图含实际文库、摘录、来源标识或受限正文，文本型 `check:opensource` 无法发现；现有安装包又缺项目 LICENSE/NOTICE/THIRD_PARTY，而 Release workflow 可在 tag 后直接公开。

**裁决：** 当前 commit 明确为 non-releasable。用许可清晰、固定 seed 的古籍/论文合成 fixture 重拍全部公开大图，并对 tracked 图片做 OCR/metadata/人工复核；Setup/Portable 必须离线携带项目和第三方许可证、SBOM/vendor manifest 与 hash。候选构建和 publish 权限分离，先完成 packaged smoke、安装/升级/卸载、本地 RC manifest 和用户明确批准；历史远端处置、push、tag、Actions、draft/public Release 均需另行授权。

### C14-21 workspace snapshot、领域草稿与关闭协调

**冲突：** 模块 09 需要恢复 tabs/view state，但正文、校对、研究、搜索和任务已有各自权威状态；把全部页面 state 写入 workspace 会复制业务真相，而只保存 descriptor 又不能保护 dirty draft。现有 Esc/窗口关闭还可绕过设置与阅读保存。

**裁决：** 模块 09 只拥有 shell descriptor、command/focus/selection、interaction generation 和轻量 `viewStateRef`；snapshot 不得保存正文、校对草稿、evidence、secret、完整 search result 或任务游标。领域 durable draft/version、operation receipt/undo 与 main 提交仍由对应 owner 管理。workspace v2 使用新 key、last-known-good、write-then-read 验证并保留 v1/future/损坏原 bytes；总 descriptor 可搜索恢复，warm DOM 有界。Esc 只取消顶层 interaction，显式退出必须经唯一 CloseCoordinator 收集领域 `clean|saved|failed|needs-confirmation` 后决定是否关闭。

## 5. 数据与迁移顺序

建议的唯一顺序如下，后一步不得绕过前一步另建临时真相：

1. 冻结破坏性启动清理；建立可靠 backup snapshot/manifest、恢复 staging 和历史备份保护。
2. 建立 typed settings 与 CredentialVault，迁移明文 protected keys；普通备份排除 sidecar。
3. 建立 shared TaskStateEnvelope/ErrorEnvelope/SettingDefinition 和运行时校验。
4. additive 建唯一 `task_jobs/task_items` 与 lease/attempt/event/artifact 引用，桥接旧队列。
5. 建 OCR run/attempt/artifact 与 CanonicalContentProvider，保护人工校对和 active 指针。
6. 建 StableReaderLocator/reader adapter，随后迁移搜索 resolver、摘录、引用和 AI evidence。
7. 建 search generation/snapshot/aggregate；持久索引任务接入 scheduler。
8. 建 ResearchEvidence/record review/output/coverage/claim lineage 和项目完整性约束。
9. 建 FileCapability、翻译 CAS/context、CitationSnapshot、ExportSnapshot/AtomicExportWriter 和研究写作投影。
10. 建合成 fixture、包内许可证/SBOM、packaged smoke 与本地 RC manifest，解除 non-releasable 前不得公开。
11. Gate 0 同步完成 CloseCoordinator/Esc、latest-request guard、drag cancel 和 workspace 无损写入等零 schema 交互安全修复；其余完整 workspace/UI/产品 epic 最后实施，不在 renderer 建临时数据库真相。

### 5.1 实施顺序第 4 步结果（2026-07-11）

- 第 4 项已落地通用物理 scheduler：`task_jobs/task_items/task_attempts/task_events/task_artifacts`、闭合六态、幂等键、bounded claim、lease/heartbeat、cursor、retry、event 与不可变 artifact 引用。
- 模块 03 的 legacy batch OCR 是第一个真实执行接入；模块 02 的 renderer 导入队列只完成兼容身份登记，逐文件执行迁移仍在后续切片。
- 旧 `batch_queue` 和 `library_import_queue_state` 保留，作为旧 IPC/旧版本投影；重复桥接使用稳定 key，不复制任务，不删除用户旧行。
- 尚未迁移的搜索、AI、翻译、导出、备份和维护只能复用现有 scheduler，禁止自行新增物理队列或把 settings JSON 变成第二份 lease/cursor 真相。
- 本步是显式批准的 additive 迁移：没有新依赖，已覆盖旧库重复初始化、约束、幂等、租约故障、事务回滚与兼容桥。公开门禁不变，仍需全部本地重构完成并由用户验收。

### 5.2 实施顺序第 5 步结果（2026-07-11）

- 第 5 项已落地唯一 `CanonicalContentProvider` 和 OCR run/attempt/artifact/active pointer；`CONS-04` 的页面正文优先级及首批跨模块消费者已经实现。
- 人工校对只在 `proof_status='completed'` 时成为正式正文；OCR 重跑、空结果或版本切换不得删除人工层，只能将其基线标 stale。
- 阅读器 DTO、搜索命中回填、AI、翻译和导出已接入统一 provider；旧 `pages` 与 `page_ocr_versions` 继续兼容读取，不做破坏性回填。
- StableReaderLocator 在第 6 步完成首批合同，SearchSnapshot/Generation 在第 7 步完成执行期一致性；引用/导出 snapshot 仍未完成，因此 `CONS-23` 不通过。
- 本步未新增依赖，迁移为可重入 additive schema；没有 commit、push、PR、Actions、tag 或 Release。

### 5.3 实施顺序第 6 步结果（2026-07-11）

- 第 6 项已建立唯一 `StableReaderLocator v2` shared 判别联合、runtime validator、legacy adapter 和引文重定位，`CONS-05` 的身份合同及首批搜索/阅读/摘录/AI 接入已落地。
- exact 只能来自可验证 canonical version/hash/range；旧零范围、译文或未知来源只能是 page/document，不能提升为 verified exact。
- 工作区和研究 locator 均惰性兼容，不增加数据库列、不批量重写旧 JSON；旧公开 API 继续读取。
- `CONS-05` 的目录/EPUB/持久阅读状态/translation unit 全覆盖尚未完成；`CONS-06` SearchSnapshot/EvidenceResolver 仍进入第 7 步。
- 本步未新增依赖，未执行任何远程或公开动作。

### 5.4 实施顺序第 7 步结果（2026-07-12）

- 第 7 项已落地 library search generation、执行期 SearchSnapshot 和唯一 SearchEvidenceResolver；`CONS-06` 中 snapshot 与长期 artifact 的类型/生命周期已明确分离。
- 查询分页复用同一 snapshot，并在开始/结束校验 generation；TTL、criteria 或 generation 变化返回稳定失效状态，不拼接两代结果。
- evidence 只从 canonical source + StableReaderLocator 解析，exact 失败 fail closed；IPC/preload 提供验证与解析入口。
- 长期 ResearchAggregateArtifact/ResearchEvidence/output lineage 仍进入第 8 步，CitationSnapshot/ExportSnapshot 进入后续步骤；不能把执行期 snapshot 当长期 provenance。
- 本步未新增依赖，数据库迁移为可重入 additive 单行表/触发器，未执行远程或公开动作。

每个迁移切片都必须支持旧 schema fixture、普通库和大库；同一迁移 apply twice；任何失败恢复原库且应用仍可用旧兼容路径打开。

## 6. 热点文件与串行边界

以下热点禁止由多个计划并行重写：

- `src/shared/types.ts`、`src/preload/index.ts`：shared DTO 和 API 合同按领域小批串行。
- `src/main/database.ts`、startup recovery、backup：迁移、维护和恢复由数据库切片统一。
- `src/main/ipc/documents.ts`：先拆服务/adapter，再改导入、阅读、搜索或导出调用。
- `src/renderer/src/App.tsx`、`app.css`：先 shell/interaction primitive，再迁移页面；不与 AI panel/reader 大改并行。
- `DocumentView.tsx`、`SourcePageReader.tsx`、`EbookReader.tsx`：先 canonical/locator，再做 UI/translation/AI。
- `semantic-search.ts`、AI/research 服务、export：先 resolver/snapshot/lineage，再做产品增强。

每个切片必须列出 owner、输入/输出 DTO、数据库写入、兼容 adapter、测试和回退；未列出的跨热点修改不得顺手合入。

### 7.1 Gate 0 文件能力一致性结论（2026-07-10）

CONS-21 的导入、文献/页面路径写入、PDF 仓库、外部文件夹扫描、托管删除和 `local-resource` 子范围已实现并通过独立规格/质量复核：renderer 仅持有 opaque selection/grant/repository ID；main 对 grant 的 owner/purpose/TTL/identity 及目录 canonical containment 重验；完成、取消、异常和 renderer 退出均释放活跃资源；目录总量无限但每批、活跃 selection、completed fallback 和 lease 绝对时长有界。

该结论不扩大到 C14-18 中尚未实施的引用规则文件、TeX、普通导出和备份完整 capability；这些入口不得复用 `document-import` purpose。当前切片未新增依赖、未迁移数据库，也不授权任何远端或公开发布动作。

### 7.2 迁移顺序第 2、3 步一致性结论（2026-07-10）

- **CONS-03 本切片已实现：** protected key 的持久真相移至 main-only safeStorage sidecar；renderer、普通设置快照、profile JSON、普通备份、错误 envelope 和直接业务 SQL 均不再包含已保存明文 secret。
- **CONS-01 前置合同已实现：** shared 顶层 `TaskStatus` 只有六个值，旧 `processing/failed/cancelled` 只能经 adapter 进入规范化 `TaskStateEnvelope`；partial 只能是 `completed + completionKind='partial'`。
- **设置与错误合同已实现：** `SettingDefinition` 负责 protected/public、类型、范围和 renderer visibility；`ErrorEnvelope` 校验稳定 code、recoverable/recoveryAction 并脱敏 secret 与绝对路径。
- **恢复边界：** backup manifest 声明凭据排除；恢复后不复用未与恢复数据库引用匹配的旧 sidecar。旧格式备份只告警，不未经授权删除。
- **明确未完成：** CONS-02 的唯一物理 scheduler 尚未建表；OCR canonical artifact、StableReaderLocator、SearchSnapshot、ResearchEvidence 和产品 epic 仍按第 4 步以后顺序实施。

### 7.3 第 4 至 8 步一致性结论（2026-07-12）

- CONS-02/04/05 已分别由唯一 scheduler、canonical provider 和 StableReaderLocator v2 落地；旧队列、页面字段和 locator 只保留兼容投影。
- CONS-06 已建立执行期 SearchSnapshot、长期 ResearchEvidence、record version 和 output version 的独立身份与生命周期；TTL snapshot 不可进入正式 provenance。
- evidence 本体与 project relation 分离，同一来源可服务多个专题；解除一个项目关系不删除 evidence。旧 note 只能在唯一定位后按条晋升。
- 正式 output 由 main 生成 manifest 并在写入时复验 evidence；renderer 无权提交权威 manifest。当前覆盖到 record/evidence 输入集合，完整 claim manifest、aggregate artifact、CitationSnapshot/ExportSnapshot 仍未完成。
- 第八步仅 additive schema，无破坏性回填、无新依赖、无远端动作；所有旧业务表继续可读。
- 第八步 B 已补齐 `ResearchAggregateArtifact`：TTL SearchSnapshot 只能在 active/complete 时由 main 提升；artifact 与 evidence/output 保持不同身份。正式 output 对 aggregate 做专题关系、hash、generation 和 exactness 校验，仍不等同于逐句 claim 已覆盖。
- 第八步 C 已补齐 output-scoped claim manifest：input coverage 说明处理了哪些 record/aggregate，claim coverage 说明哪些实际句段获得支持，两者不得互相替代。formal 同时要求 input provenance 有效和 claim coverage 全满；无映射 AI 输出降为 draft。

### 7.4 第 9/10 步兼容性复核结果（2026-07-12）

- CONS-22 已由 translation context/revision/attempt CAS 落地，机器迟到结果不能覆盖人工译文；旧 translation projection 继续读写兼容。
- CONS-23 已由 CitationResolver/CitationSnapshot 与 main-built ExportSnapshot/AtomicExportWriter 落地；引用缺字段不能冒充 verified，导出失败不能破坏旧目标，canonical 页变化会使快照 stale。
- CONS-25 的零 schema 基础已落地：Esc 不再隐式退出，workspace v2/last-known-good/v1 fallback 与通用 interaction generation 已有回归；完整 BrowserWindow close handshake 和所有领域 dirty participant 仍未完成，不能把基础类存在视为全部关闭流程完成。
- CONS-15/24 的供应链基础已落地：双用户合成 fixture、SPDX、vendor hash、包内许可证配置和 packaged smoke 脚本已建立；公开截图替换、Windows 包实测与维护者批准已在 1.1.0 候选中完成。
- 所有新增数据库结构均为 additive，未新增依赖、模型或服务；当前候选仍是 dirty 本地工作树，不是可公开 commit。

## 8. 最终实施纪律

正式业务实现前，先提交全部审阅文档，并创建 `checkpoint/before-refactor-execution-<date>` 本地检查点提交与标签。之后每个切片：先按目标成品更新/新增失败验收，完成实现，运行窄测试与完整门禁，提供本地可测试成品，再由用户决定继续修改或批准公开。

本章只裁决方案兼容性，不授权业务迁移、新依赖或公开发布。任何未在本章分配 owner 的新状态、表、服务或外部依赖都必须回到设计阶段，不能在实现中临时创造。
