# Gate 0 文件能力与托管资产边界实施计划

> **执行要求：** 使用 `superpowers:executing-plans` 与 `superpowers:test-driven-development`，逐项先写失败测试，再写最小实现；所有结果只保留在本地分支，用户本地验收前不得 push、PR、触发 GitHub Actions、创建公开 tag 或 Release。

**目标：** 落实 `11-数据库备份安全与兼容性.md` 的 D11-P0-03、D11-P0-04、DATA-10、DATA-11，以及 `14-全局冲突与兼容性复核.md` 的 C14-18、CONS-21：renderer 不能凭路径字符串获得文件系统能力，删除文献不能越出 GujiSmart 托管存储区。

**范围约束：** 不新增依赖，不迁移数据库，不改变 OCR、阅读器、检索和 AI 数据模型；旧数据库继续读取。文件和任务总量不设产品上限，只限制活跃 capability、单批展开量和并发。

**跨层数据流：**

```text
用户文件手势/main 对话框
  -> main/preload 签发 opaque capability
  -> renderer 只保存 capability ID、显示名和恢复状态
  -> main 按 purpose/TTL/type/realpath 重新校验
  -> 导入、仓库、读取或托管写入

数据库路径字段
  -> 只作为兼容读取线索
  -> 不产生新 capability
  -> 不参与递归删除目标生成
```

## 完成定义

- renderer 无法通过字符串伪造导入、仓库、读取或本地资源权限。
- 文献删除、PDF 清理、重启续删和启动孤儿清理都不能越出 canonical `data/storage/<docId>`。
- 通用文献/页面更新接口无法改写路径字段，正常 metadata/OCR/proof 更新不回归。
- 旧数据库无需迁移；旧队列失效授权可恢复；文件总量无硬上限。
- 全量 check/build/smoke 与本地手工主流程通过后，才向用户提供本地验收版本。
