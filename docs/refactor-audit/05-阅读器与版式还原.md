# 05 阅读器与版式还原

## 1. 本章结论

GujiSmart 当前已经同时支持 PDF/图片原页、OCR 正文、古籍版式校对、EPUB 原生渲染、电子书重排、单双页阅读、页内检索、跨库检索返回、目录生成与编辑、阅读位置恢复、简繁显示、研究摘录、AI 排版和逐页/整书对照翻译。古籍与通用论文并不是两套完全割裂的阅读器，而是通过文献类型、页面数据和阅读模式选择不同投影，这一基础应当保留。

当前最需要解决的不是重新制作一套阅读器外观，而是建立一个跨模式稳定的“正文、位置和来源”合同。现有实现中，同一页正文在阅读器、搜索、翻译、导出之间仍可能选择不同字段；电子书虚拟页会随字体、窗口和单双页模式重新切分；目录、检索命中、研究摘录和 AI 排版各自使用页码、元素序号或字符偏移定位。这些标识一旦遇到人工校对、重排或窗口变化，就可能漂移。

本章建议以“原始来源页/EPUB href + canonical text 版本 + 原文范围 + 引文上下文”为稳定定位核心，让原图、校对、正文重排、AI 排版、翻译和搜索都只是可重建投影。目录与 AI 排版必须先生成候选版本，校验后再激活，不能直接覆盖人工内容。整书翻译、目录绑定和大型阅读器检索必须复用有界、可取消、可恢复的后台任务框架。第一阶段不做广泛数据库重构，也不新增依赖；但当前启动维护正在破坏性删除旧目录，因此必须先冻结清理，并对尚存旧目录执行一次带备份、校验和回滚的兼容迁移。

## 3. 当前端到端数据流

### 3.1 阅读模式分流

```text
App 文献标签页
  -> DocumentView
     -> EPUB/受管电子书主路径 -> EbookReader
     -> 旧数据/元数据不一致的电子书回退 -> SourcePageReader 虚拟分页
     -> 结构化来源页 -> SourcePageReader
     -> 普通 OCR 正文 -> DocumentView 文本重排阅读
     -> PDF/图片 -> 原图、双页、鸟瞰或校对模式
     -> proof -> TextEditor / GujiFacsimileProofreader
```

模式分流已经能兼容古籍扫描件、结构化 OCR、普通 PDF 和电子书，但 `DocumentView.tsx`、`EbookReader.tsx` 与 `SourcePageReader.tsx` 分别维护分页、检索、目录、摘录、翻译和状态恢复逻辑。相同概念存在多套实现，后续修复必须先收口共享合同，再逐步替换，不适合一次性重写三个大型组件。

### 3.2 正文选择

多数翻译路径已通过 `getCanonicalPageTranslationSourceText` 优先使用人工校对文本，再使用结构化块和 OCR 文本（`src/shared/translation-source.ts:926` 至 `src/shared/translation-source.ts:938`）。搜索读取页文本也优先 `proofed_text`（`src/main/ipc/search.ts:281` 至 `src/main/ipc/search.ts:289`）。

但 `EbookReader` 对电子书页面直接使用 `ocr_text || proofed_text`（`src/renderer/src/components/EbookReader.tsx:440` 至 `src/renderer/src/components/EbookReader.tsx:448`），因此人工校对完成后，正文阅读仍可能展示旧 OCR，而搜索、翻译和导出使用校对文本。结构化阅读的 `getReadablePageElements` 又会在检查页面正文前直接返回现存 layout blocks（`src/renderer/src/utils/ocrText.ts:1736` 至 `src/renderer/src/utils/ocrText.ts:1818`）；如果人工校对只更新 `proofed_text` 而没有同步 block 文本，来源阅读器仍会显示旧字。版式阅读、AI 排版和摘录高亮由此进一步分叉。

### 3.3 分页、位置与检索返回

普通文本阅读器按字体、行高、可用宽高估算字符数，将每个来源页切成阅读页，并保存 `text-reader:<虚拟页序号>`（`src/renderer/src/views/DocumentView.tsx:1238` 至 `src/renderer/src/views/DocumentView.tsx:1291`、`src/renderer/src/views/DocumentView.tsx:2123` 至 `src/renderer/src/views/DocumentView.tsx:2137`）。电子书来源阅读器则可以把多个来源页元素装入一个 `ebook-virtual-N`（`src/renderer/src/components/SourcePageReader.tsx:433` 至 `src/renderer/src/components/SourcePageReader.tsx:567`）。

从搜索、AI 或研究证据打开文献时，`temporaryNavigationRef` 会阻止临时跳转覆盖用户原阅读进度。用户明确翻页后应释放该保护。当前只有部分页面控件调用 `releaseTemporaryNavigation`；页码跳转、快捷键、文本重排翻页、鸟瞰选择和部分书页点击直接更新索引，可能让保护永久保持，后续阅读进度不再保存。

### 3.4 原页、校对与 AI 排版

来源阅读器把 OCR 结构转换成标题、正文、表格、图片和脚注元素。AI 排版返回 Markdown 风格文本，再重新解析为新元素；缺失表格和图片时，以文本片段相似度猜测插入位置（`src/renderer/src/components/SourcePageReader.tsx:628` 至 `src/renderer/src/components/SourcePageReader.tsx:788`）。

原始元素的 `charStart/charEnd`、元素序号和 AI 元素的偏移分别重新编号，没有持久的 source-range 映射。研究摘录高亮始终按原始元素查找（`src/renderer/src/components/SourcePageReader.tsx:1704` 至 `src/renderer/src/components/SourcePageReader.tsx:1745`），而 AI 排版显示使用新元素，因此同一笔记在切换 AI 排版后可能落到错误段落或消失。

校对组件会立即更新本地 history 和界面，再调用 `onSave`。`DocumentView.handleSavePage` 捕获数据库错误、只显示消息且不重新抛出（`src/renderer/src/views/DocumentView.tsx:3520` 至 `src/renderer/src/views/DocumentView.tsx:3584`）；三个校对组件又没有等待保存 Promise（`TextEditor.tsx:218` 至 `TextEditor.tsx:227`、`OverlayProofreader.tsx:738` 至 `OverlayProofreader.tsx:746`、`GujiFacsimileProofreader.tsx:2117` 至 `GujiFacsimileProofreader.tsx:2119`）。调用者因此无法知道页面是否真正持久化，也无法正确实现保存中、失败重试和离开保护。

### 3.5 目录生成、绑定与保存

目录服务会从 OCR 标题块、目录页、文章结构和 AI 结果生成条目，再在主进程扫描页面，把标题绑定为 `page:<n>:char:<offset>`。绑定过程对每个目录条目反复遍历、筛选和打分全部页面（`src/main/toc-service.ts:1094` 至 `src/main/toc-service.ts:1141`、`src/main/toc-service.ts:1393` 至 `src/main/toc-service.ts:1471`）。

保存目录时会先删除该文献的全部 `document_toc_items`，再插入本次结果（`src/main/toc-service.ts:2003` 至 `src/main/toc-service.ts:2042`）。规则重建会保护人工/导入目录，但 AI 路径不读取这份保护；档案类抑制还会直接保存空数组（`src/main/toc-service.ts:2058` 至 `src/main/toc-service.ts:2062`）。因此运行 AI 目录可能删除人工目录、导入目录或全部目录。

视觉 OCR 生成目录时也会删除 metadata 中的人工/AI/视觉目录字段，再调用同一全量保存函数（`src/main/ipc/ocr.ts:4545` 至 `src/main/ipc/ocr.ts:4589`）。更早的兼容数据还面临启动维护：`stripLegacyTocMetadata` 先删除 `source='legacy'` 的表记录，再删除 `manual_toc/ai_toc/vision_toc/reader_toc` 和 `ebook_manifest.toc`（`src/main/database.ts:1446` 至 `src/main/database.ts:1485`），并由启动维护直接调用（`src/main/database.ts:2118` 至 `src/main/database.ts:2139`）。仓库内没有对应迁移逻辑。

### 3.6 翻译与研究摘录

电子书虚拟页可能包含多个来源页，但只把第一个元素的页面 ID 写入 `source_page_id`（`src/renderer/src/components/SourcePageReader.tsx:448` 至 `src/renderer/src/components/SourcePageReader.tsx:485`）。翻译请求使用虚拟页 ID 作为显示键、首个来源页 ID 作为缓存页 ID，并把整段跨页文本作为一个页面发送（`src/renderer/src/components/SourcePageReader.tsx:2877` 至 `src/renderer/src/components/SourcePageReader.tsx:2925`）。该路径主要服务旧数据或元数据不一致时的回退兼容；正常受管 EPUB/文本通常由 `EbookReader` 接管。即使可达范围较窄，字体或窗口变化后虚拟页边界、ID 与来源组合仍会变化，兼容数据的翻译缓存无法稳定失效或复用。

当前存在两条整书翻译链。阅读器内触发的对照翻译由 renderer 数组排队，入队时为每一项过滤旧队列，消费时使用 `shift/unshift/some`（`src/renderer/src/views/DocumentView.tsx:4269` 至 `src/renderer/src/views/DocumentView.tsx:4351`）。文库菜单触发的 `documents:translateBook` 则在 main 进程一次性 hydrate 全书页面，保留完整 work array，并在每页完成后重写整本输出文件（`src/main/ipc/documents.ts:2456` 至 `src/main/ipc/documents.ts:2638`）。两条链都只有进程内运行状态，没有统一持久化 job/item、暂停和重启续做。

两套来源阅读器都会调用 `listResearchNotes(null)` 读取全库研究摘录，再在 renderer 按 `doc_id` 过滤（`src/renderer/src/components/EbookReader.tsx:1616` 至 `src/renderer/src/components/EbookReader.tsx:1639`、`src/renderer/src/components/SourcePageReader.tsx:2843` 至 `src/renderer/src/components/SourcePageReader.tsx:2866`）。后端未传项目时执行无分页全表查询（`src/main/ipc/research.ts:351` 至 `src/main/ipc/research.ts:367`）。研究笔记数量逻辑上无限时，这一行为与有界内存约束直接冲突。

### 3.7 全书页面与页内检索加载

`documents:getLight` 虽不 hydrate 大字段，但仍一次查询并返回文献全部页面行（`src/main/ipc/documents.ts:4308` 至 `src/main/ipc/documents.ts:4331`），因此打开 10 万页文献时 renderer 的基础 page array 仍线性增长。进入来源阅读器或校对模式并执行页内检索后，`documents:getSearchPages` 又会 hydrate 全书 OCR/校对文本（`src/main/ipc/documents.ts:4421` 至 `src/main/ipc/documents.ts:4448`），`DocumentView` 保存完整数组并在 renderer 遍历每页和每个 OCR 框（`src/renderer/src/views/DocumentView.tsx:1929` 至 `src/renderer/src/views/DocumentView.tsx:1995`、`src/renderer/src/views/DocumentView.tsx:2586` 至 `src/renderer/src/views/DocumentView.tsx:2612`）。该路径直接违反“总量无限、活动内存有界”的约束。

## 4. 必须保留的能力

- 古籍扫描件的原图、竖排版式校对、文字阅读和版式还原模式。
- 通用 PDF/论文的原页、正文重排、单双页阅读、目录和页内检索。
- EPUB 的 href/CFI 导航、目录和可重排阅读；不能为了统一而退化成只读纯文本。
- 人工校对优先、原始 OCR 可追溯、版本可回退。
- 阅读主题、字体、行高、单双页、简繁显示和阅读位置恢复。
- 从全库/全文检索返回文献并高亮当前命中，返回后不污染原阅读进度。
- 研究摘录、直接引用、目录编辑、翻译和 AI 上下文能力。
- 页面总量不设产品上限；只限制当前窗口、缓存、并发和单批处理量。
- 现有 SQLite、文献页、目录、阅读状态、翻译缓存和研究摘录默认原位兼容。

## 5. 关键问题

### D05-P0-01 启动维护会先删除旧目录数据，再移除唯一兼容来源

**证据等级：已确认。**

`stripLegacyTocMetadata` 会无条件删除 `document_toc_items.source='legacy'`，随后从全部文献 metadata 删除 `reader_toc`、`manual_toc`、`ai_toc`、`vision_toc`、目录来源/更新时间和 `ebook_manifest.toc`，最后写入“已清理”标记（`src/main/database.ts:1446` 至 `src/main/database.ts:1485`）。该函数由延迟启动维护直接调用（`src/main/database.ts:2118` 至 `src/main/database.ts:2139`）。全仓搜索只发现这些旧字段的删除逻辑，没有把它们校验并迁移到 active `document_toc_items` 的逻辑。

**影响：** 尚未运行过该维护的旧数据库，一旦启动满足维护条件，人工目录、EPUB 原始目录或旧版本目录可能永久丢失；已经运行过的库只能依靠外部备份恢复。这属于 P0 用户数据风险。

**落实方案：**

1. 第一修复立即停止删除 `legacy` 行和 metadata 目录；清理标记不能再作为迁移成功证据。
2. 启动时只做只读预检：统计每个旧来源、可解析条目、当前 active 目录和冲突，不自动写入。
3. 在自动备份后，将旧目录解析为候选版本；逐文献校验条目数、标题、层级、href/页码和人工来源，再在事务内激活或保留双读。
4. 只有迁移报告确认无未处理旧目录、恢复演练通过且用户可回滚时，后续版本才允许删除冗余 metadata。
5. 对已经清理的库提供备份检测与恢复说明；不能伪造缺失目录。

### D05-P1-01 `EbookReader` 让旧 OCR 覆盖人工校对正文

**证据等级：已确认。**

`buildTextPageSource` 在 `src/renderer/src/components/EbookReader.tsx:440` 至 `src/renderer/src/components/EbookReader.tsx:448` 使用 `page.ocr_text || page.proofed_text`。与翻译 canonical source、搜索和导出的 `proofed_text` 优先规则相反。`getReadablePageElements` 在 `src/renderer/src/utils/ocrText.ts:1736` 至 `src/renderer/src/utils/ocrText.ts:1818` 又优先返回 layout blocks；人工校对只改正文而 block 未同步时，结构化阅读同样显示旧字。

**影响：** 用户完成校对后，阅读器仍可能显示旧字，搜索命中、引用、翻译与屏幕内容不一致；古籍用户和论文用户都会受到影响。

**落实方案：**

1. 复用模块 03 唯一 `CanonicalContentProvider.resolvePage(...) -> CanonicalPageContent`，优先级严格为 `active proof revision -> active OCR artifact -> source fallback`。阅读器不再定义第二个 resolver；IR、blocks 和纯文本只是同一 active artifact 内的确定性投影，不是互相竞争的独立来源。
2. 阅读器、搜索、翻译、AI、目录、摘录和导出只消费同一解析结果，不各自拼字段。
3. 返回 `proofRevisionId`、`artifactId`、`sourceKind`、`contentVersion`、`sourceHash` 和可诊断降级原因，界面可显示当前正文来源。
4. 对旧数据库零迁移：运行时从已有字段推导；只有后续需要增量索引时再旁路持久化版本号。
5. 新增同一页面含不同 `ocr_text/proofed_text/IR` 时的跨模块一致性测试。

### D05-P1-02 AI、视觉 OCR 和任何全量目录保存都可覆盖人工目录

**证据等级：已确认。**

`saveDocumentToc` 在 `src/main/toc-service.ts:2003` 至 `src/main/toc-service.ts:2042` 不区分来源，全量删除后重建。规则重建会在 `src/main/toc-service.ts:2045` 至 `src/main/toc-service.ts:2055` 检查人工/导入来源，但 `runAiToc` 没有同等保护；档案类抑制在 `src/main/toc-service.ts:2058` 至 `src/main/toc-service.ts:2062` 直接保存空数组。视觉 OCR 还会先删除旧 metadata 目录字段，再调用同一保存函数（`src/main/ipc/ocr.ts:4545` 至 `src/main/ipc/ocr.ts:4589`）。

### D05-P2-03 阅读器性能门禁缺少真实大文献与持续交互测量

**证据等级：已确认。**

现有回归主要检查源码合同和小样本，没有固定 1 万页、长 OCR 块、数千目录、数万摘录和连续 AI/翻译任务下的 heap、主进程 event-loop delay、翻页帧率、恢复耗时与缓存命中指标。

### D05-P2-04 格式化目录的缩进层级在解析前已被抹平

**证据等级：已确认。**

`normalizeForToc` 在 `src/shared/toc-format.ts:12` 至 `src/shared/toc-format.ts:19` 把连续空格压成一个并执行 `trim`，之后 `pushTocEntry` 才在 `src/shared/toc-format.ts:56` 至 `src/shared/toc-format.ts:66` 统计前导空格，`inferTocLevel` 又依赖 2/6 个空格判断二、三级。缩进输入因此会退化为同级目录。

**落实方案：** 解析前分离每一原始行的前导缩进和正文，只对正文做空白规范化；同时支持 tab、全角空格和可配置缩进宽度。目录层级优先使用明确编号/结构标签，缩进只作为次级证据。新增缩进、全角数字、罗马页码、同列多条和非目录误判测试。

### D05-P2-05 OCR 行内样式边界会截断检索高亮

**证据等级：已确认。**

`renderOcrInlineHighlighted` 先把文本解析为样式 segment，再在每个 segment 内单独匹配关键词（`src/renderer/src/utils/ocrInlineRender.tsx:57` 至 `src/renderer/src/utils/ocrInlineRender.tsx:105`）。关键词跨越粗体、下划线、上标或下标边界时，完整可见文本能命中搜索计数，但渲染层没有任何单一 segment 包含整个词，因此不生成 `<mark>`。

**落实方案：** 先构造保留 display-to-source offset 的扁平显示文本，在全串上查找命中范围，再把范围切回各样式 segment 分段渲染；一个逻辑命中可以包含多个相邻 mark 片段，但共享同一 hit identity。简繁转换或其他 `transformText` 造成长度变化时必须使用显式 offset map，不能直接复用原偏移。

### D05-P2-06 鸟瞰视图可能把未加载远页的版式异常显示为正常

`documents:getLight` 只返回 `has_ocr_result`，不返回 `ocr_result` 或 `needs_layout_attention`（`src/main/ipc/documents.ts:4308` 至 `src/main/ipc/documents.ts:4331`）。`PageBirdseyeGrid` 在两个诊断字段都缺失时直接返回正常（`src/renderer/src/components/PageBirdseyeGrid.tsx:30` 至 `src/renderer/src/components/PageBirdseyeGrid.tsx:41`），而 `DocumentView` 把整个轻量页面列表交给鸟瞰。当前窗口外尚未补全的异常页会漏报。

**落实方案：** 轻量页投影直接包含数据库可增量维护的 `needs_layout_attention` 和质量摘要，不把完整 OCR JSON 发送给 renderer。未知诊断必须显示“未检查/加载中”，不能等同正常。OCR artifact 激活时同步更新摘要，鸟瞰分页或分批读取全书状态。

### D05-P2-07 `EbookReader` 保存显示偏好但重开不恢复

**证据等级：已确认。**

`EbookReader` 每次固定初始化 `spread/17/1.85/paper`（`src/renderer/src/components/EbookReader.tsx:1445` 至 `src/renderer/src/components/EbookReader.tsx:1449`），随后把这些值写入 reader state（`src/renderer/src/components/EbookReader.tsx:1916` 至 `src/renderer/src/components/EbookReader.tsx:1944`）。`DocumentView` 恢复时主要解析位置与 proof 模式，没有把保存的字体、行高、主题和 view mode 注入 `EbookReader`（`src/renderer/src/views/DocumentView.tsx:2614` 至 `src/renderer/src/views/DocumentView.tsx:2675`）。

**落实方案：** 区分全局阅读偏好和文献位置状态：全局偏好决定新文献默认值，文献级显式覆盖可选。组件只在恢复完成后发出 state change，避免默认值先覆盖已保存值。新增 TXT/EPUB 改为单页、暗色、字号 22 后关闭重开的 E2E。

### D05-P2-08 `ImageViewer` 可能被旧图片的延迟加载结果覆盖

**证据等级：高风险推断，竞态路径明确。**

每次 `src` 变化都会创建新 `Image`，其 `onload` 无取消标记或请求序号（`src/renderer/src/components/ImageViewer.tsx:154` 至 `src/renderer/src/components/ImageViewer.tsx:163`）。若快速从 A 页切到 B 页而 A 最后才完成，A 的尺寸会覆盖 B，重新执行 fit-to-screen，并使 OCR 坐标缩放错误。

**落实方案：** 为每次加载生成 monotonically increasing token，`onload/onerror` 只有在 token 和当前 src 同时匹配时才能写状态；cleanup 清空 handler。页面切换时先标记尺寸 unknown，OCR 框在新尺寸确认前不交互。组件测试模拟 A/B 反序完成并验证最终尺寸、viewport 和框均属于 B。

### D05-P2-09 默认检查与 CI 缺少真实阅读器行为和 EPUB 样本

**证据等级：已确认。**

`npm run check` 包含多项源码合同，但不运行 `reader-state-smoke.js`、`source-footnote-regression.js` 和 `source-structured-ocr-regression.js`（`package.json:33`、`package.json:78` 至 `package.json:88`）；CI 只运行 build 和该 check（`.github/workflows/ci.yml:27` 至 `.github/workflows/ci.yml:31`）。现有阅读器样本没有 `.epub` fixture，因此 EPUB 加载、TOC、CFI 恢复和检索分支没有真实端到端保护。

**落实方案：** 建立 `check:reader-e2e`，使用完全合成且许可证清晰的小型 TXT/JSON/EPUB fixture，覆盖打开、目录、搜索、摘录、偏好、关闭重开和失败状态。先让 Windows 本地稳定，再在发布门禁启用；是否纳入每次普通 CI 可按耗时拆成快速/完整两层，但 Release 前必须执行完整层。

### D05-P2-10 EPUB `display()` 超时不会取消旧导航

**证据等级：高风险推断，竞态路径明确。**

`displayEpubTarget` 用 `Promise.race` 给 `rendition.display()` 增加 8 秒超时，但超时后没有取消原 display（`src/renderer/src/components/EbookReader.tsx:344` 至 `src/renderer/src/components/EbookReader.tsx:354`）。随后重试候选或用户发起新导航时，旧 Promise 仍可能晚完成。

**落实方案：** 每次 EPUB 导航分配 generation，只有最新 generation 的 relocated/display completion 可以提交状态；超时后如果 epub.js 支持取消则调用正式取消，否则忽略旧事件并重新确认目标 href/CFI。测试模拟旧 display 晚于新 display 完成，最终章节必须保持新目标。

### D05-P2-11 TOC 绑定排序后仍用原数组 index 查找下一边界

**落实方案：** 所有后续边界、父级和相邻条目计算必须基于同一排序后的不可变数组；为乱序输入、同页多项和跨卷页码回退增加测试。更长期由 stable locator 候选索引替代顺序猜测。

### D05-P2-12 SourcePageReader 显示异步解析状态，但未真正解析未绑定目录

**落实方案：** 删除虚假的运行状态，或接入 main/worker 的真实目录绑定 job。renderer 只显示 job snapshot 和可见结果，不自行扫描全书。未解析、解析中、失败和 disabled 必须是不同状态。

### D05-P2-13 来源阅读器只监听 window resize，不监听实际容器变化

**落实方案：** 使用浏览器原生 `ResizeObserver` 观察真正分页容器，合并短时间连续事件并以稳定 source locator 保持当前阅读位置。无需新增依赖；测试改变侧栏/翻译面板宽度并验证重新分页和位置不跳。

**证据等级：已确认。**

`ImageViewer` 的 OCR 框和左右页边热区使用带 `onClick` 的普通 `div`（`src/renderer/src/components/ImageViewer.tsx:258` 至 `src/renderer/src/components/ImageViewer.tsx:292`、`src/renderer/src/components/ImageViewer.tsx:381` 至 `src/renderer/src/components/ImageViewer.tsx:400`），没有 button/role、tabIndex、键盘处理和可读名称。

**落实方案：** 页边翻页改为语义 button；OCR 框根据用途使用 button 或可聚焦 option，并提供页码、块序号、文本摘要和选中状态。焦点切页后落到新页容器，隐藏热区不进入 tab 顺序。UI 模块统一视觉样式，但阅读器模块负责行为验收。

### D05-P2-15 PDF 超时只拒绝等待，不取消 loading/render task 或清理页面资源

**证据等级：高风险推断，资源泄漏路径明确。**

PDF 加载把 `loadingTask.promise` 包在通用 timeout 中，超时不调用 `loadingTask.destroy()`（`src/renderer/src/utils/pdf.ts:106` 至 `src/renderer/src/utils/pdf.ts:119`）。单页渲染同样只 timeout `page.render().promise`，异常路径没有保证取消 render task、`page.cleanup()` 和 canvas 释放（`src/renderer/src/utils/pdf.ts:205` 至 `src/renderer/src/utils/pdf.ts:220`）。

**落实方案：** 显式持有 loading/render task；取消、超时、切文献和卸载统一进入 finally cleanup。缓存的 PDFDocument 由有界引用/闲置策略管理，不在每页 cleanup 时误销毁共享文档。故障测试模拟挂起加载、挂起 render 和快速切页，验证任务终止、内存回落和新页可继续显示。

## 6. 目标架构与兼容策略

```text
SQLite / page payload artifacts / EPUB source
  -> Legacy TOC Compatibility Gate
     -> backup + parse + validate + reversible activation
  -> CanonicalContentProvider.resolvePage(...) -> CanonicalPageContent
     -> contentVersion + sourceHash + stable source blocks
        -> Stable Locator Service
           -> source page or href + source ranges + quote context

Reader Projection Layer
  -> facsimile projection
  -> proofing projection
  -> reflow text projection
  -> EPUB projection
  -> AI layout projection
  -> parallel translation projection
     every render block -> source range mapping

Reader Domain Controllers
  -> navigation transaction and state persistence
  -> paged annotations
  -> page directory/window query
  -> TOC draft/version activation
  -> persistent translation jobs for reader and library entry points
  -> bounded search/highlight projection
```

核心原则：

- canonical content 是内容身份，阅读模式只是投影；AI 排版和翻译不能覆盖原文。
- 长期定位必须指向稳定来源范围，不能依赖当前窗口生成的虚拟页号或元素数组下标。
- 人工目录、校对、译文和研究摘录优先，自动结果只能生成候选或新版本。
- renderer 只持有可见窗口、少量预取和分页侧栏；文献总量、页数和任务数不进入内存上限。
- 保存必须可等待、可失败、可重试并带可比较的 CAS/version 身份；界面不得把本地乐观状态当成已持久化。
- 第一阶段兼容读取现有字段和表；新增结构采用旁路、可回退和旧版本可忽略策略。
- 当前旧目录清理是唯一必须优先处理的兼容迁移：未备份、未验证、不可回滚时禁止继续删除。

### 6.1 建议的共享合同

```text
CanonicalPageContent
  documentId, sourcePageId, href, proofRevisionId?, artifactId?
  contentVersion, sourceHash
  text, blocks[], sourceKind, warnings[]

StableReaderLocator (schemaVersion='stable-reader-locator/v2' 的判别联合)
  common: precision, documentId, sourcePageId?, href?, chapterPath?, progressFallback?
  exact: precision='exact'; 必填 contentVersion, sourceHash, offsetUnit,
         non-empty sourceRanges, quote, prefix, suffix, occurrenceIndex
  block: precision='block'; 必填 stable blockId 与 contentVersion
  page/document: 不得携带伪造的 exact range；可保留页面/href 和版本身份
  legacy v1: 只经 adapter 读取并标 legacy-unverified，不提升为 exact verified

ReaderProjectionBlock
  projectionId, projectionKind, text, styleRole
  sourceRanges[], synthetic, confidence

ReaderSaveRequest / ReaderSaveResult
  pageId, expectedContentHash -> contentHash, proofRevisionId?, savedAt
```

这些 DTO 应放入 shared 并通过 preload 显式暴露；`StableReaderLocator` 的 schema、判别字段和 exact 必填项由本模块唯一拥有，模块 06/07 只能导入和消费，不能再定义近似版本。数据库行仍可保留 snake_case，在 main 边界转换。第一阶段可由现有数据动态构造，不要求立即新增列。

## 7. 分阶段落实方案

### 阶段 A：先封住数据丢失和内容不一致

- 立即冻结 `stripLegacyTocMetadata` 的破坏性删除，建立旧目录只读盘点、自动备份、候选迁移、校验和回滚。
- 修正 `EbookReader` 正文优先级，接入 shared `CanonicalContentProvider -> CanonicalPageContent`。
- 禁止 AI、视觉 OCR、空结果和任何全量 save 直接覆盖 active 目录，加入候选预览和人工项保护。
- 让页面保存 Promise 真实传播失败，先用 expected content hash 做 CAS，增加 dirty 和重试状态；长期 revision 复用模块 03 旁路版本。
- 让阅读位置 flush 返回真实结果，失败保留 pending snapshot，主动关闭不再静默丢位置。
- 更新 `reader-state-smoke`，完成真实关闭标签和重开验收。
- 除旧目录安全迁移外，这一阶段不做广泛数据库迁移、不新增依赖，先补失败测试再改实现。

### 阶段 B：稳定定位与导航事务

- 定义 `StableReaderLocator`，为阅读状态、目录、搜索、摘录、AI 证据和引用提供适配器。
- 阅读状态从虚拟页号迁移为来源范围；旧 `location_key` 继续读取并在成功恢复后惰性升级。
- 收口所有翻页、目录、页码、快捷键、鸟瞰和模式切换到统一导航命令。
- EPUB relocated 通过 href/CFI 映射数据库 section，并为 display/搜索跳转加入 latest-request-wins generation。
- 同页 OCR 聚焦按 block/source range 和 occurrence 解析，不再选择第一个同词框。
- 建立检索临时导航的开始、用户接管、返回和结束状态机。

### 阶段 C：投影映射与版式还原

- 原始 OCR/EPUB 元素生成稳定 block identity 和 source ranges。
- AI 排版输出必须返回或本地重建 source-to-render mapping；低置信映射回退原版式。
- 目录、摘录、检索高亮和翻译只通过 mapping 投影，不直接引用渲染数组下标。
- 古籍竖排、图文混排、脚注、表格和普通论文标题层级分别建立固定样本。

### 阶段 D：有界目录、摘录和阅读数据

- 目录页特征一次构建，倒排候选后精排；大任务移出主进程并可取消恢复。
- 研究摘录按文献、页范围和 cursor 查询，不再全库加载。
- `getLight/getSearchPages` 拆为页面目录、可见窗口、状态摘要和索引命中 API；阅读器不再持有全书 page/text 数组。
- 阅读器页面、搜索命中、目录和侧栏都使用窗口化/分页数据；预取由统一资源预算控制。
- 对图片 Base64、解析后的 OCR、AI layout 和翻译投影设置条目数与字节双上限。

### 阶段 E：持久化整书翻译与目录版本

- 阅读器对照翻译和文库 `documents:translateBook` 统一复用 task job/item，按稳定 source slice 分项；保留两个入口，不保留两套调度真相。
- 支持设置页并发、暂停、取消、失败重试、重启恢复和任务详情。
- 目录候选采用版本激活；人工编辑在 active 版本上产生新版本并保留父版本。
- 只有实测证明现有表无法可靠表达时才执行旁路迁移，并完成备份和恢复演练。

### 阶段 F：组件瘦身与体验优化

- 按领域控制器逐步缩小三个大型阅读器组件，避免一次性重写。
- 统一工具栏、键盘、焦点、加载/空/失败/离线状态和可访问性语义。
- 用原生 ResizeObserver 驱动容器重排；PDF/Image task 在超时、切页和卸载时可取消并清理。
- 根据固定基准优化首屏、翻页、缩放、目录跳转、搜索返回和长时间阅读内存。
- 保留古籍与论文各自适合的默认预设，允许用户切换，不拆成两个产品。

## 8. 新版验收方案

| RDR-24 | EPUB/TXT 的主题、字体、行高和单双页偏好关闭重开后恢复 | 改为暗色、字号 22、单页后重开 | 旧 reader state 缺字段时用全局默认 |
| RDR-25 | 快速 A/B 换图时旧 onload 不能覆盖当前图尺寸和坐标 | 模拟反序 onload、失败后重试 | 当前页 OCR 框不漂移 |

| RDR-27 | 旧 `legacy` 行和 metadata 目录在备份、迁移、校验前绝不删除 | 未运行维护旧库、已部分迁移库、坏 JSON、同文献多来源冲突 | 迁移失败完整回滚，原库仍可打开 |
| RDR-28 | AI、视觉 OCR、规则和导入目录均只写候选，不能绕过 active 保护 | 从 OCR 完成回调、AI、空结果、档案抑制分别触发 | 人工/导入目录和 metadata 兼容来源不丢 |
| RDR-29 | `active/unresolved/disabled` 在 main、preload 和两套阅读器含义一致 | disabled 带页码、unresolved 无 href、旧缓存缺 status | UI 不伪造 page:index 目标 |
| RDR-30 | EPUB relocated 通过 href/CFI 映射数据库 section，不把 spine index 当 page index | 一个 spine 拆 5 页、同 href 多 hash、章节内跳转 | 原 CFI/href 可继续恢复 |
| RDR-31 | 同页重复词从检索返回时聚焦 locator 指定的块和 occurrence | 双栏、表格、相同词 20 次、坐标缺失降级 | 不静默聚焦首框 |
| RDR-32 | 10 万页打开、鸟瞰和页内检索都只传输有界窗口/命中 | 记录 IPC bytes、renderer heap、同步扫描时长 | 总页数、目录和命中数仍可准确显示 |
| RDR-33 | EPUB 连续导航遵守 latest-request-wins，旧 display 晚完成无效 | A 超时后导航 B，A 最后完成 | 最终 CFI、目录高亮和阅读状态都属于 B |
| RDR-34 | 未绑定目录的解析状态真实、可取消、可恢复 | direct map 缺失、后台失败、关闭重开 | unresolved/disabled 不被误激活 |
| RDR-35 | 展开侧栏、翻译栏或拖 divider 会按容器尺寸重排并保持原文位置 | 不触发 window resize 的容器变化 | 无 ResizeObserver 环境正常降级 |
| RDR-36 | 原图 OCR 框和页边翻页可通过键盘与读屏操作 | Tab、Enter、Space、焦点切页、隐藏热区 | 鼠标拖拽和缩放行为不退化 |
| RDR-37 | PDF 加载/渲染超时、取消和切页会终止旧 task 并释放资源 | 挂起 loading/render、快速切页、组件卸载 | 共享 PDF 缓存不被误销毁 |
| RDR-38 | 阅读位置保存失败时保留最新 pending locator，主动关闭不会静默丢失 | SQLite busy、磁盘错误、IPC reject、旧响应晚到 | 恢复后只提交最新 generation |

性能门槛先在固定机器档案、确定性合成库、固定采样窗口和并发负载下记录当前基线。`renderer 心跳 p99 < 100ms`、`主进程单次同步工作 < 200ms` 只作为待基线确认的暂定护栏；基线冻结后再决定保留或调整，并写入可执行验收配置。确定性要求不变：翻页和模式切换的内存峰值必须与可见窗口、预取上限相关，不能与总页数线性增长。

## 9. 新功能建议

### 9.1 多形态同步阅读台

**用户问题：** 古籍用户需要同时看原图、校对文字和版式还原，论文用户需要原 PDF、重排正文和翻译；当前切换模式后定位和选择不一定保持。

**MVP：** 最多并排两种投影，支持原图/正文、原图/校对、正文/翻译、原版式/AI 排版。两侧通过 stable locator 同步滚动和跳转，可临时解除联动。

**实现影响：** 复用投影映射、现有 divider 和 translation view；第一版不新增数据库表，布局偏好存 settings。只加载两侧可见窗口，不复制整本文本。

**验收与回退：** 任一侧跳转后另一侧定位到同一来源范围；映射不足时显示“无法精确同步”并停在最近页。关闭功能回到现有单视图。无需新依赖。

### 9.2 目录版本与审校工作台

**用户问题：** 规则、AI、导入和人工目录互相覆盖风险高，用户也无法比较哪次生成更好。

**MVP：** 显示 active、候选和历史版本；逐条比较标题、层级、页码、置信度和来源，支持接受单条、批量合并、锁定人工项和回滚。

**实现影响：** 先复用任务 artifact 形成临时候选；需要长期历史时新增旁路版本表，实施前执行数据库备份、旧库兼容和恢复演练。

**验收与回退：** 生成失败和空结果不改变 active；应用操作原子且可回滚；旧客户端继续读取 active `document_toc_items` 投影。无需新依赖。

### 9.3 可恢复的阅读轨迹与研究路径

**用户问题：** 研究者会在文献、目录、检索命中和摘录之间来回跳转，单一“最后阅读位置”无法还原研究过程。

**MVP：** 本地记录最近的稳定位置、来源动作和时间，提供后退/前进与“今天读到哪里”；默认只保存有限条数，可按文献关闭或清除。

**实现影响：** 第一版可使用有容量上限的 settings/本地状态；若需要跨会话长期检索，再申请轻量 `reader_history` 旁路表。记录 locator 和文献 ID，不复制正文。

**验收与回退：** 历史总量和单文献条数有明确上限；删除文献同步清理；隐私设置关闭后不再记录且可一键清除。无需外部服务。

### 9.4 异本、版本和修订对读

**用户问题：** 古籍研究需要比较不同刻本/抄本，论文研究也需要比较预印本、出版版和修订稿。

**MVP：** 用户手工选择两篇文献，按目录标题、页码和文本相似度生成候选对齐；并排显示差异，允许人工修正对齐并保存为研究项目资产。

**实现影响：** 复用 canonical blocks、stable locator、全文检索相似度和同步阅读台。第一版采用现有文本算法，不引入新模型；对齐任务进入统一 job，结果旁路保存。

**验收与回退：** 自动对齐只给候选，不修改原文；人工对齐可导出/删除；超长文献分批处理、可取消恢复。若后续建议新的向量模型或 diff 依赖，标记 **实施前需用户确认**。

### 9.5 阅读问题与证据书签

**用户问题：** 普通书签只能记位置，不能表达“此处待核、与另一文献矛盾、需补引文”等研究意图。

**MVP：** 在稳定 locator 上创建问题书签，包含类型、状态、项目、备注和关联摘录；阅读器侧栏按当前文献分页显示，研究工作台可按状态汇总。上述结构化状态和关联关系属于 MVP 必需项。

**实现影响：** 基础 note 复用现有 `research_notes.kind='comment'/'idea'`、project、note、tags 和 `locator_json`；`locator_json` 只保存定位，不塞工作流元数据，也不使用未知 kind（当前未知值会被归一为 `quote`）。MVP 必须旁路新增 `research_note_workflow(note_id, issue_type, status, relations_json, updated_at)` 表表达状态和关联，由旧客户端安全忽略，并按模块 11 走备份、事务和回滚。

**验收与回退：** 关闭功能不影响普通摘录；删除问题不删除正文或关联文献；旧客户端忽略 workflow 表并继续读取基础 comment/idea note。迁移失败不创建半条 workflow 关系。无需新依赖。

### 9.6 OCR 质量热区与校对路线

**用户问题：** 大型扫描文献中，用户不知道哪些页或段最值得优先校对。

**MVP：** 鸟瞰和目录显示 OCR 质量、空页、重复文本、低置信块和版式异常；点击进入对应 stable locator，可按严重度生成校对队列。

**实现影响：** 复用模块 03 的 run/page quality 和问题码，不在阅读器重新计算 OCR。任务和筛选分页；人工忽略/完成状态不被后续 OCR 自动覆盖。

**验收与回退：** 关闭叠加不改变阅读；质量信息缺失时正常降级；重新 OCR 后只更新自动诊断，不清人工处理状态。无需新依赖。

### 9.7 可交换的本地批注包

**用户问题：** 开源用户需要在不同电脑或研究小组间交换目录、摘录和校对意见，但不一定愿意使用云同步。

**MVP：** 导出带文献指纹、stable locators、目录候选、摘录和问题书签的版本化 JSON 包；导入先预览匹配率和冲突，默认不覆盖本地人工内容。

**实现影响：** 复用备份完整性、引用导出和 locator 重定位；格式写入公开 schema 和版本。第一版不引入服务器或账号。

**验收与回退：** 文献不匹配时只保存为待绑定包；重复导入幂等；导入失败事务回滚。若后续加入实时协作或云同步，属于外部服务，必须 **实施前需用户确认**。

## 10. 依赖、迁移与审批

- 阶段 A 至 D 可使用现有 Electron、React、better-sqlite3、worker_threads 和 shared 工具完成，不新增依赖。
- canonical provider adapter、stable locator 和 projection mapping 先以纯 TypeScript 实现；不把第三方阅读器引擎作为正确性的前提。
- 默认不重写现有 `pages`、active `document_toc_items`、reader state、translation cache 和 `research_notes`。旧字段继续读取，新 locator/版本可惰性生成。
- 旧目录是明确例外：当前清理会删除尚存兼容数据，必须先冻结清理，再在自动备份后把 `legacy` 行和 metadata 目录迁移为可验证候选；失败保持原数据并回滚。
- 若实测需要 `document_toc_versions`、reader history、source mapping 或 locator 索引，必须旁路新增，自动备份，事务创建/回填，失败回滚，旧版本忽略新表，并完成升级/降级恢复演练。
- 页面保存第一阶段使用 `expectedContentHash`，不要求给 `pages` 加 revision 列；若采用模块 03 的 proof revision/artifact 旁路表，必须复用同一版本身份，不能再建第二套 revision。
- EPUB CFI 继续作为 EPUB 原生定位输入，但应用内部仍转换为统一 locator；不删除现有 href/CFI 数据。
- 新的 EPUB/PDF 引擎、排版库、diff 库、向量模型、云同步或协作服务都必须单独评估许可证、包体、Windows 打包、隐私、维护和回退，并标记 **实施前需用户确认**。

## 11. 与其他模块的约束

- OCR 模块必须拥有唯一 `CanonicalContentProvider.resolvePage(...) -> CanonicalPageContent`、不可变 artifact 版本和稳定 block identity；重新 OCR 不得清除人工校对或让 locator 无诊断漂移。
- 导入模块必须保留 PDF 页、EPUB href/CFI、结构化元素和来源指纹；不能为了快速入库只保存当前渲染文本。
- 检索模块必须返回 stable locator、source hash 和当前 canonical version；阅读器不能用 `charStart=0` 等猜测替代缺失定位。
- AI 模块生成目录、排版、摘要和回答时必须记录真实输入版本；生成内容只能形成候选投影，不能覆盖 canonical text 或人工目录。
- 翻译模块按 stable source slice 和 canonical hash 缓存，人工译文优先；虚拟页和显示模式不能成为持久化身份。
- 引用与导出模块使用同一 locator 和 canonical content，导出内容必须与用户屏幕上选择的版本一致。
- 数据库模块提供 revision、任务、artifact、备份和恢复边界；阅读器不得在 renderer 维护唯一任务真相。
- 数据库模块必须把 `stripLegacyTocMetadata` 视为待修复的破坏性迁移，不得在兼容迁移验收前继续清理旧目录来源。
- UI 与交互模块统一工具栏、焦点、键盘、错误和进度样式，但古籍原图/校对与论文/EPUB 阅读预设都必须保留。
- 性能模块建立固定合成文献和持续交互基准；有界内存、主进程不阻塞和真实重开恢复属于发布阻断门槛。
- 新版验收必须在正式实现前更新并落成自动化；完成业务实现后先交用户本地测试，用户明确确认无问题前不得 push、公开 PR、触发 GitHub Actions 或发布 Release。
