# 10 翻译、引用、导出与研究写作

## 1. 本章结论

GujiSmart 已经形成“逐单元翻译、项目/全局术语表、历史与现代文献引用、PDF/HTML/文本/结构化导出、TeX 排版、摘录整理与研究输出”的完整产品雏形。古籍、地方志、档案与现代 PDF、论文都已有可继续演进的入口，不需要为了重构改成单一文献模型，也不应牺牲任何一类用户。

当前阻断成品可信度的不是格式数量，而是五条边界尚未闭合：renderer 可让 main 读取任意规则文件并把内容发送给外部模型；TeX 编译目录与编译输入缺少文件和执行隔离；翻译返回可覆盖用户并发完成的人工修改；摘录正文修改后仍保留旧来源 hash/locator；多数导出直接写最终路径，失败可能破坏原文件。另有多套“正文真相”、缓存与输出缺少版本身份、长任务只存在内存、引用缺字段仍被判定可用，以及研究写作把截断输入和当前引用状态包装成完整结果等 P1 问题。

建议不做一次性重写。先封住 P0 文件、网络、编译和并发写入风险，再复用模块 03 的 `CanonicalContentProvider -> CanonicalPageContent`、模块 05 的 `StableReaderLocator`、模块 01/02/03 的唯一 `TaskStateEnvelope + task_jobs/task_items`、模块 06/07 的 evidence/aggregate/output lineage。翻译、引用、导出、排版和写作只保留各自领域策略，不再各自判断正文、定位、任务、证据和文件安全。

第一阶段可以不新增第三方依赖、不更换 SQLite、不强制迁移现有数据库。Node 标准库、现有 SQLite/Electron/React/Ant Design 与已安装导出组件足以完成 P0/P1 护栏。任何新字体、CSL/引文处理器、TeX 发行版、本地模型、云翻译、外部学术服务或写作同步服务，都必须先向用户说明许可证、体积、隐私、维护和回退并取得确认。文献与任务总量不设产品上限，但 worker、provider 请求、IPC 响应、内存、文件批次和并发必须有界。

## 3. 当前端到端数据流

### 3.1 翻译、术语与搜索

页面翻译由 renderer 经 `translation:getPagesUnits/translateDocument` 进入 `translation-service`。`buildTranslationUnitDrafts` 从 OCR 结构块生成单元，服务读取 active model、glossary 和模式，按单元/字符批次调用 provider，再写 `page_translation_units`，同时生成旧版 page cache；ready、非 stale 的译文随后可进入搜索。`ParallelTranslationView` 读取所有单元，展示原译并排、人工覆盖、重试和状态。

这条链路已有固定批次数与人工覆盖字段，但正文选择不一致：`translation-source.ts:926-938` 的页面 helper 优先 proof，`translation-units.ts:101-144` 却只要存在 OCR blocks 就忽略 `proofed_text`；glossary 又按 `proofed_text || ocr_text` 匹配。模型、模式、术语和 style 也没有共同冻结进当前单元的 source identity，因而“页面看的是校对稿、术语按校对稿匹配、实际翻译旧 OCR 块”可以同时发生。

### 3.2 引用样式、字段解析与摘录引用

引用由文献 metadata、类型模板、样式模板和页码 override 组成。`history-citation.ts` 提供古籍、方志、档案、论文、专著等类型；`ipc/citation.ts` 读取数据库样式/模板并渲染，CitationView 支持新增样式、编辑模板、插入占位符、样例预览和 AI 从规则文件生成草稿。摘录页则由 `renderer/utils/citations.ts` 逐条请求当前引用并附加页码，最终生成 Markdown。

当前 shared resolver 与 main 实际字段优先级并不完全一致，resolver 的 `usable` 又没有格式级必填字段。main 生成时会清掉未解析占位符，renderer 只收到字符串而收不到 diagnostics。于是“看起来完整”与“证据字段完整”没有可验证关系；样式、模板和 metadata 后续变化还会让同一摘录的引用悄悄改变。

### 3.3 多格式导出

导出入口选择文件或目录后，main 查询文献、页面和目录，补充 OCR 版本与大字段，再按类型生成普通 HTML、仿真 HTML/PDF、图片 PDF、原生布局 PDF、TXT、Markdown、TEI XML、PAGE XML 或 Paddle JSON。导出器已支持古籍左右页、竖排、页眉页脚、目录、表格、图片和多种结构化交换格式。

当前查询、hydrate、正文拼接与格式渲染不是一个冻结 snapshot；每个导出基本一次性物化整篇内容。原生 PDF 会切掉超出版面上限的行，结构化格式对 proof/OCR 的选择也不一致。多数分支直接写最终路径，HTML-PDF 虽有临时 HTML，也仍直接由浏览器打印到目标文件。导出成功目前只意味着函数返回，不意味着内容完整、来源一致、字体可显示、文件可恢复或可移植。

### 3.4 TeX 排版

TypesetEditor 从当前 OCR layout 构造 paragraph/title/table/image annotation，用户可改类型、内容、字号和对齐，再由 `generateTeX` 生成源码。main 把源码写到按 `docId` 命名的输出目录，调用 LuaLaTeX 最多两次，并以 `document.pdf` 是否存在作为成功依据；renderer 用 blob URL 预览或下载 `.tex`。

这条链路尚未接入 canonical proof、revision、任务、文件 capability 或隔离编译。annotation 只保存在组件 state，OCR/title 变化会整体重建；同文献并发编译共享一个目录，旧 PDF 可能被当成新结果。TeX 是可读取本机文件的程序输入，不能继续按普通字符串转换看待。

### 3.5 摘录、AI 分析与研究写作

ExcerptsView 一次读取全部研究项目与摘录，在 renderer 做筛选、排序、分组、引用解析和 Markdown 拼接。用户可编辑摘录/备注/引用、打开来源、复制当前视图或选中项，也可把当前范围交给 AI 研究并保存 task/output。

当前 AI context 静默只取前 36 条，却用完整筛选集合计算界面数量；文库检索失败时静默退化为摘录-only；跨文献任务只关联第一个 doc。更严重的是 research update 在 excerpt/page 改变时继续保留旧 `source_hash/locator_json`。因此当前写作产物没有稳定的“输入集合、遗漏原因、引用版本、claim 到 evidence”的不可变链路。

### 3.6 古籍与现代论文必须等价

古籍需要版次、卷次、责任者、刻印/藏本、页图、栏/叶面、竖排和异体字；现代论文需要作者顺序、年份、期刊/会议、卷期页、DOI、表格、公式和章节。两者共享 canonical content、locator、任务、引用诊断、export snapshot、文件安全和写作 lineage，但允许不同 preset、字段 schema、翻译保护器和渲染器。任何验收都必须用两类 fixture 分别通过，不能用一类成功推断另一类正确。

## 4. 必须保留的能力

- 保留古籍、方志、档案、族谱、碑刻、手稿以及论文、专著、学位论文、会议论文等类型；只统一底层合同，不减少格式。
- 保留 proof/IR/OCR、版面块、页图、目录、左右页和竖排等现有来源；统一选择权交给 canonical provider。
- 保留翻译单元、fast/balanced/quality 模式、项目/全局术语优先级、人工覆盖、单元重试、旧页面译文兼容读取和 ready 译文检索。
- 保留原译并排、页宽/字号调整、块类型与 stale/error/manual 状态；状态展示改进不能隐藏已有人工译文。
- 保留引用样式库、文献类型模板、字段占位符、实时预览、规则文件生成草稿和摘录页码 override。
- 保留 PDF、HTML、TXT、Markdown、TEI、PAGE XML、Paddle JSON 等格式，以及图片 PDF、原生古籍版式和目录/表格/图像能力。
- 保留排版 annotation、TeX 源码、PDF 预览和用户自有 LuaLaTeX 环境；安全收紧不得强制安装新的 TeX 发行版。
- 保留摘录的列表/卡片/分组、过滤、批量选择、项目关系、来源回跳、Markdown 复制和研究输出入口。
- 保留旧数据库、旧 translation cache、旧 citation style/template、旧 research note/output 的兼容读取；旧数据只能标 legacy/unverified，不能伪装成新版 verified。
- 保留本地优先与离线退路。外部模型不可用时，人工翻译、引用模板、非 AI 导出、TeX 源码编辑和研究整理仍须可用。

## 5. 关键问题

### D10-P0-01 引用规则文件可读取任意本机文件并将内容发送给外部模型

**证据等级：已确认。** `citation:inferStyleFromRuleFile` 直接接受 renderer 提供的 `filePath`（`src/main/ipc/citation.ts:645-651`）；PDF、DOCX、TXT 提取器直接读取该路径（`:310-364`），提取文本随后进入 `callLLM`（`:418-450`）。没有文件对话框签发的 capability、允许根目录、canonical path/符号链接校验、大小/解压预算，也没有外传内容预览和逐次确认。

**影响：** renderer/XSS 一旦被利用，可读取任意可读文件并借用户配置的 AI endpoint 外传。路径、私有研究材料和凭据文件都可能泄露；这是本地文件边界与网络边界同时失守。

**落实方案：** renderer 只提交 main 签发的一次性 `FileCapabilityId`，main 在用户选择时冻结 canonical path、文件标识、允许用途、大小、有效期和是否可外传。解析在 worker 中执行，限制页数、展开字节、压缩比和超时；先返回本地 `RuleImportPreview`（文件名、类型、截断/覆盖范围、将发送的字符数和目标 provider），用户确认后才发送最小文本。capability 消费一次即失效，日志、错误和模型请求不包含绝对路径。

### D10-P0-02 TeX 编译允许路径穿越并执行未隔离的文档程序

**证据等级：已确认。** main 用 renderer 的 `docId` 拼接 `dataDir/tex_output/<docId>` 并写文件（`src/main/typeset.ts:166-173`），IPC 未限制该值；LuaLaTeX 直接编译用户可控 TeX（`:185-195`），没有 path containment、每次独立工作目录、输入白名单、网络/文件系统隔离或明确 shell-escape 策略。环境探测还直接信任 PATH（`:18-39`）。

**影响：** 恶意 `docId` 可越出目标目录；TeX 可读取本机文件、写辅助文件，并利用发行版能力扩大影响。即使 renderer 未被攻陷，粘贴的 TeX 也属于不可信程序输入。编译安全不能依赖 UI 不暴露恶意值。

**落实方案：** IPC 只接受数据库校验过的 document ID 或 main 签发的 compile session；每个 attempt 使用随机、受控、已验证位于 app 临时根下的目录。固定可执行文件路径/指纹与参数，显式禁用 shell escape，限制输入/输出/运行时/进程树，并以最小允许的 TeX 能力运行；无法建立可靠 OS/TeX 沙箱时，把“编译任意 TeX”降级为明确风险的用户主动能力，默认只生成源码。成功只发布 manifest 中 hash 匹配的本 attempt PDF，临时目录按策略隔离清理。

### D10-P0-03 provider 返回可覆盖用户并发完成的人工翻译或新来源

**证据等级：已确认。** 翻译开始时读取一次 `unit.manualOverride`，保存时只依据该旧对象跳过（`src/main/translation-service.ts:445-465`）；SQL UPDATE 没有 `manual_override=0`、`expected source_hash`、attempt 或 generation 条件。用户在模型请求期间经 `updateTranslationUnit` 修改单元（`:706-726`）后，迟到 provider 结果仍会覆盖正文，同时行可能继续标记 manual override。来源在请求期间变化时也可把旧结果写成 ready、非 stale。

**影响：** 人工劳动不可恢复地丢失，数据库状态还会谎称它是人工结果；校对稿变化后旧译文也可被激活。这是明确的数据损坏与竞态，而不是普通 UI 反序。

**落实方案：** start 时冻结 `unitId/sourceHash/contentVersion/manualRevision/translationContextHash/attemptId`；提交使用单条 CAS：只有 source/context 未变、manual revision 未变且 `manual_override=0` 才可激活。CAS 失败保留 provider 结果为 detached candidate，不覆盖当前行，并返回 `superseded/manual-conflict/source-stale`。人工保存同样用 expected revision；重试创建新 attempt，所有事件按 attempt 隔离。

### D10-P0-04 修改摘录正文或页码后仍保留旧来源身份，形成错误证据

**证据等级：已确认。** ExcerptsView 可同时提交 excerpt、pageNum、citation 等更改（`src/renderer/src/views/ExcerptsView.tsx:565-576`）；research update 先保留当前 `source_hash/locator_json` 再展开更新字段（`src/main/ipc/research.ts:889-937`）。公开回归只验证创建时 hash 和不涉及 excerpt/page 的更新，没有覆盖来源身份失效。

**影响：** 用户改写引文或页码后，系统仍可把它作为原来源的 verified 摘录用于 AI、引用和正式写作。结果看似有 locator/hash，实则正文与证据不相符，属于研究完整性破坏。

**落实方案：** 分离不可变 `ResearchEvidenceRevision` 与项目 annotation。修改 note/tags 不改变 evidence；修改 excerpt/page/locator 必须创建新 evidence revision，并通过 `SearchEvidenceResolver` 重新验证 quote/hash。无法验证时状态为 `needs-review/unverified`，不得继承旧 verified。若用户明确要改写为释义，创建 annotation/paraphrase 并保留指向原 evidence 的关系，不能冒充直接引文。

### D10-P0-05 导出直接写最终路径，失败可能破坏用户已有文件

**证据等级：已确认。** 原生布局 PDF 与图片 PDF 直接 `writeFileSync(outputPath, ...)`（`src/main/export.ts:2286-2288`、`:2318-2320`）；HTML-PDF 直接打印到目标路径（`:2514-2522`）；HTML（`:2603-2608`）及文本/XML/JSON（`:2627`）也直接写最终路径。没有同目录临时文件、flush/fsync、内容校验、hash、原子 rename、旧文件保留和失败恢复。

**影响：** 磁盘满、进程退出、字体/图片/浏览器失败或格式校验失败时，目标可能变成空文件或半文件，并覆盖用户上一版成果。批量导出还会产生一部分成功、一部分破坏的混合目录。

**证据等级：已确认。** AI context 对筛选结果使用 `.slice(0, 36)`（`src/renderer/src/views/ExcerptsView.tsx:365-376`），界面范围和计数仍基于完整集合（`:398-433`、`:1000-1002`）。文库搜索失败被 catch 后静默继续摘录-only（`:405-412`），task/output 关联第一个 doc（`:405-427`）。

**落实方案：** operation preview 由 main 计算 population、processed/omitted、预算、数据源和 fallback；跨 36 条或跨文献直接创建 research job，按 cursor 生成 immutable input coverage manifest。检索失败进入 paused/error 或用户确认的降级 attempt；output 关联 project/scope snapshot/evidence pack，不伪造单一 doc owner。

### D10-P1-18 摘录页码、引用和写作输出没有统一 stable locator 与版本快照

**证据等级：已确认。** renderer 从 `source_id` 字符串和 note.page_num 猜页（`src/renderer/src/utils/citations.ts:92-105`），失败时以作者/标题和页码拼一个看似正式的 fallback（`:108-119`）。复制 Markdown 只有 excerpt/note/citation（`:163-184`），没有 locator、contentVersion、style/template snapshot、evidence ID 或 output lineage。

**影响：** 页码可能混淆 viewer index、印刷页、叶面和 PDF 页；文献 metadata/默认样式改变后历史写作无法重现。来源不可解析时仍可产生无标记的正式字符串。

**落实方案：** 页/块/选区/translation unit 全部使用模块 05 `StableReaderLocator`；显示页码是 locator 的 citation projection，不是身份。复制/导出冻结 `CitationSnapshot` 与 evidence refs；fallback 必须标 `legacy-unverified/draft`，无法验证的 exact quote 不进入正式写作。

### D10-P1-19 翻译、引用和摘录核心操作缺少键盘语义与窄窗重排

**证据等级：已确认。** ParallelTranslationView 的可选择/编辑区域是无 role/tabIndex 的 div，编辑/重试图标仅有 title（`src/renderer/src/components/ParallelTranslationView.tsx:209-277`），两列最小宽度导致窄窗横溢（`:99-104`）。摘录“复制引用”主要在右键菜单；模块 08 已将其列为 D08-P1-13。引用/翻译核心区域也没有统一窄窗布局。

**影响：** 键盘、读屏、200% zoom 和小窗口用户无法可靠完成研究闭环；图标状态和失败恢复不可发现。

**落实方案：** 使用语义 button/list/table/textarea、独立焦点与 `aria-label`/tooltip；行级操作有键盘菜单和显式命令入口。窄容器切换 source/translation tabs 或纵向堆叠，工具条可换行但不遮正文；状态由统一 `StatePanel/StatusBadge/ProgressSummary` 展示，颜色不是唯一信号。

### D10-P2-01 语言判断会静默跳过短外文、混合文本和特殊学术片段

**证据等级：已确认。** `translation-text.ts:35-52` 对少于 24 个 meaningful 字符、外文比例不足或混合文本返回不可翻译，较长混合文本又要求至少 120 个外文字符。短引文、标题、公式旁注和双语摘要容易被误判。

**影响：** 单元被 silent skipped，古籍夹注和论文术语不能稳定翻译。启发式规则被当成事实，而非建议。

**落实方案：** language detection 只产出 reasoned hint；用户选择的目标范围默认可翻译。skip 必须显示原因并可单元强制；按 script/block kind 分段，保留短文本 fixture。未来引入检测模型需单独审批，第一阶段使用现有规则即可。

### D10-P2-02 翻译 UI 隐藏 partial/stale 旧结果，计数名称与真实含义不符

**证据等级：已确认。** loading 时只显示首个 placeholder，已提交批次不可见（`src/renderer/src/components/ParallelTranslationView.tsx:201-206`）；stale/error 的保留译文被 `getDisplayTranslationForUnit` 隐藏（`:16-20`）。service 的 `cachedCount` 实际更接近 manual ready 数（`src/main/translation-service.ts:530-549`）。

**影响：** 用户误以为成果消失，无法比较旧译或决定是否重试；进度和缓存命中不可解释。

**落实方案：** 保留并标记 last-known translation，提供“当前/旧版/候选”比较；loading 增量展示 committed units。指标改为 expected/ready/manual/cache-hit/stale/error/omitted，均从 committed task artifacts 计算。

### D10-P2-03 常用现代格式未进入可管理顺序，缺年份还会制造当前年份

**证据等级：已确认。** `history-citation.ts:69-91` 的 format order 不含 GB/T 7714、APA、MLA、Chicago、Custom，尽管 label/default 已存在（`:62-66`、`:256-260`），CitationView/AI sanitizer 因而无法完整管理这些 slot。引用 key 在缺年份时使用当前年份（`src/main/ipc/citation.ts:244`）。

**影响：** 现代论文用户看得到名称却不能稳定配置；同一条缺年份记录会随年份变化，破坏可复现性。

**落实方案：** format registry 显式列出全部支持格式及版本/适用类型/required fields；缺年份使用 `n.d.`/`无年` 或格式规则，不制造系统当前年。旧自定义模板保持原 order adapter。

### D10-P2-04 引用预览、样式编辑与错误提示可能掩盖真实缺陷

**证据等级：已确认。** CitationView 用文库第一篇文献做预览，失败后静默改用 sample（`src/renderer/src/views/CitationView.tsx:404-425`）；修改 format type 会用默认值覆盖当前 draft（`:700-710`），规则文件入口没有清楚展示外传/截断范围（`:837-944`）。

**影响：** 错误模板可能因 sample fallback 看起来正常；用户切换类型丢失未保存内容，且不清楚 AI 读取了什么。

**落实方案：** 预览明确标 sample/library/error，并可选择古籍/论文 conformance fixtures；类型切换保留草稿或确认替换。外传 preview 使用模块 07 的披露合同，错误不静默换数据源。

### D10-P2-05 临时文件、YAML 与 schema 维护仍有可复现性和兼容隐患

**证据等级：已确认。** HTML 临时名只用 `Date.now()`（`src/main/export.ts:2469`），并发同毫秒可能碰撞；Markdown YAML frontmatter 值未可靠引用/转义（`:2613-2614`）。citation schema 在普通读取路径中补字段并反复保存（`src/main/ipc/citation.ts:63-90`）。

**影响：** 并发导出互删临时文件，标题/作者含冒号或换行时 Markdown 失效；读操作带 schema 写副作用，故障边界难审计。

**落实方案：** 临时路径使用 `mkdtemp`/随机 attempt ID；YAML 用现有结构化 serializer 或严格标量编码并做 parse round-trip；schema 迁移集中到版本化 migration，不在 read path 隐式写。

### D10-P2-06 关键回归以源码字符串证明安全，形成错误置信

**证据等级：已确认。** translation-units 回归用存在 `if (unit.manualOverride) continue` 证明人工保护，却未运行并发 provider/edit；citation 回归明确断言缺作者/来源仍 usable；AI/source/reader 多个脚本只查源码片段。

**影响：** 重构可以满足字符串而行为仍错误，也可能因正常改名产生假失败。P0/P1 文件、CAS、snapshot、截断和 lineage 风险没有故障注入门禁。

**落实方案：** 保留纯函数单测价值，但将发布阻断项改成真实 temp DB、IPC、worker、文件故障、provider mock、restart、Playwright/NVDA 行为测试；源码扫描只用于开源卫生和明确的禁止模式，不能证明业务正确。

### D10-P3-01 缺少可复现的引用规范一致性工作台

**证据等级：产品能力缺口。** 当前有模板编辑和单样例预览，但没有格式版本、fixture corpus、required field coverage、差异报告和导入/导出样式包。

**影响：** 用户维护复杂古籍或期刊规范时只能肉眼逐条试，规则更新后无法知道哪些文献类型回归。

**落实方向：** 在核心 resolver/diagnostics 稳定后提供 Citation Conformance Lab；详见 D10-NF-02。

### D10-P3-02 缺少跨文献的翻译术语一致性与审校闭环

**证据等级：产品能力缺口。** 当前能按单元编辑和重试，但没有术语命中对照、同源多译、遗漏保护符、人工批准记忆和 QA 报告。

**影响：** 长古籍、系列论文与团队式研究难以保持术语和专名一致，人工修改不能转化为可审阅资产。

**落实方向：** 建立本地 Translation QA Workbench；详见 D10-NF-01。

### D10-P3-03 缺少版本化写作画布和逐论点证据审计

**证据等级：产品能力缺口。** 当前摘录可复制 Markdown、研究输出可保存，但不是可编辑的 parent-linked writing revision，claim 与 evidence/citation snapshot 也没有可视化关系。

**影响：** 研究者仍需在外部工具手工维护引文与证据，修改后难以判断哪些论点失去支持。

**落实方向：** 复用模块 07 output/claim lineage 提供写作画布，不另建第二套 evidence；详见 D10-NF-03。

## 6. 目标架构与兼容策略

```text
CanonicalContentProvider.resolvePage
  -> CanonicalPageContent(contentVersion, sourceHash, text, blocks, artifact refs)
     -> TranslationSourceSlice + StableReaderLocator
        -> TranslationContextSnapshot -> unit attempts/cache/QA
     -> CitationResolver -> CitationSnapshot + diagnostics
     -> ExportSnapshot -> bounded render items -> AtomicExportWriter
     -> TypesetDraftRevision -> isolated compile attempt -> TypesetArtifactManifest
     -> ResearchEvidenceRevision -> input/claim manifests -> ResearchOutputSnapshotV2

TaskStateEnvelope + one task_jobs/task_items scheduler
  -> translation | citation-batch | export | typeset | research-writing
  -> bounded claim/lease/cursor/attempt/heartbeat/cancel/restart

FileCapability + Storage Operation Coordinator
  -> read rule/source assets | write export | compile temp root
  -> canonical path, purpose, budget, expiry, atomic publish, redacted manifest
```

核心原则：

- canonical 正文、定位、证据、任务和文件安全各自只有一个权威合同；本模块只能增加 translation/citation/export/typeset/writing 领域字段。
- 翻译、引用、导出和写作必须冻结输入身份。当前页面对象、默认样式、renderer state、文件路径和 cache key 都不能代替 snapshot。
- 用户可创建的文献、页、单元、摘录、任务和输出总量不设上限；单次 IPC、SQL 参数、worker claim、模型请求、内存、解码像素、打开文件和并发必须有界。
- preview 可以截断，但必须显示 coverage/continuation；标为完整的导出、引用清单或研究输出不得使用截断 preview。
- 古籍和现代论文使用同一真实性、安全和恢复门禁；preset 只能改变默认字段、保护规则与版式。
- 第一阶段零迁移优先。旧数据经 adapter 读取并标 legacy；只有确需持久 lease、不可变 revision/manifest 或唯一约束时才做共享 additive migration。

### 6.1 Canonical translation 与稳定单元

```ts
interface TranslationSourceSlice {
  locator: StableReaderLocator
  contentVersion: string
  sourceHash: string
  sourceKind: string
  text: string
  structureRole: string
}

interface TranslationContextSnapshot {
  source: TranslationSourceSlice
  targetLanguage: string
  mode: 'fast' | 'balanced' | 'quality'
  providerId: string
  model: string
  parametersHash: string
  glossaryVersion: string
  promptVersion: string
  protectorVersion: string
  normalizerVersion: string
  contextHash: string // SHA-256
}
```

单元 identity 以 StableReaderLocator + canonical version 为基础，坐标和 block order 只作重定位线索。每次 provider 调用产生 attempt，激活必须 CAS 当前 source/context/manual revision。人工译文、机器候选与 last-known stale 结果分别存储/投影，不能互相覆盖。旧 `page_translation_units` 和 legacy page cache 继续读；v2 context 可先放版本化 metadata，持久 job/revision 最终复用共享表。

### 6.2 唯一任务状态与资源边界

长翻译、批量引用、跨页导出、TeX 编译和研究写作直接复用模块 01 的闭合状态：`queued|running|paused|completed|error|canceled`。partial 只能是 `completed + completionKind='partial'`，credential/font/compiler/磁盘/人工复核阻塞使用 `paused + blockedReason`。每个 item 保存 stable input ref、cursor、attempt 和 committed artifact；设置 JSON 只能保存 jobId/展示快照，不保存第二份 lease 或 status。

资源预算至少包含：每 worker 的 page/unit 数、字符/token、图片像素与解压字节、SQL 参数、IPC 响应字节、打开文件数、provider 并发、编译时间和临时磁盘。单个超长单元/资源不能突破预算，必须切片、单独处理或明确暂停。短请求也有 deadline 和 response bytes；取消必须贯穿 worker、provider、backoff 和子进程。

### 6.3 CitationResolver 与引用快照

```ts
interface CitationResolution {
  documentId: string
  citationType: string
  formatId: string
  styleVersion: string
  templateVersion: string
  fields: Array<{ name: string; value?: string; source?: string; status: 'resolved'|'missing'|'invalid' }>
  locator?: StableReaderLocator
  diagnostics: Array<{ code: string; severity: 'info'|'warning'|'error'; field?: string }>
  verificationStatus: 'verified'|'draft'|'blocked'|'legacy-unverified'
  rendered?: string
}
```

required/recommended 字段由 versioned registry 按 type + format 决定；main resolver 统一 metadata priority、field mapping、页码 projection、模板选择和 escaping。`CitationSnapshot` 冻结 resolution、style/template/metadata/content version 与 hash，供摘录、写作和导出引用。样式编辑 preview 与正式生成走同一 resolver；缺目标类型模板不得回退到任意类型。

### 6.4 ExportSnapshot、原子文件与排版产物

`ExportSnapshot` 由 main 构造，至少记录 document metadata version、TOC version、按 cursor 可读的 canonical page refs/hash、citation/style snapshot、format/options、asset refs 和 expected coverage。renderer 不能提交正文或伪造 snapshot。格式 renderer 只返回有界 chunk、consumed ranges、warnings 与 asset requests；最终对 expected/consumed/omitted 做完整性对账。

`AtomicExportWriter` 与 typeset publisher 共用文件规则：只接受 dialog/capability 授权目标；canonicalize 后验证 containment，不跟随越界 symlink；同目录随机 temp；流式写与 SHA-256；格式 parse/页数/资源校验；flush/fsync；原子发布；失败保留旧目标并输出 redacted manifest。portable bundle 使用相对 asset ID，不包含不必要绝对路径。

TeX draft 是绑定 canonical source 的 revision；compile attempt 使用独立目录、固定 compiler identity/flags、时间/内存/输出预算和 cancel。只有本 attempt 新生成且 hash/parse 成功的 PDF 可进入 `TypesetArtifactManifest`。安全沙箱能力不足时，默认仍允许导出 TeX 源码，但不把本机编译描述为安全完成。

### 6.5 写作证据与不可变 lineage

模块 07 唯一拥有 `ResearchEvidence`、`ResearchAggregateArtifact`、input coverage、claim manifest 和 `ResearchOutputSnapshotV2`；本章只增加 translation/citation/typeset/export refs。直接引文修改创建新的 evidence revision 或降为 paraphrase annotation；verified 状态必须由 `SearchEvidenceResolver` 重新计算。

写作 revision 记录 parent、operation intent、输入 manifest、citation snapshots、translation source/unit refs、claim manifest、output hash 和创建时间。每个输入都有 processed/failed/omitted reason，百万条结果通过 immutable cursor/chunk artifact 读取，不内联到 IPC。引用样式、正文或译文变化只把相关 claim 标 stale/needs-review，不静默改写历史输出。

### 6.6 兼容读取与权威边界

| 现有数据 | 第一阶段兼容 | 新版权威状态 |
| --- | --- | --- |
| `page_translation_units`/legacy cache | 原样读取；旧 key 标 legacy，ready projection 校验 coverage | context snapshot + CAS attempt；共享 job item |
| citation styles/templates | 保留 ID、模板文本和默认样式；adapter 补 format registry | versioned style/template + resolution snapshot |
| research notes | 原行可读，旧 locator 标 legacy-unverified | evidence revision + project annotation/relation |
| research outputs v1 | 原内容和 snapshot 不改 | parent-linked output v2 + input/claim manifests |
| 导出文件 | 不追溯改写 | 新产物带 snapshot/manifest/hash；原子发布 |
| typeset state | 当前临时编辑仍可用 | draft revision + compile artifact manifest |

## 7. 分阶段落实方案

### 阶段 A：立即封住 P0 边界

1. 规则文件改为 main 文件 capability、解析预算、外传 preview 与一次性确认；在完成前禁用 renderer 任意路径入口。
2. 校验 typeset document identity、随机 attempt dir、固定 compiler/flags、禁 shell escape、fresh output hash；沙箱不可靠时默认仅生成源码。
3. 翻译提交增加 source/context/manual revision CAS，冲突结果保存为 detached candidate。
4. 摘录修改正文/页码时撤销旧 verified，创建 revision 或 paraphrase。
5. 所有导出接入同目录临时文件、校验、hash 和原子发布。

这一阶段不新增依赖、不迁移业务表；先写 P0 故障测试再改实现。

### 阶段 B：统一 canonical content、locator 和 citation diagnostics

- 翻译单元、glossary、TEI/PAGE/Paddle、typeset 全部消费 `CanonicalPageContent`。
- translation unit、摘录页码和写作引用导入唯一 `StableReaderLocator`。
- 建立 main-only CitationResolver、格式 required fields、field provenance 和 diagnostics；旧字符串 API 保留一个兼容版本。
- 修复公式/表格/段落保护、active OCR 选择与完整 layout overflow。

### 阶段 C：快照、流式文件与有界界面

- 落地 `TranslationContextSnapshot`、`CitationSnapshot`、`ExportSnapshot` 与 artifact manifest。
- 导出/规则解析/大术语匹配移入 worker，按 cursor/stream 处理；ExcerptsView 改为服务端分页与可见窗口引用解析。
- 原译视图与摘录/引用完成窄窗、200% zoom、键盘和读屏闭环。
- cache v2 使用 SHA-256 与完整上下文；旧 cache 隔离读取，不批量改写。

### 阶段 D：接入唯一 scheduler 与重启恢复

- 前置是模块 02/03 的共享 `task_jobs/task_items` 已完成；本章只注册 translation、citation-batch、export、typeset、research-writing kind。
- 持久化 cursor、claim、lease、attempt、provider invocation、commit manifest 和 heartbeat；取消/暂停/重试幂等。
- 大文献、大术语表、批量引用和跨文献写作均使用有界批次；partial/remote-outcome-unknown/磁盘满可恢复。

### 阶段 E：写作 lineage 与版本化输出

- 复用模块 07 evidence/aggregate/output repository，迁移旧 note 为兼容 projection，不复制 evidence 表。
- 完成 evidence revision、citation snapshot、translation refs、input coverage 和 claim manifest；AI 不再 `slice(0,36)` 冒充全集。
- 写作、TeX 和导出 revision 可比较、归档、恢复；源变化触发 stale review，不改历史。

### 阶段 F：成品验证与本地用户验收

- 用合成古籍、扫描方志、中文论文、英文论文、公式/表格、超大文献与坏资源 fixture 完成 `XPT-*`。
- 在固定 Windows 环境记录 IPC p95/p99、renderer responsiveness、峰值内存、临时磁盘、取消延迟和恢复时间。
- 用户真实文库只在本地副本验收，不进入日志、fixture、截图或公开仓库。
- 用户明确确认“测试无问题，并批准公开”之前，不 push、不创建公开 PR、不触发 GitHub Actions、不 tag、不发布 Release。

## 9. 新功能建议

### 9.1 D10-NF-01 翻译 QA 与术语一致性工作台

**用户问题与优先级：** 长古籍、系列论文和双语材料需要发现同词多译、漏译、数字/引文/公式损坏和人工修订传播。P2，中等成本；前置为阶段 B/C 的 stable units、protector 和 context snapshot。

**MVP：** 按项目展示术语命中、候选译法、当前译法、来源 locator、manual/machine/stale 状态；检查 placeholder、数字、专名和术语一致性。用户逐项批准“仅本单元/加入项目术语/忽略”，不自动改正文。

**实现影响：** 复用 translation units、项目 glossary 和任务 cursor；增加可清理 QA artifact 与审阅 annotation，不建立第二套译文。默认完全本地，无新依赖；若未来引入语言检测或质量模型，需单独审批。

**验收与回退：** 古籍异体词、中文论文术语、英文公式分别测 precision/recall；任何自动建议必须可回跳并显示依据。关闭工作台不删除译文/术语，删除 QA artifact 可重建，人工批准记录保留。

### 9.2 D10-NF-02 引用规范一致性实验室

**用户问题与优先级：** 用户需要维护古籍馆藏规范、GB/T、期刊或学位格式，并知道修改影响哪些类型。P2，中等成本；前置为 versioned CitationResolver 和 diagnostics。

**MVP：** 提供合成古籍/论文 fixture corpus、required field coverage、模板前后 diff、批量 preview 和 style package JSON 导入导出；规则文件 AI 只生成 draft，必须通过 conformance 才能设为默认。

**实现影响：** 使用现有模板语言和 JSON，不需 CSL 依赖；style package 含 schemaVersion、license/source note、format/version 与 hash。若引入 CSL processor 或公开样式库，必须先确认许可证、包体和兼容策略。

**验收与回退：** 每个格式/类型有 golden + missing-field 负例，升级能显示差异且旧版本仍可选择。导入失败不改当前默认；删除新版本可回到上一 version，不删除历史 citation snapshot。

### 9.3 D10-NF-03 版本化研究写作与逐论点证据审计

**用户问题与优先级：** 摘录和 AI 报告进入成稿后，研究者需要编辑、比较版本并知道每个事实句由什么支持。P2/P3，高成本；前置为模块 07 output/input/claim manifests 和本章 CitationSnapshot。

**MVP：** 密集的 Markdown/富文本写作视图，revision parent 链、引用插入、claim 状态、来源回跳、stale filter 和“正式/草稿”门禁；只消费唯一 ResearchEvidence/aggregate，不复制摘录。

**实现影响：** 新增 writing projection 与 editor state，持久内容作为不可变 output revision；导出复用 AtomicExportWriter。第一版用现有编辑能力，不引入协作、云同步或新富文本框架。

**验收与回退：** 修改来源/引用样式后历史 revision 不变、新 revision 显示 stale；unsupported claim 不能标正式。关闭写作视图仍可读取/导出 Markdown 和旧 research output；删除草稿不级联删除 evidence。

### 9.4 D10-NF-04 可复现研究交换包

**用户问题与优先级：** 单个 HTML/XML/Markdown 无法同时携带相对资源、引用样式、来源版本和完整性信息。P3，中高成本；前置为 ExportSnapshot、portable assets 与 writing lineage。

**MVP：** 导出 ZIP/目录包，含正文或许可允许的短 quote、相对资源、citation/style snapshot、evidence/output manifest、SHA-256 和人类可读 README；可选择“仅清单/含资源”，preview 明确隐私范围。

**实现影响：** 复用现有 ZIP 能力与 Node crypto，按 stream/cursor 写；manifest 版本化，绝不包含 secret 和不必要绝对路径。第三方字体/模板/原图是否可打包由许可字段决定。

**验收与回退：** 在另一台离线 Windows 环境验证 hash、链接、格式与缺失资源报告；篡改任一文件可检测。失败不影响普通导出，删除交换包不删除应用内文献或研究记录。

### 9.5 D10-NF-05 双语平行语料与版本对照

**用户问题与优先级：** 用户需要把人工译文、机器译文和不同版本原文按可验证单元对照，而不仅是当前页面两列。P3，高成本；前置为 stable unit locator、translation revisions 和模块 05 对读投影。

**MVP：** 选择两份 source/translation revision，以 locator/文本重定位生成候选 alignment，人工确认后导出带 source hashes 的 TMX-like JSON/TSV；自动 alignment 永远标候选。

**实现影响：** 复用 existing unit/parallel projection 和 bounded job；不自动上传语料，不在第一版引入 embedding。alignment 是可删除派生 artifact，不修改原文/译文。

**验收与回退：** 页/块移动、插段、重复句和 source stale 都能显示未决而非错配；古籍分栏和论文段落分别测。关闭功能回到现有逐页并排，删除 alignment 不删除 revision。

## 10. 依赖、迁移与审批

### 10.1 第一阶段依赖结论

- 阶段 A 至 C 可用现有 Electron、Node `crypto/fs/path/stream/worker_threads`、better-sqlite3、React、Ant Design、现有 PDF/ZIP/浏览器导出与测试工具完成，不新增第三方运行时依赖。
- 当前 LuaLaTeX 是用户环境中的外部程序，不应被视为已批准的新依赖。改变发行版、自动下载 TeX、捆绑二进制或引入沙箱工具，均需再次获得用户确认。
- CJK/古籍字体的自动下载、捆绑或替换必须逐项提供来源、许可证、子集化规则、包体和无字体回退，并在实施前获得用户确认。未获确认时只检测用户字体并明确暂停/降级。
- CSL/citeproc、新语言检测/分词/翻译模型、云翻译、外部学术元数据/规范服务、协作/同步服务都不是核心修复前提；任何引入需单独评估隐私、许可证、Windows 打包、维护、离线和卸载回退。

### 10.2 迁移清单与所有权

| 结构 | 必要性与所有权 | 兼容/回退 |
| --- | --- | --- |
| canonical/locator adapter | P1 必需；模块 03/05 权威 | 首阶段动态构造，无业务表迁移；旧 locator 标 legacy |
| cache/context v2 | P1 必需；模块 10 | 新 namespace/additive metadata，旧 cache 只读，不批量重算 |
| `task_jobs/task_items` | 跨模块长任务必需；模块 02/03 唯一拥有 | additive 表、自动备份、旧同步入口适配；本章不建第二套 |
| citation style/template version | P1；模块 10 | 可先以兼容 JSON/snapshot artifact；确需列/表时 additive、事务、旧版忽略 |
| evidence/record/output lineage | P1；模块 07 唯一拥有 | 旧 note/output 投影 v1；新 revision/manifest additive，不原地伪造历史 |
| export/typeset artifacts | P1；模块 10 文件 manifest | 先 sidecar/任务 artifact；备份登记，失败不改旧文件 |

任何数据库迁移都必须先预检 schema/磁盘/foreign key，创建可验证自动备份，以短事务和固定小批 cursor 幂等执行，支持 apply twice、每写点故障注入、结果 count/hash/`foreign_key_check` 和恢复演练。大库可以慢、暂停和降低优先级，不能永久跳过正确性迁移。新增结构只能旁路添加，不删除或重写现有业务表。

### 10.3 隐私、文件与公开审批

- 翻译/引用 AI preview 必须列出 provider/model、发送的正文/术语/规则范围、字符/token、截断和文件来源；默认最小披露，不发送绝对路径、未选项目、完整数据库或 secret。
- 日志、错误、manifest、诊断包和公开 fixture 不含真实正文、Key、私有 endpoint、用户/文献 ID 或本机绝对路径。用户主动选择的目标路径只在本地 UI 显示。
- 新字体、模板、样式包、模型和二进制资源记录来源、版本、许可证、NOTICE、hash、下载/升级/卸载方式。
- 本章只授权本地文档与后续本地实现/验证；用户本地验收和明确批准之前没有任何远程发布权限。

## 11. 与其他模块的约束

- **模块 01 产品与架构：** renderer-facing DTO 必须同步 shared/preload/main/renderer；全部长流程复用闭合 `TaskStateEnvelope`，非法状态由 main 拒绝。普通设置经 typed registry；文件 capability/错误 envelope 进入架构门禁。
- **模块 02 导入与入库：** 翻译、导出和研究 scope 使用 relation/cursor，不传全量 page/doc IDs；持久任务复用唯一 scheduler、lease 和资源优先级，不能让后台导出饿死导入/OCR。
- **模块 03 OCR 与校对：** 只有 active OCR/proof artifact 进入 `CanonicalContentProvider.resolvePage -> CanonicalPageContent`；版本切换使 translation cache、typeset draft、citation evidence 和 export snapshot stale。本章不得重写 proof 优先级或建立第二套 OCR hydrate。
- **模块 05 阅读器与版式：** page/block/selection/OCR box/ebook href/translation unit 只使用 `StableReaderLocator v2`；exact 必填 contentVersion/sourceHash/sourceRanges/quote/context，page/document 不伪造 exact range。页码 display 是 projection，不是新 locator。
- **模块 06 检索：** 译文仅在 ready、非 stale、context verified 后可见；摘录、引用和导出只消费 `SearchEvidenceResolver` 的 verified evidence。无法解析的 hit 显式跳过并给原因，不退到首段。长期写作不能引用有 TTL 的 SearchSnapshot，必须提升为持久 artifact。
- **模块 07 AI 与研究：** 规则推断、翻译和写作沿用 operation preview/外传/attempt 合同；模块 07 唯一拥有 ResearchEvidence、aggregate、input/claim manifest 和 output lineage。模块 10 只附 translation/citation/export refs，不建平行 evidence/output 表。
- **模块 08 UI 视觉：** 翻译、引用、摘录和写作保持安静、密集、可扫描；使用统一 token、StatePanel/StatusBadge/ProgressSummary、窄容器和 200% zoom。所有图标按钮有 tooltip/accessible name，coverage/stale/partial 不只靠颜色。
- **模块 11 数据库与备份：** 文件发布采用 staging/hash/原子切换，不能先删后建；missing/corrupt 显式传播。job/artifact/manifest/revision 纳入备份和完整性检查，临时/cache 可重建；用户人工译文、样式、摘录、写作 revision 和已发布导出不得被维护任务误删。
- **模块 12 性能、测试与发布：** 以本章 `XPT-01` 至 `XPT-38` 为成品门禁，源码字符串不能替代行为；固定机器记录资源。业务成品必须先交用户本地测试，明确批准前不得公开。
- **模块 13/14 路线与冲突复核：** D10-NF 只进入统一路线排期，不暗含依赖批准；最终重点核对 canonical content、StableReaderLocator、TaskStateEnvelope/scheduler、CitationResolver、AtomicExportWriter 与 research lineage 均只有一个权威实现。
