# 09 交互与工作区

## 1. 本章结论

GujiSmart 已经具备接近浏览器式工作台的基础：文献、文件夹、检索和研究可以开成独立标签；标签支持分组、折叠、拖动、搜索和最近关闭恢复；文件夹与文库支持单选、Ctrl/Meta 多选、Shift 范围选择、框选、拖放和批量操作；工作区会保存标签、分组、活动标签和侧栏状态。这些能力应保留，不应退回单页面路由或只能逐项操作的文库。

当前风险不在“功能数量不够”，而在交互状态没有形成统一事务边界。最高风险是默认 `Esc` 在非阅读页直接执行 `window.close()`，绕过设置页离开保护；工作区标签实际只渲染活动页，切换标签会卸载其他页面；工作区保存失败、版本不认识或超过 60 个标签时会静默丢状态；文件夹、标签、摘录 AI 和标签标题刷新没有统一 latest-request-wins；框选是纯鼠标实现，拖动排序在移动途中就持续改写并保存真实标签顺序；批量选择只覆盖已加载数据或静默前 1000 条；删除、移动和排除缺少后端可验证的 undo。

目标不是引入另一套路由框架，而是在现有 React、Zustand、Ant Design、Electron 和浏览器原生能力上建立一个统一的交互内核：`WorkspaceStore + NavigationTransaction + CommandRegistry + Overlay/FocusManager + SelectionModel + DragTransaction + OperationReceipt`。页面总量和历史总量逻辑上不设产品硬上限，活动 DOM、请求、缓存、标签可见窗口和批次必须有界；古籍/扫描史料与现代 PDF/论文使用同一套命令和状态合同，只通过阅读方向、默认工具、密度和工作区 preset 调整默认值。

第一阶段优先零数据库迁移：工作区描述、窗口布局、快捷键和非敏感交互偏好可使用兼容的 renderer/main 本地状态；正文、校对草稿、研究记录、组织关系和任务状态仍由各领域的数据库与任务合同拥有。任何新增依赖、SQLite 表或外部服务都必须在实施前再次获得用户确认。完整实现必须先在本地构建和用户文库副本上验收；用户明确回复测试无问题并批准公开前，不 push、不创建 PR、不触发 GitHub Actions、不发布 Release。

## 3. 必须保留的能力

- 保留首页、文库、文件夹、检索、研究、摘录、引用、设置和多文献标签，不退回单视图状态。
- 保留标签分组、颜色、折叠、搜索、关闭全部/其他、最近关闭恢复、中键关闭和拖动预览；重构后补齐键盘、触控和取消语义。
- 保留文库与文件夹的单选、Ctrl/Meta 多选、Shift 范围、框选、批量栏、右键菜单和拖到文件夹；明确“当前页/已加载/当前筛选全集”。
- 保留文件/文件夹外部拖入、去重、导入进度和目标文件夹语义；拖放只是增强，文件选择器和键盘命令必须同样可完成。
- 保留阅读位置、搜索返回、目录、原图/校对/正文/EPUB 模式和稳定 locator；工作区不能把虚拟页号提升为长期身份。
- 保留 `appWorkspace.v1`、旧快捷键 setting keys 和旧 reader state 的兼容读取；新格式成功写入前不得删除旧快照。
- 保留 local-first、无账号、无遥测和不上传工作区内容的默认；工作区不得保存 API Key、正文、完整 search session 或未授权外传内容。
- 保留古籍竖排/原貌优先和现代论文元数据/表格/引用优先两类工作方式，但不复制两套交互组件和数据库。
- 保留现有 React、Zustand、Ant Design、Electron 和 SQLite；第一阶段不因交互重构更换框架或强制迁移用户库。

## 4. 关键问题

### D09-P0-01 默认 `Esc` 可绕过 dirty/flush 协调直接关闭整个窗口

**证据等级：已确认。** 默认 `back` 是 `Esc`（`src/renderer/src/utils/shortcuts.ts:14` 至 `:21`）。非文献标签激活时，App 的全局监听直接执行 `window.close()`（`src/renderer/src/App.tsx:1946` 至 `:1956`）。设置离开保护只包裹 App 内部导航函数（`App.tsx:894` 至 `:917`），`beforeunload` 也只保存工作区描述（`App.tsx:563` 至 `:574`）。阅读器主动返回会等待位置 flush（`DocumentView.tsx:2190` 至 `:2193`），组件卸载却只 fire-and-forget（`:2715` 至 `:2720`）。

**影响：** 用户在设置页修改未保存配置后，只要焦点不在输入框且没有被 DOM selector 识别的浮层，按一次 Esc 就可能关闭应用并放弃修改；其他领域未来接入 dirty draft 后也会被同一路径绕过。这是可造成用户输入丢失的发布阻断问题。

**落实方案：** 建立唯一 `CloseCoordinator` 和 dirty registry。Esc 只按 `drag cancel -> top overlay close -> transient mode cancel -> reader/navigation back` 的优先级处理，永不隐式退出应用；退出必须是显式命令。BrowserWindow close 事件向 renderer 发起带超时的 `prepare-close`，收集 settings、reader、proof、research draft 的 `clean|saved|failed|needs-confirmation`，只有全部可安全离开或用户明确选择放弃才关闭。保存失败保留 pending snapshot 和恢复动作，不能把关闭成功当作保存成功。

### D09-P1-01 标签页切换会卸载页面，现有快照不足以恢复真实工作上下文

**证据等级：已确认。** `renderView` 只返回活动标签的一个组件（`App.tsx:2227` 至 `:2317`）；切换 `activeTabId` 后原组件卸载。工作区模型只保存有限导航字段（`appWorkspace.ts:31` 至 `:57`），Folders 也仅保存文件夹、名称和 scrollTop（`:14` 至 `:18`）。

**影响：** 搜索结果、研究项目局部状态、摘录筛选、批量选择、展开项、焦点、编辑弹窗和未提交草稿会在标签切换时重置或重新请求。用户看见多个标签，却得不到浏览器标签应有的上下文隔离；古籍校对和多论文对读尤其容易丢工作位置。

**落实方案：** 每个 tab 拥有稳定 `tabId/resourceIdentity/generation` 和版本化的轻量 `viewStateRef`。活动标签与少量 LRU warm tabs 可挂载，其他标签保存领域定义的可序列化 snapshot 后卸载；正文、完整结果和任务不复制进 snapshot。领域页面实现 `prepareSuspend/restoreSnapshot/hasDirtyState`，无法安全暂停的 dirty 页面留在有界 warm set 或先完成持久化。总标签可搜索可恢复，活动 DOM 数有明确上限。

### D09-P1-02 v1 恢复会静默截断标签/分组，并在未知版本时删除原快照

**证据等级：已确认。** `MAX_RESTORED_TABS=60`、`MAX_RESTORED_TAB_GROUPS=40`（`appWorkspace.ts:74` 至 `:83`）；sanitize 循环到上限直接 break（`:249` 至 `:268`、`:336` 至 `:354`），保存时也先执行同一截断（`:393` 至 `:413`）。版本不等于 1 时直接 `removeItem`（`:357` 至 `:365`）。界面没有“未恢复 N 项”提示。

**影响：** 当前会话可以继续打开超过 60 个标签，但下一次保存/重启会无提示消失；新版写入格式再被旧版打开时，旧版会删除新版快照，破坏回滚和前向兼容。

**落实方案：** 取消静默产品上限。可见/挂载标签窗口有界，全部 descriptor 进入可搜索 overflow/工作区索引；若达到存储预算，阻止新增或提示归档，而不是丢弃已有项。读取未知 schema 时保留原 bytes，显示“此版本无法恢复”并从最后兼容快照启动。v2 使用新 key、manifest、item count 和 checksum；v1 只在 v2 写入及回读验证成功后标记可清理，回滚期内继续保留。

### D09-P1-03 工作区保存是同步 fire-and-forget，没有 last-known-good、错误提示或关闭确认

**证据等级：已确认。** `saveAppWorkspace` 捕获所有异常并仅返回 boolean（`appWorkspace.ts:393` 至 `:417`）；App 在每次 tabs/groups/active/sider 变化和 beforeunload 中调用后忽略结果（`App.tsx:554` 至 `:574`）。拖动排序期间 tabs 可逐帧变化，因此同一路径会同步 JSON stringify/setItem 多次。

**影响：** localStorage 不可用、quota 满、序列化异常或关闭时写入失败时，用户仍以为工作区已保存；下一次启动回到旧状态。直接覆盖单 key 也没有经过校验的前一份快照可供恢复。

**落实方案：** 只在已提交的交互事务后 debounce 保存；写 `pending -> read-back/validate -> current`，保留 last-known-good 和单调 revision。保存结果进入非阻塞状态栏，失败时给出重试/导出描述/清理旧快照动作；关闭协调器必须知道是否仍有未持久化 revision。workspace descriptor 可使用浏览器内置 IndexedDB 或原子 main sidecar，但采用前必须先做 v1 双读、断电和回滚测试，且不得保存业务正文。

### D09-P1-04 多个异步流程没有共同的 latest-request-wins 身份

**证据等级：已确认。** FoldersView 切换文件夹后直接 await 并写 `folderContent`，没有 folderId/request generation 校验（`FoldersView.tsx:383` 至 `:415`、`:441` 至 `:444`）；TagsView 的标签和文献加载同样直接写 state（`TagsView.tsx:100` 至 `:123`）；Excerpts AI 请求完成后无条件写回结果和 loading（`ExcerptsView.tsx:392` 至 `:440`），即使输入变化已清空结果（`:984` 至 `:997`）；文献标签标题刷新只校验 tabId，不校验该 tab 当前 docId（`App.tsx:1077` 至 `:1088`）。LibraryView 的递增 requestId（`LibraryView.tsx:2268` 至 `:2344`）证明现有代码已有可复用模式，但尚未统一。

**影响：** 快速切文件夹、搜索、文献或 AI 问题并人为反转响应顺序时，旧数据可覆盖当前界面，旧请求还可提前清除新 loading。用户可能在标题 B 下操作文件夹 A 的文献，或把旧 AI 回答误认为当前问题的结果。

**落实方案：** 所有 renderer resource 使用 `{workspaceId, tabId, resourceKey, generation, requestId}`；identity 变化先递增 generation 并 abort 可取消请求。response、error、finally 和流式 event 均须在 commit 前验证完整 identity，旧请求不得 toast、写 state 或清 loading。流式事件另校验单调 seq/attemptId。建立共享 `LatestRequestGate` 纯函数和 hook，但领域缓存 key/内容仍由领域模块拥有。

### D09-P1-05 快捷键由多个全局 listener 竞争，缺少命令作用域、冲突和保留键治理

**证据等级：已确认。** `shortcuts.ts` 只定义八个 action 和字符串匹配（`shortcuts.ts:1` 至 `:32`、`:64` 至 `:125`），不检查重复绑定、OS 保留组合或命令可用条件。App、LibraryView、DocumentView 分别注册 window listener（`App.tsx:1931` 至 `:1957`；`LibraryView.tsx:1997` 至 `:2048`；`DocumentView.tsx:4487` 至 `:4549`）。浮层阻断依赖 DOM selector（`shortcuts.ts:127` 至 `:136`），而不是实际的 overlay/focus 栈。

**影响：** 同一组合可能被多个页面处理，隐藏但仍留在 DOM 的 Ant 浮层可能永久阻断快捷键；IME、编辑器、阅读器和应用命令的优先级不可解释。用户也无法判断自定义键是否冲突或根本不会触发。

**落实方案：** 建立 typed `CommandRegistry`，command 声明 scope、label、default bindings、when predicate、repeat policy 和 destructive level。唯一 dispatcher 按 `modal > popover > editor > reader > active view > workspace > app` 路由；设置页实时检测重复、前缀、OS/浏览器保留键和不可达组合，允许恢复默认。快捷键保存继续兼容旧 setting keys，通过 adapter 映射到 commandId，不强制数据库迁移。

### D09-P1-06 标签栏不是完整的可访问 tablist，也没有键盘分组/排序等价路径

**证据等级：已确认。** 标签是普通 button，但关闭使用嵌套的 `span role="button"`，不可独立聚焦（`App.tsx:2349` 至 `:2388`）；标签轨道、标签和分组未提供 tablist/tab/aria-selected/roving focus。分组设置以 contextMenu Popover 打开（`:2549` 至 `:2582`），拖动只有 Pointer 路径（`:1742` 至 `:1880`）。

**影响：** 读屏无法得到“第几项、是否选中、所属分组”；键盘用户不能可靠关闭、移动、分组、重命名或打开上下文菜单。icon density 下标题与关闭图标隐藏后，可发现性进一步下降。

**落实方案：** 使用 `tablist -> tab + sibling close button` 或经过验证的 composite pattern；只让活动/roving tab 进入 Tab 序，方向键、Home/End、Ctrl+Tab、Delete、Shift+F10 和菜单拥有明确合同。分组采用可访问 group label 与展开状态；键盘“移动到前/后/分组”调用同一 reorder command。焦点在关闭后落到确定的相邻标签，在恢复后落到恢复项。

### D09-P1-07 框选 hook 是纯 MouseEvent 会话，触控不可用且卸载中断没有清理保证

**证据等级：已确认。** hook 导入 React `MouseEvent`（`dragMultiSelect.ts:1`），从 `onMouseDown` 建 session（`:381` 至 `:449`），只注册 window mousemove/mouseup（`:451` 至 `:538`）。清理函数仅由 mouseup finish 调用；没有 effect unmount cleanup、Escape cancel、pointercancel 或 lost capture 路径。Library/Folders/Tags 均把它接到 `onMouseDown`。

**影响：** touch/pen 无法框选；拖选时切标签、关闭 modal 或卸载页面可能残留全局 listener、`body.userSelect='none'`、cursor、overlay 或 preview class。用户也不能按 Esc 回滚本次选择。

**落实方案：** 改为 Pointer Events 并使用 `setPointerCapture`；session 必须拥有 idempotent `commit/cancel/dispose`，在 pointerup、pointercancel、lostpointercapture、Escape、blur 和 unmount 全部清理。coarse pointer 默认不以空白拖动框选，提供长按进入选择模式或显式“批量选择”；鼠标 marquee 继续保留。选择预览与真实 selection 分离，只有 commit 更新领域状态。

### D09-P1-08 文件夹/文献 HTML5 拖放没有键盘和可靠触控替代

**证据等级：已确认。** FoldersView 的树行和卡片通过 `draggable`、dragenter/over/drop 移动（`FoldersView.tsx:1449` 至 `:1569`），文献卡也只在 native dragstart 写 dataTransfer（`:1681` 至 `:1696`）；移动文件夹/文献后直接调用命令（`:582` 至 `:631`、`:1238` 至 `:1283`）。Library 的文件夹行虽可 Enter 激活，但移动仍依赖 draggable（`LibraryView.tsx:5646` 至 `:5734`）。

**影响：** 触屏、笔、读屏和纯键盘用户不能完成文件夹排序、移入/移出或把文献放入文件夹；拖错目标后也没有统一影响预览。原生 drag 在高 DPI、滚动容器和跨 input modality 下行为不一致。

**落实方案：** 所有拖放命令都提供菜单/批量栏中的“移动到…”对话框和键盘 reorder；拖动只是同一 command 的 pointer 快捷方式。pointer drag 使用稳定 target ID、before/inside/after 和可见 drop announcement；main 重新校验环、来源、目标和权限。触控命中区、自动滚动和长按阈值按 pointerType 区分，外部文件 drop 保留 native dataTransfer，但文件选择器必须可完成同一导入。

### D09-P1-09 标签拖动在 pointermove 中持续提交真实顺序，`pointercancel` 仍按完成处理

**证据等级：已确认。** tab/group 拖动在 animation frame 中调用 `setTabs(nextTabs)`（`App.tsx:1502` 至 `:1588`）；pointerup 与 pointercancel 共用 finish handler（`:1795` 至 `:1807`、`:1867` 至 `:1879`）。finish 还会改变分组成员（`:1592` 至 `:1694`）。没有 Escape rollback，且每次中间 setTabs 都触发工作区保存。

**影响：** 系统取消 pointer、窗口失焦或用户想放弃拖动时，中间顺序已经成为真实状态并可能持久化；大量同步保存和 DOM 动画还会造成拥挤标签下卡顿。

**落实方案：** `DragTransaction` 保存 original order/group，pointermove 只更新 preview model；pointerup 对有效目标只 commit 一次，pointercancel/Escape/blur/unmount 统一 rollback。commit 返回 before/after snapshot 供本地 tab undo；持久化只观察 committed revision。邻居动画从 preview/commit diff 派生，不再把动画帧当业务事务。

### D09-P1-10 “全选/范围/框选”只面向已加载数组，选择范围对用户和后端都不稳定

### D09-P1-11 部分工作台在总量增长时要么线性持有全部对象，要么用静默上限伪装完整

**落实方案：** tab/navigation undo 可由 workspace store 本地完成；业务写命令必须由 main 返回 `operationId, affectedCount, completionKind, undoUntil, recoveryAction`。关系移动可用幂等逆命令；实体删除默认 soft-delete/回收站或领域版本，永久删除只在回收站影响预览后二次确认。UI 的 UndoNotice 只消费后端 receipt，重启后是否可撤销由领域任务/数据合同决定，不能伪造成功。

### D09-P2-01 主窗口、AI 面板和按钮布局没有形成可恢复的显示器安全状态

## 5. 目标交互架构与兼容策略

### 5.1 唯一状态与事件链

```text
Input adapters
  keyboard | pointer | touch | menu | screen reader action | external file drop
      -> CommandRegistry + scope stack
         -> Navigation / Selection / Drag / Overlay / Domain command
            -> transactionId + workspaceId + tabId + generation
               -> main/preload typed command or local workspace reducer
                  -> result/event with revision + seq + operation receipt
                     -> identity guard
                        -> committed state
                           -> focus + live summary + debounced durable snapshot
```

原则如下：

- input 只决定如何发出 command，不决定业务语义；鼠标拖放与“移动到”菜单调用同一命令。
- preview 与 commit 分离；drag、selection、batch、AI operation 和删除都先形成可取消 preview。
- renderer state 不是数据库真相；业务 undo、任务状态、关系校验和保存版本由 main/领域服务确认。
- 每个异步 commit 必须带完整 identity；`finally` 也不能越过 generation。
- focus、announcement、snapshot 保存只在事务 commit 后执行，cancel 保持原状态。

### 5.2 建议的核心合同

```ts
interface WorkspaceTabDescriptorV2 {
  id: string
  kind: 'home' | 'view' | 'document'
  resourceIdentity: string
  title: string
  titleOrigin: 'default' | 'resource' | 'user'
  groupId?: string
  createdAt: string
  orderKey: string
  viewStateRef?: string
  generation: number
}

interface InteractionIdentity {
  workspaceId: string
  tabId: string
  resourceKey: string
  generation: number
  requestId: string
}

type SelectionDescriptor =
  | { mode: 'explicit'; ids: string[]; scopeSnapshotId: string }
  | { mode: 'all-matching'; scopeSnapshotId: string; excludedIds: string[] }

interface OperationReceipt {
  operationId: string
  commitState: 'committed' | 'rejected'
  completionKind?: 'full' | 'partial'
  affectedCount: number
  undoUntil?: string
  error?: ErrorEnvelope
}
```

这些是交互层合同，不重新定义文献、folder/tag、StableReaderLocator、TaskStateEnvelope、AI request/job 或数据库 revision。`OperationReceipt` 是一次命令的提交回执，不是第二套 `TaskStatus`；partial 仍使用全局 `completionKind`，拒绝原因复用 `ErrorEnvelope`。`viewStateRef` 只能引用非权威的轻量 snapshot；未保存正文、校对草稿和研究内容必须进入各领域的 durable draft/version 合同。

### 5.3 工作区恢复与资源边界

- v1 key 继续只读兼容；v2 使用新 key/存储并保留 last-known-good。未知版本不删除。
- 启动先恢复 shell、active descriptor 和窗口，再按优先级恢复活动页；其余 tab 懒恢复，不在首屏同时请求。
- 活动 tab 1 个，warm tab/页面/图片/请求/cache 数均有配置或硬预算；被逐出的 tab 保存 snapshot 并 abort generation。
- overflow/搜索可到达全部 tab descriptor；可见标签轨道窗口化，不把所有标签压成不可辨图标。
- 资源不存在时显示 unavailable placeholder、原 stable ID 和恢复/关闭动作；不得按同名对象自动重定向。
- workspace snapshot 不进入普通数据库备份的业务完整性承诺；若备份包含设置，应明确窗口布局可选、secret/正文排除。

### 5.4 命令、焦点和辅助技术

- CommandRegistry 是唯一快捷键分发处，旧快捷键设置通过 adapter 读取。
- OverlayManager 提供 topmost Esc、focus trap/inert、关闭后返回焦点、layer owner 和 click-through 防护。
- tablist、tree、listbox、grid/table selection 遵守对应 composite pattern；方向键不与阅读器翻页冲突。
- 图标命令同时有 tooltip 和 accessible name；动态选中使用 aria-selected/checked/pressed，不靠颜色。
- live region 只播阶段和摘要，连续 pointermove、token delta、每条批处理不逐项播报。
- touch/coarse pointer 的目标至少 44px；compact 视觉可小，但命中区和间距不能缩到不可用。

### 5.5 古籍与现代论文兼容

两类用户共享 WorkspaceTab、SelectionDescriptor、StableReaderLocator、Command 和 Undo 合同。古籍 preset 可默认显示原图/校对、竖排方向、OCR 框和异体字工具；现代论文 preset 可默认文本/PDF 对照、目录、引用、DOI/作者和表格工具。preset 只调整默认命令显隐、密度、阅读方向和新标签模板，不改变数据身份、快捷键冲突规则、删除保护、证据真实性或可访问性。

## 6. 分阶段落实方案

### 阶段 A：先封住关闭丢失与反序响应

1. 把 App 的 `Esc -> window.close()` 移出普通 back command，建立最小 CloseCoordinator 和 settings/reader dirty adapter。
2. 为 Folders、Tags、Excerpts AI、tab title 和模块 07 指定流程加入 identity generation；Library 模式抽为共享测试样板。
3. 先写反序响应、dirty close、save failure 和 pointercancel 的失败测试；不迁移数据库、不改视觉主题。

### 阶段 B：抽出 workspace store 与兼容快照

1. 从 App 抽出 tab/group reducer、navigation service 和 committed revision。
2. 设计 v2 双读/双写、last-known-good、未知版本保留和容量错误 UI；v1 回归继续通过。
3. 增加 tab view snapshot lifecycle、活动 + LRU warm window、窗口/显示器恢复和恢复默认布局。
4. 删除 60/40 静默截断；在容量压力时提示归档/清理，永不自动丢 descriptor。

### 阶段 C：统一命令、overlay、焦点和 tablist

1. 建 CommandRegistry/dispatcher，把 App、Library、Document 快捷键逐个迁入。
2. 建 OverlayManager 和 focus transaction，修复 Esc 顺序、隐藏 overlay、关闭返回焦点和 live region。
3. 标签/分组改为可访问 composite，补 Ctrl+Tab、方向键、Delete、Shift+F10、键盘移动/分组。
4. 保留现有视觉 primitive，和模块 08 串行修改 App/样式，不并发重写同一热点。

### 阶段 D：选择、Pointer 拖放和 undo

1. 将 dragMultiSelect 改为 Pointer session，补 pointer capture、cancel/dispose 和 coarse pointer 策略。
2. tab drag 改 preview-only transaction；文件夹/文献 drag 与菜单 move 共用 command。
3. 引入 SelectionDescriptor、范围 snapshot、全匹配排除模型和批量影响预览。
4. tab undo 本地落地；业务 undo 只在领域 command 返回 operation receipt 后启用，不做 renderer 假撤销。

### 阶段 E：有界窗口与双用户工作流

1. 标签轨道/菜单、Tags picker、Excerpts 和 Library 改 cursor/虚拟窗口，冻结 DOM、IPC 和 cache 预算。
2. 古籍与现代论文 fixture 走相同键盘、拖放、恢复、批量和阅读链路；preset 只改默认布局。
3. 统一失败、partial、stale、unavailable、undo-expired 和恢复动作，不以 toast 替代持久状态。

### 阶段 F：成品门禁与本地用户测试

1. 静态字符串脚本降为最小合同，增加 reducer unit、renderer behavior、Electron restart、NVDA 和固定机器性能层。
2. 运行窗口/DPI/触控/IME/大库/断电矩阵，验证 INT-01 至 INT-40。
3. 提供本地构建、结果、已知限制、工作区 v1 回退和数据库零迁移说明。
4. 用户在真实古籍与普通论文副本上明确确认后，才能另行批准任何公开动作。

## 8. 新功能建议

### 8.1 D09-NF-01 命名工作区与安全恢复点

**用户问题：** 用户可能同时进行古籍校勘、地方志专题和现代论文综述，当前只有一个自动覆盖的最近工作区，无法命名、比较或回到稳定恢复点。

**MVP：** 创建/重命名/复制/切换本地工作区；每个工作区保存 tab descriptor、分组、活动对象、轻量 view snapshot 和布局。自动保留一个 last-known-good 和有限历史恢复点，显示保存时间、版本和 unavailable 对象。

**实现影响：** 使用 v2 workspace store 和稳定 ID，不复制正文/AI 输出，不新增 SQLite 业务表；逻辑工作区数量不设硬 cap，列表 cursor 化，历史 bytes 有明确预算。古籍/论文 preset 只是新工作区默认模板。

**验收：** 强退、future schema、删除对象、显示器变化和 1000 tab descriptor 下可恢复；切工作区会 abort 旧 generation，旧流不能串入。

**回退：** 禁用功能后打开最近兼容工作区；v1 key 保留一个版本周期，删除工作区只删布局描述，不删文献、项目或任务。

### 8.2 D09-NF-02 命令面板与快捷键冲突中心

**用户问题：** 高频命令分散在侧栏、右键和双击，用户不知道当前可用快捷键，也无法判断自定义组合冲突。

**MVP：** 一个本地命令面板，按当前 scope 搜索命令/最近文献/固定文件夹/专题；设置页显示默认/自定义绑定、冲突、不可用原因和恢复默认。命令面板不做全文搜索替代品。

**实现影响：** 复用 CommandRegistry、旧 settings keys 和模块 08 Action primitive；对象建议只读有界最近索引，不读取全库数组。第一版无需新依赖和数据库迁移。

**验收：** 键盘、NVDA、中文 IME、Ctrl/Meta 和 modal/reader scope 均正确；执行结果与原按钮相同，不绕过确认/权限。

**回退：** 关闭面板后原按钮/菜单继续工作；清除新 command setting 回到旧默认映射，不删除业务数据。

### 8.3 D09-NF-03 可恢复操作中心

**用户问题：** toast 很快消失，用户无法查看刚才移动/删除/批处理的真实范围、部分失败或剩余撤销时间。

**MVP：** 侧栏展示最近 operation receipt：命令、范围、完成/部分/失败、undoUntil、失败项和恢复动作；支持撤销仍有效的操作及打开对应任务详情。

**实现影响：** UI 只消费模块 04/07/任务系统的权威 receipt。tab/navigation receipt 可存 workspace journal；业务 receipt 持久化由唯一 task/operation 合同拥有。若现有表不能表达 durable undo，任何旁路表必须单独审批，不在模块 09 私建第二份真相。

**验收：** 部分失败、重启、undo 过期、并发双击和重复撤销都幂等；显示数量与数据库一致。

**回退：** 移除中心不删除 receipt、回收站或任务；原领域页面仍可查看结果。未实现后端 undo 的命令只显示结果，绝不显示假“撤销”。

### 8.4 D09-NF-04 选择范围与批量影响预览

**用户问题：** 大库用户难以区分“选了当前 50 条”与“选了筛选出的 8 万条”，批量移动/加标签/AI 外传风险差异巨大。

**MVP：** selection bar 显示范围、exact/estimated count、筛选 snapshot 和 exclusions；批量命令先显示目标、冲突、跳过、外传/删除影响，再确认执行。

**实现影响：** 复用 SelectionDescriptor 和模块 04 query snapshot；renderer 不枚举全集。第一阶段兼容显式 ID 小批 API，不要求数据库迁移；若 durable scope snapshot 需要旁路表，按模块 04/11审批。

**验收：** 1001/10 万项、筛选变化、跨页排除、并发关系变化和 stale preview 均给出准确结果或拒绝，不静默扩大范围。

**回退：** 关闭 all-matching 后退回明确的当前页/已加载选择；已有关系和选择不会被自动提交或删除。

### 8.5 D09-NF-05 键盘移动助手

**用户问题：** 拖放适合鼠标，但深层文件夹、大量文献、触屏和读屏场景更适合搜索目标并确认移动。

**MVP：** “移动到…”面板支持搜索/树导航、最近目标、before/inside/after、影响数量和冲突；文件夹、文献、标签页均调用同一领域 reorder/move command。

**实现影响：** 复用现有 folder tree、CommandRegistry 和 main 校验，不引入 DnD 库；目标列表 cursor 化。模块 08 提供视觉，模块 04 保持关系真相。

**验收：** 不用鼠标完成深层移动、排序和撤销；循环、删除中目标、权限变化和 stale snapshot 被 main 拒绝；结果与 pointer drag 相同。

**回退：** 面板关闭后现有 drag/menu 仍在；取消零副作用，不保存半完成目标。

### 8.6 D09-NF-06 研究导航历史与“回到来源”

**用户问题：** 从检索、摘录、AI 证据和目录连续跳转时，单个“最后阅读位置”无法还原研究路径，也容易污染原进度。

**MVP：** 每个 workspace 保存有界的 navigation entries：origin、StableReaderLocator、tabId、时间和是否临时；提供后退/前进、回到来源和固定节点。临时跳转与用户接管遵守模块 05 导航事务。

**实现影响：** 第一版只存 locator metadata，不复制正文；使用有界 workspace journal，无数据库迁移。若需要长期跨设备历史，必须另行审批表/同步，不在 MVP 内。

**验收：** 搜索->文献->摘录->另一文献往返位置稳定；字体/窗口变化按 locator 重定位；source stale/unavailable 时明确降级，不猜同名文献。

**回退：** 可关闭记录并一键清除历史；不影响现有 reader state 和文献，关闭后后退只在当前会话工作。

### 8.7 D09-NF-07 可停靠双工作面

**用户问题：** 古籍用户常需原图/校对并排，论文用户常需 PDF/正文或两篇论文对读；当前只能在标签间来回切换或让浮动 AI 遮住内容。

**MVP：** 一个 workspace 最多两个活动 pane，tab 可显式移到左/右；每 pane 有独立 activeTab/focus，AI 可停靠。超过两个的标签仍休眠在同一 descriptor 列表，不同时挂载无限页面。

**实现影响：** 复用 workspace store、StableReaderLocator 和 floating layout；活动 pane 上限固定为 2，cache 预算共享。第一版只保存布局 preference，不新增业务表或同步服务。

**验收：** 古籍原图/校对、论文 PDF/正文和两文献分别验证同步/独立滚动、键盘切 pane、DPI、恢复和内存；关闭 pane 不关闭 tab 或丢位置。

**回退：** 切回单 pane 时保留最近活动 tab，其余回到标签列表；清除布局恢复现有单工作面，不改文献数据。

## 9. 依赖、迁移与审批

### 9.1 第一阶段结论

- 阶段 A 至 D 可使用现有 React、Zustand、Ant Design、Electron、TypeScript、Pointer Events、ResizeObserver、Web Animations API/禁用策略和浏览器 IndexedDB/localStorage 完成，不新增运行时依赖。
- 第一阶段优先零 SQLite 迁移。workspace v2、window placement、panel layout、command bindings、tab/history metadata 都是非敏感应用状态，不进入业务表。
- 工作区只保存 stable ID/locator metadata/布局，不保存正文、OCR payload、AI answer、credential、完整 searchSession 或领域唯一状态。
- `appWorkspace.v1`、旧快捷键 keys、旧 reader state 继续读取；v2 写入/读回/崩溃验证完成前不得清理旧值。

### 9.2 必须再次获得用户确认的候选

| 候选 | 当前审批状态 | 采用前必须提交 |
| --- | --- | --- |
| `@dnd-kit`、React Aria 等交互库 | 未批准，第一阶段不需要 | 许可证、包体、键盘/读屏/触控实测、与 Ant/Pointer 冲突、移除回退 |
| `axe-core/@axe-core/playwright` | 未批准，可选测试依赖 | 许可证、安装体积、误报策略、离线性和无依赖替代 |
| 新 workspace/operation/undo SQLite 表 | 未批准，默认零迁移 | 现有结构不足证据、schema、自动备份、幂等迁移、apply twice、失败回滚、旧版忽略和恢复演练 |
| 云同步、账号、遥测、崩溃上传 | 未批准且不在本章 MVP | 数据清单、用户同意、加密、隐私、离线降级、删除和自托管/退出方案 |
| 全局快捷键/native hook | 未批准且非必需 | OS 权限、安全、冲突、签名/打包、禁用与卸载行为 |

任何候选依赖都不能以“实现拖放/可访问性更快”为由跳过用户确认。纯浏览器能力足以先建立正确状态机；是否引库只能在行为基线后以维护收益决定。

### 9.3 数据与回退边界

- 模块 09 不拥有 folder/tag/document/research 数据迁移；需要 soft delete、operation log 或 selection snapshot 持久化时，由模块 04/07/统一任务模块提出唯一 schema。
- 任何 additive migration 都必须按模块 11：预检、自动备份、短事务/小批 cursor、apply twice、故障注入、校验、失败回滚、旧版本安全忽略。
- 降级到旧版本前保留 v1 workspace；旧版不认识 v2 时只能忽略，不能删除。窗口布局/快捷键新字段缺失时使用当前兼容默认。
- 交互重构失败不得要求清空数据库、重导文献、重做 OCR 或丢弃研究记录。

## 10. 与其他模块的约束

- **模块 01 产品与架构：** 复用唯一 TaskStateEnvelope、typed settings 和三进程边界。App 壳层按 workspace store、navigation、tab drag、close、floating controller 渐进拆分；UI 不绕过 preload。总量无限、窗口/并发/缓存有界。
- **模块 04 文库组织：** folder/tag/document scope、稳定 ID、分页、selection snapshot 和关系完整性由文库服务拥有。模块 09负责范围表达、键盘、drag preview、确认和 undo 展示；main 必须重新校验环、冲突、数量和 revision。
- **模块 05 阅读器：** 使用唯一 StableReaderLocator 和导航事务；workspace snapshot 不保存虚拟页作为长期身份。关闭/切 tab 必须等待或保留 reader/proof pending save，latest-navigation、搜索临时跳转和有界页面窗口属于共同发布门禁。
- **模块 07 AI 与研究：** scope/session/project/dataset/output 和 stream event 必须携带 workspace/tab generation；旧流不能更新新页面。对话、摘录、大纲、排除和报告删除使用领域 operation receipt/回收站，模块 09不复制 AI job 或 evidence 状态。
- **模块 08 UI 视觉：** 模块 08拥有 token、focus 外观、touch target、layer 和 motion 视觉；模块 09拥有 command、roving focus、Pointer drag、overlay 生命周期、undo 和恢复。对 `App.tsx/app.css/DocumentView` 的改动必须按阶段串行，不能并发建立两套 primitive。
- **模块 11 数据库与备份：** workspace/窗口默认零数据库迁移；任何 durable undo/operation 表只能旁路新增并通过备份、回滚和旧版兼容。UI 不得把“已写 localStorage”描述成业务已保存，也不得把备份当即时 undo。

共同硬约束是：业务正确性、资源有界、旧库兼容和本地用户验收优先于动画与便利功能。新版验收必须先于实现更新；完成后先交用户在本地副本测试，用户明确确认并批准公开前不得执行任何远端 Git/GitHub/Release 动作。
