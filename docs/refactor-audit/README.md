# GujiSmart 全面重构审阅

本目录记录 GujiSmart 的全量代码审阅、分模块优化设计、新功能路线图与实施计划。审阅以当前活跃仓库为唯一事实来源，遵循 `AGENTS.md`、现有架构与发布规范；业务实现按 `plans/` 中的切片逐项测试、复核和本地验收。

## 审阅原则

- 按用户功能闭环审阅，同时完整追踪 shared、preload、main IPC、SQLite、renderer 与回归脚本。
- 逐一登记已跟踪的源码、脚本、配置和文字文档；二进制资源只检查用途、体积、许可证与打包合规。
- 每完成一个模块就更新文档、执行文档门禁并独立提交。
- 当前测试用于记录现状和回归边界；正式实施前先按目标成品更新验收方案，再按新版方案验收。
- 优先保持现有数据库与用户文件兼容。只有收益显著且具备备份、回滚、兼容读取时才建议迁移。
- 新增依赖、本地模型或外部服务只能作为候选，实施前必须获得用户确认。
- 文库与任务数量不设产品上限，但并发、缓存和内存必须有界；超大规模允许耗时增长，不允许丢任务、崩溃或阻塞阅读。
