# 08 UI 视觉系统

## 1. 本章结论

GujiSmart 已经形成鲜明的“墨色工作台 + 古铜金品牌 + 纸张阅读面”视觉语言，密集文库、搜索、引文和阅读器也确实面向长期研究，而不是营销式展示。需要重构的重点不是推翻这套身份，而是把它从大量局部 CSS 和 Ant Design 覆盖，收敛为可验证、可扩展的语义设计系统。

高优先级问题已经覆盖首屏、文库、设置、AI、研究和摘录工作流：欢迎页、文件夹和浮动 AI 入口仍有不可聚焦的点击 `div`；AI 面板只能用鼠标拖动和缩放；工作区标签与研究大纲存在嵌套交互元素；CSS variables 与 Ant token 双源维护；状态色、弱文本、AI 金色渐变和部分选中态没有稳定达到 AA；全局 `.ant-progress-bg` 会覆盖成功、失败等进度语义；欢迎页、引用页和摘录库在小窗口或 200% 缩放下可能裁切或横向溢出；减弱动画只覆盖标签页。现有视觉仍以单一暗色金棕体系为主，古籍与普通 PDF/论文虽然共用功能底座，却没有通过主题、密度、字体和阅读 preset 提供同等成熟的视觉适配。

本章的目标是建立一个由单一主题合同驱动的工作台视觉系统：保留古铜金品牌和纸张阅读面，把操作 UI 调整为更清晰的中性工作区；统一 token、组件状态、焦点、层级、密度、响应式和视觉回归。古籍与普通论文使用同一组件合同；内容 preset、明暗方案、对比度、密度和阅读字体是正交设置，不复制两套页面，也不把高对比限定给某一类文献。

## 3. 当前视觉基础

### 3.1 主题与字体

`global.css:4` 至 `global.css:46` 定义古铜金、墨色、纸色、四类状态色、三档文字、间距、动画和阴影；`main.tsx:50` 至 `main.tsx:81` 又独立定义 Ant 主色、状态色、圆角、字体以及 Layout/Menu/Button/Progress token。两套值目前接近，但没有生成关系，任何一侧改动都可能让原生 CSS 与 Ant 组件出现不同的背景、状态或交互色。

全局字体为 `Inter -> Noto Serif SC -> system sans`（`global.css:63` 至 `global.css:65`、`main.tsx:59`）。Inter 不含中文，因此多数中文操作文本实际落到 `Noto Serif SC`。衬线字体适合品牌、古籍正文和纸张阅读面，不适合 10 至 13px 的筛选器、状态、表单说明和密集工具栏。新的字体合同应区分 `font-ui`、`font-reading-serif`、`font-reading-sans` 和 `font-mono`。

### 3.2 欢迎页

欢迎页以产品名、说明和六张等权快捷卡为中心。优点是第一屏能直接识别产品和主要功能，视觉安静、结构简单；问题是它更像静态功能目录，而不是用户每天打开的软件工作区。导入、继续阅读和恢复任务应高于设置、引用模板等低频入口，最近文献、未完成任务和固定专题也应在首屏可恢复。

当前“导入文献”只写 PDF、图片和扫描件（`WelcomeView.tsx:19` 至 `WelcomeView.tsx:23`），而实际直接解析能力还包括 JSON、TXT、Markdown 和 EPUB。文件选择器虽然列出 MOBI、AZW/AZW3，但导入路径固定要求用户先转换（`src/main/ipc/documents.ts:655` 至 `src/main/ipc/documents.ts:664`、`:3732` 至 `:3742`、`:3975` 至 `:3977`）。因此欢迎页、选择器和真实解析能力三者都需按模块 02 的格式合同统一，不能把“可选择但必失败”写成已支持。

### 3.3 错误边界

renderer error boundary 使用原生按钮、`role='alert'`、可展开错误详情和“数据没有被删除”的明确说明（`main.tsx:27` 至 `main.tsx:40`），这是应保留的基础。后续只需要接入统一 token、焦点落点、可安全复制的脱敏诊断和高对比模式，不应把它改成只显示技术堆栈的空白错误页。

### 3.4 App 壳层与工作区标签

标签系统已经实现分组、颜色、折叠、compact/tight/icon 密度、全标签菜单、拖拽预览和关闭入口，并大量使用 `min-width:0`、ellipsis 和固定 control size 防止动态标题破坏布局。这些功能值得保留。

问题在于 1 至 820 行用同一 CSS 区段承载 Ant header、popover、标签分组、拖拽、菜单、密度和动画，依赖大量内部 selector、硬编码颜色和 z-index。关闭入口还以 `span role='button'` 嵌套在外层 tab `button` 中（`App.tsx:2349` 至 `App.tsx:2388`），视觉上可见，语义上却不是可独立聚焦的控制。

### 3.5 文件夹、标签、引用与文库

文件夹文献卡已使用原生 button，网格使用 `auto-fill` 和可调尺寸，真实封面优先且标题有稳定截断；文库翻译进度、健康指标和风险清单也提供清晰的状态结构。这些信息架构应继续保留。

文件夹树行、文件夹卡片和批量标签仍使用点击 `div/article`（`FoldersView.tsx:1449` 至 `FoldersView.tsx:1452`、`:1511` 至 `:1538`、`:1877` 至 `:1892`，`TagsView.tsx:439` 至 `TagsView.tsx:454`）。引用页固定 280px 侧栏和最小 360px 卡片（`app.css:1460` 至 `app.css:1506`），翻译任务固定三列（`app.css:1709` 至 `app.css:1715`），健康指标固定五列（`app.css:1833` 至 `app.css:1837`）。这些区域缺少同层的窄窗重排。

### 3.6 设置页

设置页已经有较好的桌面降级：1120px 最大内容宽度、220px 分类导航、`minmax(0, 1fr)` 表单列和长路径 `overflow-wrap:anywhere`；860px 以下切为单栏，分类导航改为横向滚动，双列表 provider 编辑器和双列表单也切为单列（`app.css:2090` 至 `app.css:2423`）。这些规则应保留。

问题是设置导航、provider 新建/选择和大量 11 至 12px 辅助文本仍依赖局部 hover、裸颜色与 `--gs-text-tertiary`；相似的面板、边框和说明样式在 OCR、AI、数据与关于页面重复。视觉系统应提供统一的 settings section、provider list、field hint、danger zone 和 capability state。普通设置键保持兼容；凭据 UI 必须接入模块 07 的唯一 CredentialVault，不能以“保持现状”为由保留明文回填边界。

### 3.7 AI、研究与摘录

AI Markdown 已正确处理长文本、链接、代码和宽表格；scope popover、研究记录列表使用有界高度与局部滚动；研究工作台在 1280px 和 720px 有初步降级。这些是应保留的工程基础。

主要缺口在输入方式和信息完整性。导入/AI 浮钮、拖拽标题和八个 resize handle 只使用鼠标事件；AI 按钮和用户消息的白字在金棕渐变上对比不足；研究记录被三行裁切且字段只显示前六个，没有完整详情入口；摘录工具栏含 320px 搜索组、260px 输入框和固定视图切换，却没有自己的窄窗规则。全局 Progress 金色覆盖还会把数据库升级、模型下载和维护任务的成功/失败状态都涂成同一种品牌进度。

## 4. 必须保留的能力

- 古铜金品牌识别和墨色工作台可以保留，但品牌色不应承担所有选中、状态和操作层级。
- 阅读器中的纸张背景、原图/版式还原对照和古籍衬线正文继续作为领域视觉资产。
- 文库、搜索、引文和研究工作台保持高信息密度，不改成大卡片营销页面。
- Settings 当前按功能分组、错误页有恢复说明、长 Select 值有省略保护，这些工程基础继续复用。
- 现有 Ant Design 和图标库足以完成第一阶段；不需要为了重构视觉系统立即增加 UI 依赖。
- 古籍和普通 PDF/论文继续共享一套 token 与组件，通过 preset、字体和密度配置兼容。

## 5. 关键问题

### D08-P1-01 欢迎页六个主入口没有键盘和辅助技术语义

**证据等级：已确认。**

六个入口均为带 `onClick` 的 `div`（`src/renderer/src/views/WelcomeView.tsx:16`、`:26`、`:36`、`:46`、`:56`、`:66`），没有 `button`、`tabIndex`、键盘处理或可访问名称合同。CSS 只有 hover 位移和图标缩放（`src/renderer/src/styles/app.css:1599` 至 `src/renderer/src/styles/app.css:1629`），没有 `:focus-visible`。

**影响：** 纯键盘和读屏用户无法进入导入、文库、文件夹、检索、引用或设置；这是首屏全部主操作的阻断，不是局部美观问题。

**落实方案：** 使用原生 `<button type='button'>` 或共享 `WelcomeActionButton`，标题作为 accessible name，描述作为辅助说明；Enter/Space 由原生语义处理。视觉上同时定义 hover、focus-visible、active、disabled 和 loading，焦点环不得只改颜色。验收要求在不使用鼠标时可依序访问并激活全部入口，焦点顺序与视觉顺序一致。

### D08-P1-02 CSS variables 与 Ant token 双源维护，组件颜色已经开始漂移

**证据等级：已确认。**

全局 CSS 在 `global.css:4` 至 `global.css:46` 定义品牌、状态、文字、间距和阴影；Ant 主题在 `main.tsx:50` 至 `main.tsx:81` 再写一遍主色、状态色、圆角和 Layout/Menu/Button/Progress。状态 badge 又混合 Ant 常用绿色 surface 与另一套 `--gs-success` foreground（`global.css:270` 至 `global.css:288`）。

**影响：** 同一“成功/选中/主要操作”会在 Ant 组件、普通 DOM 和截图中出现不同色值；深浅主题、对比度修正和品牌升级必须同时修改多个位置，容易遗漏。

**落实方案：** 新建唯一 `theme contract`，以 semantic token 生成 CSS variables 与 Ant token：`surface-*`、`text-*`、`border-*`、`action-*`、`status-surface-*`、`on-status-*`、`focus-ring`、`radius-*`、`control-height-*`、`motion-*` 和 `layer-*`。第一阶段使用现有 TypeScript/CSS，不新增依赖；raw color 只允许出现在 token 文件、文献原图投影和明确的用户自定义色入口。

### D08-P1-03 状态色、弱文本和部分选中态没有稳定满足 WCAG AA

**证据等级：静态颜色计算与截图均已确认。**

12px 状态 badge 直接把基础状态色作为前景（`global.css:260` 至 `global.css:288`）。在当前暗色 surface 上，processing、completed 和 error 约为 3.07:1、3.67:1 和 2.48:1，未达到普通文本 4.5:1。`--gs-text-tertiary` 在较浅暗色 surface 上也低于稳定余量；欢迎页描述以 13px 使用该颜色（`app.css:1637` 至 `app.css:1640`），截图中已经明显发灰。

**影响：** 状态、说明和禁用信息恰好是用户判断任务是否完成、失败或需要处理的关键内容；弱对比会同时影响低视力用户、低质量屏幕和高亮环境。

**落实方案：** 状态 surface 与 on-status 前景分离，按实际组合自动计算对比；普通正文和图标达到 4.5:1，大字达到 3:1，非文本焦点/边界达到 3:1。`text-tertiary` 只用于非关键辅助信息，状态、错误、数量和操作原因不得使用 tertiary。增加可叠加任一内容 preset 的高对比模式和 Windows forced-colors 验收。

### D08-P1-04 操作 UI 与阅读正文共用衬线字体，密集界面可读性不足

**证据等级：已确认。**

`Inter` 不含中文，当前全局 stack 会让中文工具栏、表单、状态、筛选器和 10 至 13px 小字落到 `Noto Serif SC`（`global.css:63` 至 `global.css:65`）。品牌标题和阅读正文也使用同一字体角色。

**影响：** 密集搜索、引用模板、研究统计和设置说明的字形更拥挤；普通论文用户的英文/中文混排与古籍阅读需求被压进一个字体选择。

**落实方案：** 操作 UI 默认使用系统中文无衬线栈（Windows 优先 `Microsoft YaHei UI`/`Microsoft YaHei`，macOS 优先 `PingFang SC`），品牌和古籍正文使用 serif，现代论文阅读面允许 serif/sans 单独设置。字体大小、行高和字重进入 role token，不按 viewport 宽度缩放，也不使用负字距。

### D08-P1-05 欢迎页在小窗口和 200% 缩放下可能裁掉入口

**证据等级：CSS 约束已确认，需窗口矩阵复现。**

根节点固定 `overflow:hidden`（`global.css:57` 至 `global.css:61`）；欢迎页固定 `height:100%`、48px padding、`overflow:hidden`（`app.css:1560` 至 `app.css:1570`），六张卡始终三列（`app.css:1591` 至 `app.css:1597`），没有欢迎页专用断点。

**影响：** 低分辨率笔记本、窗口化、125% 至 200% DPI/浏览器缩放和更长本地化文案可能让第二行卡片或标题不可见，且页面无法滚动恢复。

**落实方案：** 欢迎页使用 `min-height:100%`、可滚动容器和稳定 grid：宽屏三列，中等两列，窄窗一列；高度不足时从垂直居中切换为顶部对齐。测试 1024x640、1280x720、1920x1080、200% zoom、最长中英文标题和系统大字体，所有操作必须可达且不重叠。

### D08-P1-06 文件夹树、文件夹卡和批量标签仍有鼠标专用复合控件

**证据等级：已确认。**

文件夹树行是可点击、可双击、可拖拽的 `div`，没有 treeitem、Tab 焦点或键盘展开/激活（`FoldersView.tsx:1449` 至 `FoldersView.tsx:1456`、`:1877` 至 `:1892`）；文件夹卡是带点击和双击的 `article`（`FoldersView.tsx:1511` 至 `FoldersView.tsx:1538`）；批量标签入口是带 `onClick` 的 `div`（`TagsView.tsx:439` 至 `TagsView.tsx:454`）。对应 CSS 主要定义 hover/selected（`app.css:885` 至 `app.css:901`、`:991` 至 `:1007`、`:1386` 至 `:1413`）。文献卡已经使用原生 button，是可复用的正向模式。

**影响：** 用户无法只用键盘遍历目录、进入文件夹或批量选择标签；视觉选中态与辅助技术选中态没有共同合同。

**落实方案：** 文件夹树使用标准 tree/roving tabindex，Left/Right 展开收起，Up/Down 导航，Enter 打开，Space 选择；文件夹卡使用 button 或内部明确的主操作 button，拖拽是增强而不是唯一入口；标签批选使用 checkbox/listbox 语义。视觉 primitive 必须统一 focus、selected、drag-target、drop-before/inside/after 和 disabled，不只在 hover 时出现。

### D08-P1-07 工作区标签把关闭控件嵌进外层按钮，无法独立聚焦

**证据等级：已确认。**

每个 tab 是原生 `button`，内部再放 `span role='button'` 作为关闭入口（`App.tsx:2349` 至 `App.tsx:2388`）。关闭 span 没有 `tabIndex` 或键盘处理；CSS 默认把它设为 opacity 0，只有 hover、active 或 focus-within 才显示（`app.css:762` 至 `app.css:786`）。

**影响：** 形成嵌套交互语义，读屏树和键盘焦点不可靠；icon density 下用户可能看见关闭图标，却无法单独激活。

### D08-P2-10 全局 Progress 覆盖会抹掉成功、失败和调用方颜色语义

**证据等级：已确认。**

无作用域 `.ant-progress-bg` 使用 `!important` 强制所有 Ant Progress 为金色渐变（`app.css:3827` 至 `app.css:3830`）。数据库升级、模型下载、数据库维护和批处理都复用 Progress（`App.tsx:2685`、`SettingsView.tsx:1676`、`:2241`、`DashboardView.tsx:128`），因此组件 `status` 或调用方 `strokeColor` 可能被全局覆盖。

**影响：** 旁边的文字、Alert 或 Tag 仍可能保留状态信息，但进度条本身无法区分 running、completed、error、paused 和 partial completion，削弱模块 01 的任务状态合同。

**落实方案：** 删除无作用域覆盖；默认 Progress 由 Ant component token 和共享状态映射生成，只有明确的 `.progress-brand` 变体使用品牌渐变。进度条旁必须有状态文字、数值与恢复动作，颜色不是唯一信号；error/canceled/paused/partial 分别按 `TaskStateEnvelope` 渲染。

### D08-P3-01 `app.css` 含无生产引用的规则和动画，缺少可达性清理门禁

**证据等级：静态全仓搜索已确认。**

`pulse-glow`、`fade-in-up` 两个 keyframes，以及 `doc-list-*`、`research-grid`、`focus-mode-active` 等 selector 在 TSX/JSX 中未找到生产引用（`app.css:2001` 至 `app.css:2052`、`:2540`、`:2989`、`:3228`、`:3832` 至 `:3842`）。当前没有 owner、用途或删除验证记录。

**影响：** 死规则增加误判、specificity 和迁移成本；后续开发者可能把废弃样式当作可复用合同，或不敢删除而继续堆叠。

**落实方案：** 建立 selector reachability 报告和明确 allowlist；动态 class、第三方 slot 与运行时状态必须登记 owner。删除前用页面清单和视觉基线确认，删除后运行全 UI 回归；无法证明用途的规则先移入待清理清单，不在重构时继续复制。

## 6. 目标架构与兼容策略

目标链路固定为：

```text
ThemeDefinition
  -> semantic tokens
  -> CSS variables + Ant ConfigProvider
  -> shared visual primitives
  -> domain page composition
  -> orthogonal content / color-scheme / contrast / density settings
  -> static + behavior + visual acceptance
```

### 6.1 单一主题合同

建议在 `src/renderer/src/theme/` 建立纯 TypeScript `ThemeDefinition`，由同一对象生成 CSS variables 和 Ant token，不再在 `global.css` 与 `main.tsx` 手写两份值。合同至少包含：

- canvas/surface/elevated/overlay 与对应 border；
- text primary/secondary/tertiary/disabled、link、focus ring；
- action primary/secondary/danger 与 `on-action` 前景；
- status surface/on-status/icon，映射闭合 TaskStatus；
- typography role、control height、touch target、spacing、radius、shadow；
- motion duration/easing/reduced 值；
- layer token 与 overlay owner；
- density、workspace preset 和 forced-colors fallback。

raw color 只允许出现在主题定义、用户自定义色、原始文献/OCR 投影和明确第三方兼容层。第一阶段使用现有 TypeScript、CSS variables 和 Ant `ConfigProvider`，无需新增运行时依赖。

### 6.2 共享视觉 primitive

| Primitive | 唯一职责 | 首批替换范围 |
| --- | --- | --- |
| `ActionButton/IconButton` | hover/focus/active/disabled/loading、名称和稳定命中区 | 欢迎入口、浮钮、研究图标、标签关闭 |
| `ActionSurface` | 可选择/可拖放的行、卡片或 treeitem 状态 | 文件夹树/卡、标签选择、研究大纲 |
| `StatePanel/InlineNotice` | empty/loading/error/offline/permission/stale 与恢复动作 | 导入、OCR、检索、AI、设置健康状态 |
| `StatusBadge/ProgressSummary` | `TaskStateEnvelope` 与领域 phase 的视觉投影 | 批处理、数据库升级、模型下载、AI job |
| `WorkspaceTabs` | tab/group/close/unsaved/focus/drop 的可视状态 | App 标签栏 |
| `ResponsiveToolbar/MetricStrip` | 命令分组、overflow、换行和指标降级 | 文库、引用、研究、摘录、设置 |
| `OverlaySurface` | layer、focus trap、Esc、返回焦点、碰撞边界 | dropdown/popover/modal/AI panel/selection toolbar |
| `RecordPreview/DetailDrawer` | 明确 preview 与完整详情边界 | AI 记录、摘录、搜索证据、研究输出 |
| `OperationPreview/SelectionScopeSummary` | 影响范围、当前页/全部 N 项、冲突与确认 | 批量移动、删除、AI 外传、研究排除 |
| `UndoNotice/ConflictPanel` | 后端 operationId、undoUntil、保存冲突和恢复 | 文件夹/标签、校对、研究与设置 |

Primitive 只负责视觉与输入状态，不复制领域数据。任务状态、证据身份、CredentialVault、搜索 locator 和数据库真相继续由模块 01 至 07/11 拥有。

### 6.3 CSS 文件与 Ant 边界

第一阶段不强制一次性改成 CSS Modules。按低风险顺序拆分为 `tokens.css`、`base.css`、`shell.css`、`components/*.css`、`views/*.css`，由保留的 `app.css` 按固定顺序导入；使用 `@layer` 或稳定 `data-slot` 控制作用域。每迁移一个页面即删除对应旧区段，禁止新旧 selector 双写长期并存。

Ant 主题优先使用 `ConfigProvider.components`、组件 `styles/classNames` 和局部 wrapper；裸 `.ant-*` 只允许在登记的兼容文件中。门禁记录 raw color、`!important`、裸 z-index、无作用域 `.ant-*` 和重复 selector 的基线，后续提交不得增加，存量按阶段递减。

### 6.4 窗口、缩放、密度与动效

- 最低正式支持窗口定为 `1024x640@100%`；`800x600` 与 320/480px 组件容器作为压力测试，不承诺手机式页面，但所有核心命令仍可到达。
- Electron zoom 与 Windows DPI 分开测：`1024x640@100%`、`1280x720@150%`、`1920x1080@200%`，另测 125%/150% 系统缩放的 Windows 本地包。
- page shell 使用 container query，而不是只看全窗口；只有表格、代码、原图等声明容器可横向滚动，根页面不得意外横滚。
- 所有列表、选择器、任务、命中、record 和 output 使用 cursor/window/虚拟化；renderer 只持有可见窗口、聚合和已选 ID，不把前 20/200/1000 条伪装成全部。并发设置只限制活跃 worker，不限制可接收总量。
- normal/compact 只改变密度，不隐藏唯一命令；pointer coarse 下命中区至少 44px，键盘焦点环始终可见。
- reduced motion 关闭非必要位移、缩放、脉冲、自动滚动和宽度动画；状态变化改用即时颜色、边框与文字。

### 6.5 状态、安全与外传 UI 合同

- 视觉状态按 task、persistence、evidence、coverage、review、capability 六轴表达：任务含 commandState/completionKind，保存含 dirty/saving/conflict，证据含 precision/resolution/verificationStatus，覆盖含 exactness/countsExact/truncated/continuation，复核含 pending/confirmed/excluded/needs-review，能力含 configured/offline/credential-required。禁止把这些压进一个 status 或由 UI 自行计算 sourceHash。
- 设置和 onboarding 只能读取 `PublicProviderProfile`、credential presence/version/state；保存后的 Key 不回填 renderer，不提供“显示已保存密钥”，错误、toast、复制和诊断不得包含 secret。
- AI 外传 operation preview 必须展示 scope、provider/model、内容类别、coverage、预算和产物；确认按钮只消费 main 创建的一次性 preview，不由 UI 自报安全状态。
- 普通问题不得由视觉默认值静默升级为完整研究；正式报告只接受 confirmed 且 provenance verified 的记录，探索草稿必须明确标记为不可直接引用。
- 研究/检索/摘录的 verified/stale/unresolved 必须使用模块 05 至 07 的 locator 和 evidence status；UI 不能把“有颜色/有图标”当作已验证。

### 6.6 双用户 preset 与数据兼容

古籍、地方志和扫描史料内容 preset 保留纸张阅读面、古籍衬线正文、竖排/版式还原和 OCR 质量提示；现代论文内容 preset 使用更中性的工作区、无衬线阅读选项、紧凑表格和作者/DOI/引用信息层级。内容 preset、`system|light|dark` 色彩方案、`normal|high` 对比度、密度和阅读字体互相独立；forced-colors 服从系统。所有组合共享相同功能、状态和 DOM 结构，不复制页面或数据库。

第一阶段把可选非敏感 UI 键加入模块 01 的 `SettingDefinition` 和原子 typed patch；旧键继续读取，缺失时沿用当前行为。不新增表、不改文献、OCR、研究或阅读器数据。阅读器已有 `paper|sepia|dark` 偏好继续由模块 05 拥有，workspace preset 不覆盖单篇阅读偏好。只有实测证明现有 settings 无法表达按文献/工作区配置时，才提出 additive migration，并按模块 11 的备份、幂等事务、回滚、兼容读取和降级写入保护审批。

3. 文库、研究和摘录减少卡片套卡片，增加列表/表格/metric strip 的扫描效率。
4. 文档截图在批准的 Release Candidate 上重新生成，不能由普通 CI 自动覆盖。

### 阶段 F：成品验收与本地用户测试

1. 新增 UI contract、Electron 行为、视觉、contrast、motion 和 overlay 门禁；源码字符串只保留最小架构合同。
2. 在 Windows unpack/安装包执行 NVDA、DPI、高对比、古籍与现代论文主流程。
3. 提供本地构建、变更清单、已知限制、截图差异和回退方式，由用户测试。
4. 用户明确确认无问题并批准公开前，不 push、不创建 PR、不触发 GitHub Actions、不发布 Release。

2. 使用公开合成古籍与论文 fixture 生成自动证据；用户真实文件和数据库只用于本地副本验收，不写入截图或日志。
3. 向用户提供启动方式、UI-01 至 UI-20 结果、截图差异、已知限制、设置兼容和回退步骤。
4. 用户在真实古籍/扫描史料与普通 PDF/论文上测试欢迎、导入、文库、阅读、搜索、AI、研究和摘录。
5. 只有用户明确回复“测试无问题，并批准公开”后，才允许另行 push、PR、GitHub Actions、tag 或 Release。

## 9. 新功能建议

### 9.1 D08-NF-01 工作区显示 preset

**用户问题：** 古籍阅读需要纸面、衬线与版式提示，论文研究更需要中性、紧凑和表格扫描；当前只能共用一套暗色金棕 UI。

**MVP：** 设置页分别提供“古籍研究 / 现代论文 / 自定义”内容 preset、system/light/dark、normal/high contrast、normal/compact 密度和阅读字体，实时预览 toolbar、状态、列表、阅读面和 focus。工作区 preset 与单篇阅读器偏好分开，允许文献覆盖。

**影响与验收：** 复用 ThemeDefinition 和现有 settings，不新增表或服务；切换后不重载文献、不改变 OCR/正文/研究数据。双 fixture 完成同一流程，关闭功能回到当前默认。

### 9.2 D08-NF-02 可恢复的欢迎工作台

**用户问题：** 用户每天首先需要继续阅读或查看进行中任务，而不是重新从六张等权功能卡选择。

**MVP：** 展示继续上次工作、最近文献、进行中/暂停任务、固定专题和紧凑快捷入口；所有数据使用现有分页 API、工作区快照和共享任务摘要，不全库物化。

**影响、验收与回退：** 不增加同步或账号；卡片缺数据时正常降级为导入/打开文库。恢复项目必须使用稳定 ID 和 workspace generation，旧任务不可串入当前页面。关闭该工作台组合后回到现有快捷入口，不删除最近记录、任务或工作区状态。

### 9.3 D08-NF-03 AI 面板停靠与布局记忆

**用户问题：** 浮动面板容易挡住正文，当前只能鼠标拖动/缩放，跨窗口尺寸恢复也不透明。

**MVP：** 提供左/右停靠、浮动、恢复默认和记住当前工作区布局；支持 Pointer、键盘移动/缩放和可见尺寸提示。

**影响与验收：** 使用现有 floating viewport helper 和非敏感 settings；窗口缩小、DPI 变化和显示器切换后重新 clamp。关闭增强功能回到当前浮动默认，无数据库迁移。

### 9.4 D08-NF-04 研究证据检查抽屉

**用户问题：** AI record、摘录和搜索证据在列表中被截断，用户无法在确认前看到完整字段和来源状态。

**MVP：** 一个共享抽屉展示完整 record/摘录、verified/stale/unresolved、coverage、lineage、原文/译文回跳和人工处理动作。

**影响、验收与回退：** 只消费模块 05 至 07 的 locator、record snapshot 和 manifest，不新建证据表；任何 source mutation 后状态同步变 stale，抽屉关闭不改变记录。禁用抽屉后继续使用现有列表和 CSV/JSON 导出，不能删除或改写 evidence/record。

### 9.5 D08-NF-05 文库与研究多视图配置

**用户问题：** 封面网格适合浏览，紧凑列表和元数据表更适合大库筛选；当前不同页面的视图能力不一致。

**MVP：** 文库、文件夹、研究和摘录共享网格/列表/表格视觉合同，按工作区保存列、密度与排序；选择状态以 ID 保存，不依赖当前页对象。

**影响、验收与回退：** 复用现有分页和虚拟化，不增加数据上限；10 万条 fixture 下 DOM 与可见窗口相关，切换视图不丢选择或改变查询语义。关闭新增视图或清除视图设置后回到当前默认视图，保存的列配置可被旧版本忽略且不影响数据。

### 9.6 D08-NF-06 本地能力与健康中心

**用户问题：** OCR、索引、AI provider、数据库维护和备份状态分散在多个页面，失败后难以判断下一步。

**MVP：** 只读汇总 capability snapshot、最近成功时间、stale/blocked 原因和恢复入口；不在打开页面时同步扫描全库。

**影响、验收与回退：** 复用模块 03/06/07/11 的小型 health snapshot 和 TaskStateEnvelope；不得展示 Key、真实路径或正文。关闭或移除中心后，各原设置、任务和健康页继续可用，不删除 snapshot 或触发维护任务。

### 9.7 D08-NF-07 可定制快捷工作区

**用户问题：** 高频用户需要快速进入最近文献、固定文件夹、保存检索或专题，低频入口不应永久占据首屏。

**MVP：** 用户可固定现有命令和对象到欢迎页/侧栏快捷区，支持排序、移除和恢复默认；命令执行与快捷键冲突由模块 09 统一。

**影响、验收与回退：** 第一版保存稳定对象 ID 和布局，不复制对象数据；对象删除后显示 unavailable 并允许移除，不自动指向同名对象。禁用快捷区或恢复默认只清理布局引用，不删除目标对象；无需新依赖。

## 10. 依赖、迁移与审批

- 阶段 A 至 F 可使用现有 Electron、React、Ant Design、TypeScript、CSS、Playwright 和 Node/PostCSS 能力完成，不新增运行时依赖。
- 第一阶段不需要 UI 框架替换、Storybook、CSS-in-JS、主题服务、云字体或外部设计平台；Ant Design 继续使用，但覆盖边界收敛。
- 自动 axe 扫描可考虑 `axe-core/@axe-core/playwright`，但仓库目前未安装。引入前必须单独向用户确认，并提交许可证、包体、维护、误报处理和无依赖替代方案；未获确认时使用 Playwright accessibility tree、键盘测试和 NVDA 人工验收。
- workspace preset、density、motion、panel layout 和快捷区优先保存为现有 typed settings 的可选非敏感键；旧版本忽略，新版本缺失时取兼容默认，不需要数据库迁移。
- 若未来按文献保存更细的显示 profile 或自定义列无法由现有 preference/settings 表达，只能 additive 新增字段/表；必须先证明收益，执行备份、事务、失败回滚、旧版兼容读取和恢复演练。
- 任何新图标包、字体、视觉测试服务、遥测、云同步或外部可访问性服务都标记 **实施前需用户确认**；第一版不上传截图、界面树、文献标题或使用数据。

## 11. 与其他模块的约束

- **模块 01 产品与架构：** ThemeDefinition 和 typed UI settings 属于 renderer 基础设施；任务视觉只消费闭合 `TaskStatus=queued|running|paused|completed|error|canceled`，partial/blocked 使用既有字段，不再定义第二套状态。
- **模块 02 导入与入库：** 欢迎页与选择器只把可直接解析格式称为支持；MOBI/AZW/AZW3 进入明确转换路径。导入数量不设上限，UI 只显示分页队列和用户设置的有界并发。
- **模块 03 OCR 与校对：** OCR 进度、页状态和质量只投影 active artifact/TaskStateEnvelope；视觉 preset 不改变 canonical OCR、坐标或人工校对优先级。
- **模块 04 文库组织：** 文件夹/标签语义、分页和稳定 ID 由文库模块拥有；ActionSurface 只改善键盘、焦点、拖放和视觉状态，不在 renderer 全库物化。
- **模块 05 阅读器：** workspace preset 不覆盖 `paper|sepia|dark` 等单篇阅读偏好；原图、版式还原、竖排、stable locator 和人工内容优先级保持不变。
- **模块 06 检索：** 搜索结果数量、截断、stale 和 locator 使用检索共享合同；UI 不把当前页统计伪装为全局总量，也不靠颜色声称结果 verified。
- **模块 07 AI 与研究：** provider 设置只显示 PublicProviderProfile/credential state；CredentialVault secret 不进入 renderer。外传 preview、evidence status、record/output immutable lineage 和 claim manifest 由模块 07 拥有，详情抽屉只消费。
- **模块 09 交互与工作区：** 模块 08 拥有视觉 token、primitive 和状态外观；模块 09 拥有命令、快捷键、roving focus、拖放、undo、窗口恢复和 latest-request-wins。两章共同修改 `App.tsx` 时必须按阶段串行。
- **模块 10 翻译、引用、导出与写作：** 翻译/引用/导出状态复用同一 Progress/Notice；宽表格、长引用和写作 preview 使用明确局部滚动与完整详情，不静默裁掉可导出内容。
- **模块 11 数据库与备份：** UI 设置默认零迁移；备份、恢复、数据库维护和安全状态只显示脱敏 snapshot，绝不显示真实 Key、私有路径或正文。
- **模块 12 性能、测试与发布：** 建立固定环境视觉基线、资源预算和 UI 快速/完整门禁；CI/Release 顺序后续调整为先验收后打包。业务成品先本地测试，用户批准前不得公开。

实施热点文件按 `theme/global/main -> primitive -> app.css 分域 -> 页面迁移 -> App/Document/Research 浮层` 顺序串行修改，避免 UI、交互、阅读器和 AI 计划同时改写 `app.css`、`App.tsx`、`DocumentView.tsx` 与 `ResearchView.tsx`。本章没有要求数据库迁移，也没有批准任何新依赖或外部服务。
