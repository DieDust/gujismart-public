# 06 全文检索与全库检索

## 1. 本章结论

GujiSmart 当前已经具备一套覆盖面较广的本地检索能力：页面正文与译文索引、简繁转换、单字和短语检索、FTS5/trigram 候选、文件夹与标签范围、文献属性筛选、按文献聚合、全库分页、本文命中目录、阅读器回跳、保存检索、检索历史、AI 关键词扩展、完整段落导出、引用生成和保存为研究摘录。索引写入采用 staging 表和原子替换，后台重建也已经移入 worker，这些基础不应推倒重来。

当前主要问题不是“没有搜索框”，而是搜索结果在不同阶段缺少同一套真实性合同。后端先计算全库总量并分页，前端又只对当前页重新计数并覆盖全局总量；索引按 UTF-16 code unit 逐字做 OpenCC，查询却按整句转换；长页分段重叠会重复计数；导出和研究摘录找不到精确来源时会退到错误首段；本文命中最多物化 20,000 条却不声明截断。搜索、阅读器、译文、导出和 AI 因此可能对“同一命中”给出不同计数、文本和位置。

本章建议把检索重构为四个稳定层次：统一 canonical content 与 phrase-aware normalizer；带版本、可原子切换的索引 generation；在 worker 中执行且有游标、预算和取消语义的 query planner；供阅读器、导出、摘录和 AI 共用的 evidence resolver。文献数量和命中数量不设产品上限，但任何一次请求、内存缓存、IPC 响应和后台 claim 都必须有界。第一阶段无需更换 SQLite，也无需新增依赖；由索引算法变化产生的重建属于可丢弃派生数据升级，不应修改用户正文。只有持久任务、搜索可见状态 generation 或长期快照确有收益时，才执行旁路增量迁移，并按既定规范备份、事务、幂等和回滚。

本章未发现会直接删除用户原文的 P0，但确认多项会造成错误分页、漏检、重复命中、错误证据或主进程长时间阻塞的 P1。它们都应列为优化成品发布阻断项。

## 3. 当前端到端数据流

### 3.1 正文变化与索引生成

```text
导入 / OCR 激活 / 人工校对 / 译文更新
  -> markSearchIndexStaleForPages/Documents
  -> search_index_status = queued
  -> 内存 queuedReindexDocIds
  -> search-index-worker
     -> 分批读取 pages 与 page_translation_units
     -> 选择 proofed_text / OCR / layout / translation
     -> 4000 字分段，后段回退 80 字重叠
     -> OpenCC 归一化 + offset map
     -> staging segments / ngram rows
     -> 原子替换 search_index_segments
     -> FTS5 unicode/trigram 外部内容表
     -> search_index_status = ready
```

页面内容选择已经优先读取 `proofed_text`，并能通过 `proofed_text_ref/ocr_text_ref/ocr_result_ref` hydrate 外置大字段（`src/main/semantic-search.ts:719` 至 `src/main/semantic-search.ts:805`、`src/main/search-index-worker.ts:457` 至 `src/main/search-index-worker.ts:526`）。古籍、报纸、地方志和受管电子书还会按结构化 OCR/IR 读取顺序构造索引文本。译文只索引 ready、非 stale、非 skipped 的 `page_translation_units`（`src/main/semantic-search.ts:3043` 至 `src/main/semantic-search.ts:3080`）。

后台 worker 每次处理一个文献，页面读取批次为 4，segment 写批次为 4，staging 提交后才替换 active 索引（`src/main/search-index-constants.ts:1` 至 `src/main/search-index-constants.ts:17`、`src/main/semantic-search.ts:1477` 至 `src/main/semantic-search.ts:1599`）。这套原子切换是正确方向，应保留并扩展为显式 generation，而不是退回边建边覆盖。

### 3.2 查询、筛选与候选召回

`querySearchV2` 先把查询整句简体化，再把文献、文件夹、标签、作者、年代、阅读状态、元数据状态和收藏条件解析为 doc IDs。随后并行概念上合并 trigram FTS、unicode FTS、ngram、LIKE/scan、exact phrase 和 stale 页面兜底候选，最后重新验证每个 segment 中的 occurrence（`src/main/semantic-search.ts:3350` 至 `src/main/semantic-search.ts:3558`）。

当前标签多选是 AND，文件夹多选及递归后代范围是 OR；文献属性在 SQL 和 `matchesDocumentFilters` 中再次校验。原文/译文 scope 会直接筛选 `source_kind`。这些语义已经被 UI、保存检索和 AI 范围使用，重构时必须显式写入 query contract，不能在性能优化时悄悄改变。

候选查询仍通过同步 `better-sqlite3` 在 Electron main 进程运行。单字和二字查询会强制进入 scan；由于 ngram 当前关闭，scan SQL 没有 LIMIT，会把全库匹配 segment 一次性 `stmt.all()` 到内存（`src/main/search-index-constants.ts:16` 至 `src/main/search-index-constants.ts:17`、`src/main/semantic-search.ts:2586` 至 `src/main/semantic-search.ts:2618`、`src/main/semantic-search.ts:3458` 至 `src/main/semantic-search.ts:3476`）。trigram 和 exact phrase 路径也存在先物化全部匹配候选、再在 JavaScript 聚合的问题。

### 3.3 全库聚合、分页与前端二次计数

后端先遍历所有候选，按文献累积 `totalHits` 和 score，再按 relevance、hitCount、updated、lastOpened 或 title 排序。完成全局排序后才截取当前文献页；因此每一页响应中的 `totalDocuments/totalHits/totalPages` 都应表示同一个全局快照（`src/main/semantic-search.ts:3111` 至 `src/main/semantic-search.ts:3271`）。preview 只给每篇少量 hit，但 total 应保持完整。

`SearchView` 收到一页 groups 后，又为当前页每篇调用 `getDocumentSearchHitPage`，试图让结果数量和阅读器可见命中一致。`applyViewerHitCounts` 只遍历当前页 groups，最后却把 `totalDocuments` 改成当前页 group 数，把 `totalHits` 改成当前页计数和，并用这些 groups 做 `hitCount` 排序（`src/renderer/src/views/SearchView.tsx:501` 至 `src/renderer/src/views/SearchView.tsx:544`）。分页器又依赖这个已被覆盖的 `totalDocuments`（`src/renderer/src/views/SearchView.tsx:1518` 至 `src/renderer/src/views/SearchView.tsx:1523`）。例如后端正确返回 27 篇、每页 10 篇，后台二次计数完成后第一页会变成 10 篇总量，分页器消失。

二次计数请求还没有携带 `translationScope` 和 `contextMode`（`src/renderer/src/views/SearchView.tsx:509` 至 `src/renderer/src/views/SearchView.tsx:516`），却会把返回的 hits/topHits 一并覆盖。仅译文检索可能被原文命中污染，点击后再把错误 locator 交给阅读器。

### 3.4 本文命中、阅读器回跳与返回状态

展开一篇文献时，前端调用 `getDocumentSearchHitPage`。后端实际上先加载整篇全部 segment，构造最多 20,000 个 hit，再在内存中切当前 10 条（`src/main/semantic-search.ts:3561` 至 `src/main/semantic-search.ts:3624`）。因此 UI 看似分页，main 进程的工作和内存仍与整篇命中数线性增长，而且超过上限时没有 `truncated/countsExact/nextCursor`。

点击命中后，`SearchView` 把 locator、关键词和单条 search session 传给 `DocumentView`。精确 locator 理论上包括 page/href、segment、绝对 char range、query term 和 occurrence。阅读器再把它映射到文本、高亮或 OCR 框。模块 05 已确认 `DocumentView` 的 OCR 聚焦会退到同页第一个包含关键词的框；搜索侧又会在旧扁平结果缺 locator 时伪造 `charStart=0/charEnd=0`（`src/renderer/src/views/SearchView.tsx:426` 至 `src/renderer/src/views/SearchView.tsx:444`）。这两条降级会把“只能定位到页”伪装成“精确定位到字符”。

检索返回快照保存在 sessionStorage，Zustand 则只保存 keyword、results、groupedResponse、filters 和签名。mode、sort、contextMode 仍是 `SearchView` 本地默认状态（`src/renderer/src/stores/useSearchStore.ts:22` 至 `src/renderer/src/stores/useSearchStore.ts:64`、`src/renderer/src/views/SearchView.tsx:619` 至 `src/renderer/src/views/SearchView.tsx:624`）。打开文献后 SearchView 卸载，返回时 AI/全文模式、命中数排序和上下文长度可能重置，签名不一致又会清除滚动和展开状态。

### 3.5 导出、研究摘录与 AI 证据

导出预览、正式导出、诊断导出和“保存全部检索摘录”都会重新以 `exhaustive + resultMode='all'` 执行查询（`src/main/ipc/search.ts:846` 至 `src/main/ipc/search.ts:1007`）。随后 `getHitSourceText/getHitParagraph` 尝试从页面或 segment 恢复完整段落，并生成引用和 research note locator。

当前页面证据读取只查 inline `proofed_text/ocr_text`，不 hydrate `*_ref`；无论命中是否来自译文，只要原页面有正文就优先返回原文；segment 内 occurrenceIndex 又被拿去查整页第 N 次出现（`src/main/ipc/search.ts:278` 至 `src/main/ipc/search.ts:408`）。若匹配和 charStart 都失败，`expandToParagraphWithRange` 会返回候选中的第一段，而不是 fail closed。索引 segment 只持久保存前 360 字（`src/main/semantic-search.ts:1413` 至 `src/main/semantic-search.ts:1421`），页面正文超过阈值时又会外置，因此错误降级并非罕见边界。

AI 搜索先生成计划和多语言关键词，再对最多 32 个查询依次执行本地全文检索，按页去重并交给 AI 回答（`src/main/semantic-search.ts:3882` 至 `src/main/semantic-search.ts:4186`）。如果底层命中、计数或 locator 不真实，AI 的“有引用回答”也只是在放大错误证据。因此 AI 模块不能建立另一套搜索真相，必须消费同一个 evidence pack 和 snapshot。

### 3.6 保存检索、缓存与健康状态

保存检索会把 keyword、mode、filters、sort、contextMode 和当前结果缓存写入 `saved_searches.filters` JSON。运行时用文献、页面和索引状态的 count/MAX 时间生成 library fingerprint（`src/main/semantic-search.ts:4211` 至 `src/main/semantic-search.ts:4300`）。标签/文件夹 junction 变化以及 `last_opened_at` 更新不一定改变这些统计，因此筛选或 lastOpened 排序已经变化时仍可能命中旧缓存。

AI 保存检索在缓存失效后不会重新执行 `aiPlannedSearch`：`runSavedSearch` 只为 fulltext 模式重跑，AI 模式返回空 results/grouped，却由前端提示“已重新检索并刷新缓存”。这是伪成功。

索引状态列表固定最多返回 200 条，无 cursor 和总数（`src/main/semantic-search.ts:1846` 至 `src/main/semantic-search.ts:1853`）。`ready` 只检查存在 segment，不校验 `SEARCH_INDEX_VERSION`；健康映射也允许未知旧前缀继续 ready。查询同步 scan 完成后仍返回并缓存 `status='scanning'`（`src/main/semantic-search.ts:3529` 至 `src/main/semantic-search.ts:3558`），把“执行策略”误写成“尚未完成的任务状态”。

## 4. 必须保留的能力

- 完全本地、离线可用的全文检索；不能把外部服务作为基本搜索的前提。
- 古籍与通用 PDF/论文同等支持，保留单字、短词、繁简、异体显示和长短语搜索能力。
- 人工校对优先，OCR、结构化版面、电子书正文和 ready 译文均可检索，并能区分来源。
- 文件夹递归范围、标签组合、文献选择、作者、类型、年代、OCR/阅读/元数据状态和收藏筛选。
- 按文献聚合、全局排序、全库分页、每篇预览和本文命中分页。
- 从检索命中精确返回原页、正文、OCR 框或译文单元；无法精确定位时必须诚实降级。
- 保存检索、最近检索、返回状态、导出 TXT/Markdown/CSV/JSON、引用和保存研究摘录。
- AI 检索、AI 问答和 AI 研究继续复用本地检索证据，不另建不可追溯结果池。
- staging 构建、原子索引切换、内容变化标 stale、大字段外置兼容和删除文献后的索引清理。
- 文献、页、任务和命中总量不设产品上限；只限制当前请求、批次、游标窗口、缓存字节和工作并发。
- 现有 SQLite、`pages`、`search_index_segments`、`search_index_status`、`saved_searches` 和研究摘录默认原位兼容。

## 5. 关键问题

### D06-P1-01 当前页二次计数会破坏全局总量、分页、排序和译文范围

**证据等级：已确认。**

后端先计算全部 group 的总量和排序，再只返回当前页 groups（`src/main/semantic-search.ts:3184` 至 `src/main/semantic-search.ts:3270`）。前端 `applyViewerHitCounts` 只重算当前页，却把 `totalDocuments`、`totalHits` 和 groups 全部替换（`src/renderer/src/views/SearchView.tsx:501` 至 `src/renderer/src/views/SearchView.tsx:544`）。分页显示条件使用被改写的 `totalDocuments`（`src/renderer/src/views/SearchView.tsx:1518` 至 `src/renderer/src/views/SearchView.tsx:1523`）。`hitCount` 也只在当前页排序，无法得到真正的全局命中数排序。

该请求没有传 `translationScope/contextMode`，但会替换 hits/topHits。仅译文和仅原文结果可被另一来源污染，用户点击后进入错误位置。

**影响：** 正确的后端分页会在页面渲染后消失或变少；全局总命中和排序错误；译文/原文 scope 可能展示并打开错误证据。这是直接用户可见的准确性问题。

**落实方案：** 删除 renderer 的“当前页重写全局 totals”和局部 recount 职责。后端初始 snapshot 直接返回与阅读器使用同一 normalizer/evidence resolver 得出的全局 counts，`hitCount` 必须先全局聚合排序再分页。若精确计数只能异步完成，校准必须生成新的完整 snapshot，重新完成全局聚合、排序和分页后原子替换；不得只 patch 当前文献而让文献计数之和、全局 totals 和页边界属于不同快照。

### D06-P1-02 索引、查询和阅读器使用不同归一化与 offset 算法

**证据等级：已确认并用 OpenCC 探针复现。**

查询通过 `normalizeChineseSearchText` 整句转换（`src/main/text-normalization.ts:1` 至 `src/main/text-normalization.ts:12`），索引主线程和 worker 却对每个 UTF-16 code unit 单独调用转换器（`src/main/semantic-search.ts:582` 至 `src/main/semantic-search.ts:598`、`src/main/search-index-worker.ts:333` 至 `src/main/search-index-worker.ts:349`）。这会漏掉 `一目瞭然/反覆` 等上下文短语，并把 `上鍊` 索引为与整句查询不同的字。

renderer 的 `searchHitCount.ts` 又对整段 OpenCC 后直接把归一化字符串 index 当原文 index（`src/renderer/src/utils/searchHitCount.ts:92` 至 `src/renderer/src/utils/searchHitCount.ts:148`）。遇到转换为补充平面字符的文本，UTF-16 长度变化会让 charStart、高亮和切片错位。校对模式部分路径只 lowercase，不做相同繁简归一化。

`SEARCH_INDEX_VERSION` 已到 `segments-v12-trigram-fts-verified`，但 ready 判断只检查 segment 是否存在，不校验 source hash 前缀（`src/main/search-index-constants.ts:1`、`src/main/semantic-search.ts:1061` 至 `src/main/semantic-search.ts:1080`）。升级 normalizer 后旧索引仍可能被当成当前索引。

**影响：** 古籍和繁体文献出现系统性漏检；计数、snippet、locator 和阅读器高亮不一致；索引算法升级后无法可靠触发重建。

### D06-P1-03 导出和研究摘录可能返回错误原文或错误首段

### D06-P1-04 80 字 segment overlap 会重复计数、分页和导出同一命中

### D06-P1-05 短词和大候选查询在 Electron 主进程同步无界物化

**证据等级：已确认。**

**落实方案：** 查询执行移入只读 search worker，main 只负责 IPC 生命周期和轻量聚合。所有 SQL 使用 cursor/keyset 或固定 candidate batch，响应以 document page/hit page 分批返回。短词第一阶段在 worker 分块精确扫描，保持完整召回但不阻塞 main；随后基于现有 `search_ngram_index` 评估无 positions 的 1/2-gram sidecar，按基准决定是否启用。缓存采用条目数、估算字节和单响应上限三重预算，all-mode 不进入普通响应缓存。

### D06-P1-06 主检索、全库分页和本文命中分页没有 latest-request-wins

**证据等级：异步控制流已确认。**

**落实方案：** 明确三种不同身份。renderer 单调 generation/requestId 从请求发出前就存在，阶段 A 先用它保证旧响应绝不写 UI、history、cache 或 loading；criteriaKey 只表达 query、page、scope、sort 和 context 是否相同，不负责竞态仲裁；snapshotId 由后端响应生成，只用于后续 cursor、aggregate、导出和 evidence 一致性。阶段 A 尚在 main 同步查询时不承诺真实中断，只做结果失效；阶段 B 查询移入 worker 后，再通过 `search:cancel(requestId)`、deadline 和 worker cooperative cancel 真正停止后续批次。保存检索恢复、历史恢复、完整 snapshot 替换和导出预览等所有写搜索状态的入口都经过同一 generation gate。

### D06-P1-07 capped 与 unbounded 搜索路径分裂，均缺少完整性合同

**证据等级：已确认。**

`MAX_DOCUMENT_SEARCH_SESSION_HITS=20000` 会限制单文献 `buildHitsFromRows/getDocumentSearchHitPage`，source/translation 特殊分支也把 SQL 候选限制为 20,000（`src/main/semantic-search.ts:332` 至 `src/main/semantic-search.ts:333`、`src/main/semantic-search.ts:2947` 至 `src/main/semantic-search.ts:2979`、`src/main/semantic-search.ts:3419` 至 `src/main/semantic-search.ts:3435`、`src/main/semantic-search.ts:3601` 至 `src/main/semantic-search.ts:3624`）。这些响应没有 `truncated/countsExact/nextCursor`。

一般 `querySearchV2(..., resultMode='all')` 并不统一受该上限保护，`groupRowsByOccurrences` 仍可能物化全部匹配 rows/hits。当前合同因此一部分静默截断，另一部分无界占用内存，调用方却无法区分。

**影响：** 高频单字或大型语料可能静默少报命中，也可能在一般 all-mode 中无界增长；最后页、导出和统计不可信，用户无法知道结果是否完整。

**落实方案：** 统一 capped/unbounded 两类路径：列表分页采用 cursor，不为得到第 N 页先物化前 20,000 条；任何安全上限触发都必须返回 `truncated=true` 和 continuation，一般 all-mode 也必须受 candidate/response 字节预算约束。响应明确返回 `countsExact`、`truncated`、`continuation`、`coverage` 和 `snapshotId`。精确总数可作为独立可取消 aggregate job 渐进计算；未完成前 UI 显示“至少 N 条/仍在统计”，不得伪装精确值。导出使用流式 cursor 直到完成或用户取消，不复用 UI 截断集合。

### D06-P1-08 大范围筛选会物化全部 doc IDs，筛选控件又静默只加载 1000 篇

**影响：** 小库正常、大库筛选报错或静默不完整；这与“文献总量逻辑上无限”的产品约束直接冲突。

**落实方案：** query planner 直接使用 `EXISTS/JOIN` 和临时 scope relation，而不是先把全量 ID 拉进 JavaScript。明确文献 ID 小集合才使用 chunked IN；大范围以 scope token 或只读临时表传给 worker。筛选控件改为服务端搜索、cursor 分页和已选项单独 hydrate，不能把“可选择范围”绑定到前 1000 条。

### D06-P1-09 索引重建队列可能永久卡死、重启丢失或被环境变量误禁用

**证据等级：已确认。**

**影响：** 用户看到 queued/processing 永久不结束；手动修复可能无效；大库全量重建本身违反队列有界要求。

**落实方案：** worker 未 settled 的任何 exit 都 reject；增加 progress idle timeout 和 hard timeout，超时 terminate、记录错误并继续下一 item，迟到消息只能结算一次。代码库当前尚不存在模块 02/03 所规划的统一 `task_jobs/task_items` scheduler，因此搜索持久重建阶段明确阻塞于该共享迁移完成，不得先建搜索专属物理队列。统一 scheduler 中使用 `kind='search-index'`，以 `(docId, canonicalContentVersion, indexVersion)` 去重；同一文献的新版本合并/取代未开始旧 item，一个数据库同一时刻只允许一个索引写 claim，并与 OCR 激活和 database maintenance 协调写预算。全库任务按文献主键 cursor 发现，`autoReindex` 只控制自动创建，手动任务始终可执行；重启恢复 lease 过期项，支持暂停、取消和失败重试。

## 6. 目标架构与兼容策略

```text
Canonical Content Activation
  -> Search Visibility Generation
     -> Persistent Reindex Job / Item / Lease
        -> Phrase-aware Normalizer vN
        -> Stable Source Slices + Source Range Map
        -> Staging SearchIndexGeneration
        -> Atomic activation, old generation still readable

SearchRequestEnvelope
  -> requestId + rendererGeneration + query state + deadline
  -> Search Query Worker
     -> scope relation / metadata filters
     -> query parser and planner
     -> trigram / FTS / short-query sidecar or bounded scan
     -> exact verification + canonical overlap dedupe
     -> global aggregate/sort -> document cursor
     -> per-document hit cursor
  -> SearchResponseEnvelope
     -> snapshotId + coverage + countsExact + truncated + continuation

Canonical SearchEvidenceResolver
  -> reader navigation
  -> export stream
  -> research excerpts
  -> AI evidence packs
  -> citations and diagnostics
```

核心原则：

- 索引和搜索结果都是派生数据；任何升级失败不得破坏用户原文、校对、译文或研究摘录。
- 一个 canonical source range 只对应一个用户可见命中，segment、FTS row 和缓存 key 不是命中身份。
- 全库总量、排序和分页必须来自同一 snapshot；当前页不能反向改写全局事实。
- SQLite 不提供可跨 IPC 自动恢复的 MVCC snapshot；本方案使用 generation-bound snapshot，generation/TTL 变化时返回 `snapshot_expired` 并原子重跑，绝不混合两代数据。
- 精确定位必须可验证；不知道字符范围时诚实返回 page precision，不填假零值。
- stable sourceRanges 统一使用带版本的 UTF-16 code unit offset；code point 只用于 normalizer 对齐，边界转换必须显式。
- main 进程不执行会随语料规模增长的同步查询、聚合、段落解析或文件拼接。
- 文献/任务/命中总量可无限增长，但 worker 并发、claim 数、candidate batch、响应字节、缓存字节和导出批次必须有界。
- 搜索、阅读器、AI、引用和导出使用同一 normalizer、content version、locator 和 evidence resolver。
- 第一阶段优先兼容现有 SQLite 和 JSON；新增结构旁路写入，旧客户端可忽略，旧数据惰性升级。

DTO 放入 shared 并通过 preload 显式暴露。`StableReaderLocator` 是模块 05、搜索、目录、摘录、引用和 AI 共用的唯一定位基类，完整 schema、判别 variants 和必填项以模块 05 为权威；搜索只能组合 `SearchMatchMetadata`，不能改名基类字段或再发明平行 locator。现有 `SearchHitLocator` 消费者至少保留一个公开版本：exact stable locator 通过 adapter 投影现有 `docId/segmentId/segmentOrdinal/charStart/charEnd`，需要旧 `pageId/pageIndex` 时只在 adapter 内由 `sourcePageId` 映射；page/document precision 不生成假 legacy locator，而是通过现有 `OpenDocumentTarget.pageIndex` 打开，旧 flat result 的 optional locator 保持缺省。新 API 同时返回 stable locator，迁移完成后再删除 legacy 投影。

第一阶段可把 `SearchIndexGeneration` 映射到现有 `search_index_status.source_hash + staging tables`，不要求立即给 `pages` 加列。`SearchGroupedResponse` 继续返回旧字段，同时 additive 增加 envelope 字段；旧 renderer 一个兼容周期内仍可工作。当前全局 Zustand/sessionStorage key 必须迁移为按 `tabId/sessionId` 隔离的 `SearchTabSession`，否则多个搜索标签页仍会互相覆盖。

`SearchSnapshot` 不通过长时间持有 SQLite 只读事务实现。worker 创建 snapshot 时记录 library generation 和当前范围内 active index generation 的稳定 hash；每次 document cursor、hit cursor、aggregate、导出和 evidence 请求都重新校验。generation 变化或 TTL 到期时返回 `snapshot_expired`，renderer/任务可在新 generation 上原子重跑，不允许把旧第一页与新第二页拼接。这样避免长事务阻塞 WAL checkpoint，也不要求物化全量结果表。

## 7. 分阶段落实方案

### 阶段 A：先修正确性和请求竞态

- 删除当前页 recount 覆盖全局 totals 的逻辑；scope/context 完整透传，后端建立唯一计数语义。
- shared normalizer 改为整句 phrase-aware，并生成 normalized code point/code unit 到 source UTF-16 range 的版本化映射，覆盖索引、查询、reader highlight 和 evidence。
- 提升 index version；ready 判断增加 current/compatible/incompatible，后台用 staging 重建旧 generation。
- 按绝对 source range 去重 overlap 命中；计数、排序、分页和导出使用同一 canonical hit key。
- 检索导入模块 05 的 shared `StableReaderLocator` 判别联合，并以独立 `SearchMatchMetadata` 附加查询信息；旧结果只经 adapter 生成 page precision，不伪造 charStart=0。
- 修正 evidence resolver：hydrate refs、区分 translation、按 range/quote 验证、失败 fail closed。
- 主检索、完整 snapshot 替换、本文命中和导出预览加入 renderer generation；阶段 A 只保证旧结果失效，不声称能中断仍在 main 执行的同步 SQL。
- worker `exit(0)`、timeout、迟到消息和 cleanup 补齐生命周期测试。
- 本阶段不迁移用户正文、不新增依赖；索引可随时从 canonical content 重建。

### 阶段 B：查询移出主进程并建立有界游标

- 新增只读 search query worker，复用当前 worker_threads 和 SQLite；main IPC 只转发 request/cancel/status，阶段 B 起才提供真正的 deadline/cancel。
- 将 filter scope 变为 SQL JOIN/EXISTS 或 worker 内 scope token；只对很小显式 docIds 使用 chunked IN。
- document groups 和 document hits 分别使用稳定 cursor；不先构造 20,000 hits 再 slice。
- snapshot 绑定 library/index generation vector；每次 cursor 校验，变化或 TTL 到期返回 `snapshot_expired`，不持有跨 IPC 长事务。
- 返回 snapshotId、coverage、countsExact、truncated 和 continuation；精确计数独立可取消。
- 短词先使用 worker 分块 scan 保持召回；基准后评估启用现有 ngram 表的 1/2-gram sidecar。
- 缓存建立 entry/bytes/single-response 三重预算，all-mode 和导出流不进入普通缓存。
- UI 文献筛选改为远程搜索和 cursor 分页，已选项独立 hydrate。

### 阶段 C：共享 scheduler 落地后的持久索引任务与 generation 存储

- 前置条件是模块 02/03 的统一 `task_jobs/task_items/lease` 已完成共享迁移和运行时；搜索只注册 `search-index` kind，不建立独立 scheduler。
- item 去重键为 `(docId, canonicalContentVersion, indexVersion)`；新内容版本合并未开始旧 item，已开始旧 item 完成后不得激活为 current。
- 以文献主键 cursor 发现任务，不一次装入全部 IDs；单数据库索引写 claim 与 OCR/维护写操作共享资源协调器。
- 手动、自动、OCR 激活、校对提交、译文更新和数据库维护都创建同一类型 job；优先级和并发由设置页统一控制。
- `autoReindex=false` 只禁止自动创建，手动修复始终可执行。
- worker heartbeat/idle/hard timeout、暂停、取消、重启恢复和错误重试写入持久状态。
- 建立 `librarySearchGeneration`，所有搜索可见变更事务内 bump，统一失效内存和保存检索缓存。
- 在支持激活后回滚、双代并存或延迟清理前，必须完成 generation-aware additive storage migration，例如 generation 主表与带 generationId 的 segment 存储；现有表只能保证“新 staging 提交前旧 active 仍可用”，不能承诺提交后的旧代回滚。
- generation-aware 存储落地后，activation 原子更新 active 指针，旧 generation 按保留策略延迟清理；失败保留可搜索版本。

### 阶段 D：证据、导出、摘录和 AI 统一

- 阅读器、检索列表、导出、研究摘录、引用、AI 问答和 AI 研究全部调用 `SearchEvidenceResolver`。
- 导出使用 snapshot cursor、流式 writer、临时文件和原子 rename；支持取消、失败恢复和真实统计。
- 批量保存摘录按幂等 evidence hash 小事务提交，并保留 unresolved/skipped 原因。
- 译文 hit 直接聚焦 translation unit，并能同步显示对应原文 source slice。
- AI search/research 保存 query plan、snapshotId、index coverage 和 evidence contentVersion；底层证据变化时标 stale，不静默复用。
- 保存 AI 检索 cache miss 时真正重跑或明确要求用户重跑，不返回伪成功空结果。

### 阶段 E：查询体验与状态恢复

- 将条件、导航和可见快照分别收口为 `SearchCriteria`、`SearchNavigationState` 和 `SearchViewSnapshot`；每个搜索标签由 `SearchTabSession(tabId/sessionId)` 独立持有。
- 标签页返回、应用重启、保存检索和最近检索都恢复完整状态；多个搜索标签页不得共享全局 return key。旧 page number 通过兼容适配器转换为 cursor，旧历史惰性补默认值。
- 模式使用 segmented/radio 语义并在 AX tree 暴露选中状态；Select/Switch 有关联名称；删除、保存、导出使用带 `aria-label` 的独立图标按钮，tooltip 只作视觉补充。
- loading、结果总数、错误、取消和截断通过 status/live region 宣告；删除后焦点移动到相邻记录，从阅读器返回后恢复到原命中或展开项。
- 空结果、索引补建、部分覆盖、截断、取消、离线和错误使用统一 status envelope。
- 大量结果列表和 facet 使用窗口化/分页，不在 renderer 保留全量 hit 或文献对象。

### 阶段 F：基准、可选增强索引与兼容迁移

- 建立古籍、论文、OCR 噪声、繁简短语、单字高频、译文和超大库固定语料基准。
- 冻结当前机器上的 p50/p95、event-loop delay、worker RSS、DB 增量、索引构建吞吐和召回率基线。
- 只有 1/2-gram sidecar 明显改善短词 p95 且磁盘增长可接受时启用；支持 lightweight/enhanced 配置并可重建回退。
- 持久 search job 依赖统一 scheduler migration；激活后回滚/双代并存依赖 generation-aware storage migration。这两项一旦进入对应阶段就是前置条件，不得以现有表声称已支持。
- `librarySearchGeneration` 若需要事务级一致性，执行单行 additive migration；全部迁移都自动备份、事务建表、幂等回填、旧版忽略、失败回滚。
- 外部搜索服务、向量数据库、本地 embedding/重排模型只作为后续候选，实施前必须单独获得用户确认。

| SRCH-28 | canonical content 激活后才使匹配版本的索引 item 可见 | OCR staging、proof draft、active revision 切换、旧 item 晚完成、与维护写竞争 | 未激活内容不进入搜索；过期 item 不激活；单数据库写预算受协调器约束 |
| SRCH-29 | folder/tag/lastOpened/page/index 变化都使 saved cache 失效 | 分别变更一种状态 | 无变化的第二次运行可 cache hit |
| SRCH-30 | AI 保存检索 cache miss 后按明确合同处理 | 模型可用时必须真实重跑；模型不可用时返回 `requiresRerun`；另测索引 stale | 任何分支都不返回空成功 |
| SRCH-31 | 完整查询状态按搜索标签隔离并跨阅读器返回恢复 | 两个 search tab 使用不同 mode/scope/page；分别打开并关闭文献标签返回 | criteria、展开项、hit cursor、滚动锚点和焦点各自保留 |
| SRCH-32 | 导出 100 万命中使用流式 cursor | TXT/MD/CSV/JSON、取消、磁盘满 | 临时文件清理，已保存源数据不变 |
| SRCH-33 | 导出预览只展示 3 条但总统计精确 | 大于 3 段且含 unresolved hit；等待流式 count pass 完成 | ready 时 `exportableParagraphs/skippedHits` 等于完整 snapshot，不固定为 3 |
| SRCH-34 | 批量保存摘录幂等、可恢复、部分失败可诊断 | 重复执行、DB busy、进程退出 | 已保存记录不重复，原研究笔记不覆盖 |
| SRCH-35 | 同步完成结果状态为 complete | 首次 scan 与缓存命中 | strategy 可为 scan，status 不为 scanning |
| SRCH-36 | 健康列表可分页并筛选所有失败项 | 1000 个 status、旧版、错误版 | 旧 200 条调用方继续读第一页 |
| SRCH-37 | 空、失败、取消、stale、partial 和 truncated 可区分 | worker timeout、空范围、坏索引、用户取消 | 旧字段仍提供兼容值 |
| SRCH-38 | 模式、筛选、历史、删除和结果状态可键盘/读屏操作 | Playwright role/name/keyboard + Chromium AX tree；Release 前 Windows NVDA smoke | `aria-label`、选中状态、live region 和焦点恢复正确；鼠标不退化 |
| SRCH-39 | 古籍和通用论文共用合同但保留适合的查询体验 | 单字竖排古籍、英文论文、表格、EPUB、译文 | 不要求迁移到另一文献类型 |
| SRCH-40 | 搜索结果、阅读器、引用、导出和 AI 对同一命中返回同一稳定身份 | 逐模块比较 sourceKind、contentVersion、sourceHash、sourceRanges、offsetUnit 和 quote | 无法一致时阻止证据消费 |
| SRCH-41 | 旧数据库可无损升级索引，并在需要双代/回滚时完成 generation-aware migration | 旧库、半建 staging、坏 status、磁盘不足、generation 表迁移失败、激活后回滚 | 自动备份；迁移/构建失败继续使用旧 active；无 generation 存储时不宣称激活后回滚 |

性能门槛先在固定 Windows 机器、固定 SQLite、固定语料和固定并发下冻结基线。`main event-loop delay p99 < 50ms`、取消后 200ms 内停止继续投递批次、单响应默认小于 2MB、renderer 只保留当前文献页和命中页窗口可作为待实测确认的初始护栏；最终阈值按基线调整。确定性要求不变：主进程工作、worker 并发、内存、缓存和 IPC 不得随总库规模无界增长。

## 9. 新功能建议

### 9.1 D06-NF-01 高级检索构造器与可读查询语法

**用户问题：** 当前输入框会在整句和分词 fallback 之间切换，但用户无法明确表达“必须同时出现”“排除”“相邻”“字段限定”和“精确短语”。古籍研究常需要字词共现，论文用户又需要作者、题名、年份和正文组合。

**优先级、成本、风险与前置：** P3（第一批增强），中等成本。主要风险是 parser 歧义、旧保存检索含义漂移和复杂条件导致计划退化；前置任务为阶段 A 的统一 normalizer/criteria contract、阶段 B 的 query planner 与阶段 E 的标签页状态隔离。

**MVP：** 在现有搜索页增加可视化条件行：必须包含、任一包含、排除、精确短语、同页/同段相邻距离，以及 title/author/body/translation/folder/tag 字段。高级用户可查看并编辑一套稳定、可分享的 query text；普通用户继续直接输入关键词。

**实现影响：** shared 增加版本化 query AST，parser 只输出白名单节点；planner 映射到 FTS、metadata JOIN 和 exact verifier。保存检索保存 AST 和可读文本，不保存拼接 SQL。第一版可用现有 TypeScript 自写小型 parser，不引入依赖。

**系统与合规影响：** shared/preload/IPC additive 增加 `queryAst/queryText/schemaVersion`；数据库只扩展 `saved_searches.filters` JSON，设置保存每个搜索标签的高级模式偏好，导出快照 JSON 记录 AST 版本。全部本地执行，不增加文献外传、许可证或离线依赖。

**新版验收与回退（D06-NF-01-A）：** parser 错误显示具体位置，不执行部分查询；同一 AST 序列化幂等；关闭高级模式仍可运行现有简单关键词。旧 saved search 惰性包装为 `simpleText` 节点。

### 9.2 D06-NF-02 检索分面与结果分布分析

**用户问题：** 用户知道“命中了多少”，但难以快速判断结果集中在哪些年代、作者、文献类型、标签、文件夹或章节。

**优先级、成本、风险与前置：** P3，中等成本。风险是高基数聚合拖慢查询、近似 count 被误认为精确值以及分面与主结果跨 snapshot；前置任务为阶段 B 的 worker/cursor/snapshot 和阶段 E 的统一状态 envelope。

**MVP：** 结果侧栏展示文献类型、年代、作者、标签、文件夹和原文/译文分面；点击分面追加筛选。分面绑定同一 snapshot，可选择“当前结果精确统计”或“快速近似”。

**实现影响：** query worker 在同一 scope 上运行有界 aggregate cursor，返回 bucket、count、countsExact 和 continuation。高基数字段只返回 top K + 搜索入口，不向 renderer 传全量作者/标签。

**系统与合规影响：** IPC additive 增加 facet cursor/envelope；交互式分面第一版不新增用户数据表，只使用可清理派生缓存。若某项 aggregate 被 AI 数据集、正式报告或研究输出采用，必须在 SearchSnapshot 过期前提升为核心 `ResearchAggregateArtifact`，冻结 criteria/generation/exactness/population/sample/coverage/result payload+hash，并按引用计数保留；正式输出不得引用 TTL cache。设置保存侧栏开关、精确/快速统计偏好。内容留在本机，无新依赖、许可证或联网要求。

**新版验收与回退（D06-NF-02-A）：** 分面 count 与应用后的结果总量一致；统计未完成时明确标记；取消或换查询立即废弃旧 snapshot。关闭侧栏不影响主检索。

### 9.3 D06-NF-03 OCR 置信度与异体字感知检索

**用户问题：** 古籍 OCR 常把形近字识错，严格字符串检索会漏掉最需要校对的材料；普通论文扫描也有断词、连字符和页眉干扰。

**优先级、成本、风险与前置：** P3，高成本。主要风险是假阳性、不同 OCR 引擎置信度不可比和扩展候选误入引用/AI；前置任务为模块 03 的 canonical OCR range/置信度合同，以及阶段 A、D 的 normalizer 和 evidence resolver。

**MVP：** 默认仍返回严格命中；用户可开启“扩展召回”，加入 OCR 低置信候选、常见异体/形近字和断词变体。每条扩展结果标明原因和置信度，不与严格命中混为同一精度。

**实现影响：** 复用 OCR artifact 的 block confidence、错误码和 canonical range。第一版使用可审阅的本地规则表与项目词表；如果后续引入新的异体字库、模糊匹配库或模型，必须先审查许可证、体积和准确率，并标记 **实施前需用户确认**。

**系统与合规影响：** IPC 返回扩展原因、规则版本和 confidence，数据库第一版不迁移，只引用现有 OCR artifact/项目词表；设置提供 strict/扩展开关和规则白名单，导出格式显式标注候选而非事实。默认离线且不上传正文；任何新字库、模型或服务都需单独评估许可证、包体、隐私并在实施前获得用户确认。

**新版验收与回退（D06-NF-03-A）：** strict 模式召回不变；扩展命中可解释、可一键排除规则；任何未经用户逐条确认的扩展候选都不得进入引用或 AI 证据。用户确认后仍必须引用真实 source slice，并记录规则版本和 `confirmed_by_user`，不能把模型/规则置信度当成人工确认。

### 9.4 D06-NF-04 保存检索监测与新增命中提醒

**用户问题：** 文献持续导入和 OCR 后，用户需要知道某个研究主题是否出现新证据，而不是反复手动运行保存检索。

**优先级、成本、风险与前置：** P3，高成本。风险是后台任务争抢 OCR/索引资源、重复提醒和库 generation 误判；前置任务为阶段 C 的统一 scheduler、`librarySearchGeneration` 和版本化 query AST。

**MVP：** 保存检索可开启本地监测。仅在导入、OCR/校对激活、标签/文件夹变化导致 library generation 前进时增量重跑，显示“新增 N 篇/N 处”，可查看自上次确认后的差异。

**实现影响：** 保存 `lastEvaluatedGeneration` 和稳定 query AST；监测任务复用统一 scheduler，低优先级、并发有界。差异保存 locator/evidence hash，不复制整段原文。第一版不发送云端通知。

**系统与合规影响：** preload/IPC 增加 monitor CRUD、暂停与差异 cursor；持久状态优先 additive 写入 saved search JSON，若任务历史需要独立表则按备份/事务/回滚迁移；设置提供全局并发、安静时段和单项开关，差异可导出版本化 JSON。默认仅本地通知和本地计算，无新依赖、许可证或外部服务。

**新版验收与回退（D06-NF-04-A）：** 重复 generation 不重复提醒；删除文献显示移除而不制造新命中；关闭监测立即停止任务，卸载/降级时旧客户端仍可忽略 additive 状态。

### 9.5 D06-NF-05 可复现证据篮与研究证据快照

**用户问题：** 研究写作需要说明“当时用什么条件、在哪个库版本下选取了哪些证据”。当前历史和保存检索会随库变化刷新，无法重现当时被研究者确认并采用的证据集合。

**优先级、成本、风险与前置：** P3，中高成本。风险是长期 quote 带来存储/隐私负担、用户把 stale 快照当成当前事实，以及删除源文献后的证据语义；前置任务为阶段 A、D 的 stable locator/evidence resolver 和阶段 B 的 generation-bound snapshot。

**MVP：** 用户把选定命中加入证据篮，生成长期 `ResearchEvidenceSnapshot`，记录 query AST、filters、sort、来源查询 snapshot generation、index coverage、locator、source hash 和引用信息。它只冻结用户选定的证据及其检索上下文，不承诺永久保存当时的完整结果集；可导出版本化 JSON/Markdown 清单，并在源内容变化时标 stale。

**实现影响：** 复用模块 07 唯一 `ResearchEvidence` identity、project annotation 和引用格式；模块 06 只拥有“从哪个 SearchSnapshot/query 选择并加入证据”的 basket/snapshot relation，不再创建平行 evidence 本体。`ResearchEvidenceSnapshot` 与带 TTL 的执行期 `SearchSnapshot` 使用不同类型、存储和 API。只保存必要的短 quote 与 hash，完整正文仍从本地 canonical source 解析；长期 basket relation 可旁路新增轻量表，旧客户端忽略。

**系统与合规影响：** IPC 增加 evidence-basket CRUD/verify/export；数据库采用旁路 additive 表并纳入备份，设置提供 quote 长度和保留策略，文件格式为带 schemaVersion 的 JSON/Markdown。默认离线，不发送正文；导出前提示其包含研究摘录，沿用项目许可证且不引入第三方依赖。

**新版验收与回退（D06-NF-05-A）：** 同一 `ResearchEvidenceSnapshot` 在内容未变时证据集合稳定；查询 TTL 到期不删除长期证据篮，内容变化时不静默替换旧证据；界面不得把证据篮描述为完整历史结果集。删除研究证据快照不删原文或研究笔记。若新增表，按备份、事务、回滚执行，旧客户端忽略新表仍可读取原库。

### 9.6 D06-NF-06 异本、同文与平行段落发现

**用户问题：** 古籍用户需要找同一句在不同版本中的异文，论文用户需要找重复段落、引用复用和不同版本稿件。

**优先级、成本、风险与前置：** P3，高成本。风险是假相似、长任务资源占用、相似度阈值对古籍与论文偏置；前置任务为阶段 A 的 canonical range/normalizer、阶段 B 的有界候选 cursor、阶段 C 的 scheduler 和模块 05 的对读投影。

**MVP：** 用户从一段文字发起“查找平行段落”，先用现有 normalized ngram/FTS 生成候选，再做本地字符级相似度精排；结果按 stable locator 并排展示差异，自动结果只作候选。

**实现影响：** 复用 canonical source slices、query worker 和模块 05 对读投影。第一版采用现有算法和小范围候选，不引入向量模型。大任务持久化、可取消，结果记录 source versions。

**系统与合规影响：** IPC 增加 compare job、结果 cursor 和 cancel；数据库只保存可清理的派生 job/result 与 source version，设置提供阈值、范围和并发，导出为带 locator 的 JSON/Markdown 对照。第一版完全离线、无新依赖；若后续引入 embedding、重排模型或向量库，必须评估许可证、包体、隐私和回退并在实施前获得用户确认。

**新版验收与回退（D06-NF-06-A）：** 原句、增删字、繁简和 OCR 噪声样本分别测 precision/recall，并分别报告古籍/论文指标；不会修改原文；关闭后退回普通全文检索。

### 9.7 D06-NF-07 人名、地名、时间和主题检索视图

**用户问题：** 研究者经常不是找一个固定词，而是追踪人物别名、地名沿革、年代和主题共现。

**优先级、成本、风险与前置：** P3，高成本。风险是同名实体误合并、古今地名/纪年解析错误和自动候选被当成事实；前置任务为 D06-NF-01 query AST、项目词表/研究项目合同以及模块 10 的引用与研究写作数据边界。

**MVP：** 用户从已确认的搜索命中创建实体词表，维护别名、时代和说明；查询时把实体展开为可审阅 terms，并在结果上生成共现表和时间/文献分布。所有实体建议先进入候选，人工确认后才成为项目词表。

**实现影响：** 第一版消费模块 07 唯一 `ResearchEntity` 台账投影出的 versioned project glossary，并复用 query AST；模块 06 不再创建第二套 entity/alias 表，也不自动运行云端 NER。若需要新的本地 NER 模型、知识库或外部实体服务，必须评估隐私、许可证、包体和维护成本，并 **实施前需用户确认**。

**系统与合规影响：** 模块 07 提供实体/别名 CRUD 和候选确认，模块 06 只提供 query expansion preview 与搜索投影；设置保存展开策略，词表导入导出使用版本化 JSON/CSV。第一版本地离线，不自动上传文本；任何 NER 模型、知识库或外部服务实施前必须完成许可证、隐私、体积和回退评估并获得用户确认。

**新版验收与回退（D06-NF-07-A）：** 别名展开完全可见、可逐项关闭；实体候选不改文献 metadata；删除词表不影响普通检索。古籍纪年和现代年份分别使用明确解析规则，并用同名人物/地名反例验证不会自动合并。

## 10. 依赖、迁移与审批

- 阶段 A 至 D 可使用现有 Electron、TypeScript、OpenCC、SQLite FTS5、better-sqlite3、worker_threads、page payload store 和统一任务规划完成，不新增第三方依赖。
- normalizer/index version 升级只重建派生索引，不迁移用户正文。必须先在 staging 生成、校验 count/hash/offset 后原子激活；失败继续使用旧 generation。
- 第一阶段可继续把 index version 编码在 `search_index_status.source_hash`，只提供 staging 提交前的原子安全。任何激活后回滚、双代并存和延迟清理都必须先旁路新增 generation-aware 存储（如 `search_index_generations` 与 generation segment 关系），旧 status 仅投影 active 状态。
- `task_jobs/task_items` 当前尚未实现；搜索持久任务必须等待并复用模块 02/03 的统一 scheduler，注册 `search-index` kind 和上述去重/lease/写预算合同，不得另建第二套 claim/lease 物理队列。
- `librarySearchGeneration` 可先放兼容 settings/metadata 记录；若事务一致性需要独立单行表，属于收益明确的 additive migration，必须自动备份、幂等建表、事务 bump 和回滚。
- `ResearchAggregateArtifact` 是模块 07 正式统计 provenance 的 P1 必需结构，模块 06 拥有创建/校验合同；使用旁路 immutable artifact/payload ref 与引用计数，旧客户端忽略，不把会过期的 SearchSnapshot 或可清理 facet cache 当长期真相。
- 现有 `search_ngram_index` 可作为 1/2-gram sidecar 候选。启用前必须用古籍和论文真实分布评估数据库增量、构建时间、查询 p95 和维护清理冲突；收益不明显时保留 worker 分块 scan。
- saved search JSON additive 增加 schemaVersion/query AST/generation；旧 JSON 容错解析并惰性升级，不批量重写全部记录。
- stable locator 新合同与现有 `SearchHitLocator` 双写至少一个公开版本；只有 exact locator 可投影旧字符字段，page/document precision 走 pageIndex 并省略 optional legacy locator。
- 外部 Elasticsearch/OpenSearch/Meilisearch、向量数据库、云检索、embedding、reranker、NER 或新异体字库均不是基本功能前提。任何引入都必须单独评估许可证、Windows 打包、资源、隐私、离线能力、迁移和回退，并标记 **实施前需用户确认**。
- 索引、缓存和临时导出均可重建或清理，但 active source、人工校对、译文、研究摘录和引用不得因索引维护被删除。

## 11. 与其他模块的约束

- OCR 模块只在 active artifact 或 proof revision 成功提交后发出搜索可见事件；staging、失败和未授权内容不得进入索引。
- 导入模块完成入库后持久投递索引任务，不等待全库索引才允许用户浏览；任务量无限但 claim 和并发有界。
- 阅读器模块必须消费 shared `StableReaderLocator` 及其搜索扩展和同一 normalizer；不能自行用首框、首词或虚拟页号猜测精确命中。
- 文库组织模块的 folder/tag/收藏/阅读状态/lastOpened 变化必须 bump library search generation；大范围 scope 通过 query relation，不传全量对象。
- AI 模块保存 query plan、执行期 snapshot、coverage 和 evidence versions；正式统计先引用模块 06 的持久 `ResearchAggregateArtifact`，不得把 TTL snapshot、partial/truncated/unresolved 结果包装成完整研究结论。
- 翻译模块只在 ready、非 stale unit 激活后更新索引，并保留 translation unit 到原文 source range 的映射。
- 引用、导出和研究写作模块只能消费已验证 evidence；无法解析的 hit 显式跳过并给原因，不退到错误首段。
- 数据库模块备份 active/旧 index generation、saved search、task lease 和外置 payload；索引可重建，但重建过程不得长事务阻塞页面保存。
- UI/交互模块统一搜索状态、分页、筛选、键盘、空/错/取消/截断显示；保持密集、可扫描的研究工作台，不把结果改成营销式卡片页面。
- 性能与发布模块使用本章新版验收，不以旧源码断言代替行为测试。业务实现完成后必须先交用户本地测试；用户明确确认无问题并批准公开前，不得 push、创建公开 PR、触发 GitHub Actions 或发布 Release。

## 12. 第五步 canonical 正文接入结果（2026-07-11）

- 搜索命中回填页正文已改由 `CanonicalContentProvider` 解析，不再自行选择 `proofed_text/ocr_text`；已确认校对、active OCR 和旧投影的优先级与阅读器一致。
- 当前索引表和搜索 generation 尚未迁移，旧索引仍可包含历史投影；本步保证命中展示/摘录回填使用当前 canonical 正文，但不能宣称索引代际、精确 locator 或原子重建已经完成。
- 后续第六步先建立 StableReaderLocator，第七步再建设 SearchGeneration/Snapshot/Resolver，并以 canonical source hash 检测旧命中是否 stale。

## 13. 第六步检索定位接入结果（2026-07-11）

- `SearchHit` 和扁平 `SearchResult` additive 双写 `stableLocator`，旧 `SearchHitLocator` 至少保留一个兼容版本。
- main 仅在非译文命中可由当前 canonical 页面验证 quote/range 时生成 exact v2；上下文读取使用最多 400 页、2 秒 TTL 的有界缓存，来源变化后仍由 source hash 检测。
- 旧扁平结果、译文来源或缺少 version/hash 的命中只能生成 page/document precision；renderer 不再把零范围传给阅读器冒充 exact。
- 搜索摘录保存 v2 locator 和旧 locator compatibility metadata；普通旧摘录继续读取。

SearchGeneration、execution-time SearchSnapshot、SearchEvidenceResolver、stale/relocated 验证输出和 translation unit 精确定位仍属于第七步。

## 14. 第七步 generation、snapshot 与 evidence resolver 结果（2026-07-12）

- additive 新增 `search_generation_state` 单行状态；文献、页面、标签/文件夹关系和 index status 的搜索可见写入通过数据库触发器保守 bump。旧版本忽略该表，不回填或重写正文/索引。
- `SearchSnapshotManager` 最多保留 128 个内存元数据，默认 TTL 60 秒、上限 10 分钟，不持有 SQLite 长事务；criteria、TTL 或 generation 任一变化都 fail closed。
- `querySearchV2` additive 返回 snapshot ID、library generation、vector hash 和 expiresAt；同条件分页可复用，查询前后双重验证防止执行中 generation 改变后拼接两代结果。response cache key 包含 generation。
- `SearchEvidenceResolver` 只从 canonical content + StableReaderLocator 解析，输出 exact/relocated/unresolved 与 verified/stale/source-missing/legacy-unverified/migration-pending；exact 无法验证时不退到首段。
- IPC/preload 新增 `validateSearchSnapshot` 与 `resolveSearchEvidence`；旧查询字段和旧 renderer 继续兼容。

本步没有实现查询 worker、稳定 cursor、百万命中流式导出、translation unit resolver 或长期 `ResearchAggregateArtifact`；SearchSnapshot 到期即丢弃，不能被报告当成持久证据。

## 15. 第八步 B 持久研究统计结果（2026-07-12）

- `querySearchV2` 在 main 内为 snapshot 登记 totals、status、warnings、exactness 和 coverage；renderer 不能提交或覆盖统计 payload。
- active 且 complete 的 snapshot 可提升为 immutable `ResearchAggregateArtifact`，冻结 criteria hash、library/index generation、result hash、exactness 与 coverage；相同身份幂等复用。
- artifact 与专题通过独立 relation 关联，列表最多 200 条并使用 cursor。generation 变化返回 stale-generation，结果 hash 不一致返回 corrupt；历史行不被静默改写。
- 只有 exhaustive complete 统计标为 exact；preview 即使有 totals 也保持 bounded-preview。正式研究输出只接受同专题、verified、exact artifact，草稿可记录省略 coverage。
