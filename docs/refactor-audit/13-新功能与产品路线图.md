# 13 新功能与产品路线图

## 1. 本章结论

前述模块已经提出 70 项以上新功能方向，其中不少是同一能力在不同页面的投影：模块 01、08、09、11 和 12 都提出健康/恢复入口；模块 02、03、04、07、09 都提出任务、操作中心或收件箱；模块 05、06、07、08、10 都提出证据查看、对读或研究复核。如果按原标题逐项实现，会形成多套任务中心、多份 evidence、本地状态和相似页面。

本章把这些建议收敛为 13 个产品能力。优先级不是“最吸引人的界面先做”，而是先完成凭据、备份、统一任务、canonical content、stable locator、搜索快照、证据 lineage、文件 capability 和原子产物等可信底座，再开放建立在它们之上的工作台。古籍/扫描史料和现代 PDF/论文始终使用同一底座；内容 preset 只改变默认策略和呈现，不改变数据真实性、人工保护或隐私门禁。

第一阶段所有 MVP 都能使用现有 Electron、React、TypeScript、Ant Design、SQLite 和 Node 能力完成。任何新模型、字库、字体、向量库、文件 watcher、图形库、云同步、通知、遥测、SaaS 或外部知识服务，都只能作为候选，实施前单独提交用户确认。

## 2. 输入来源与去重原则

路线图输入包括：

- 架构层的工作模式、健康中心、脱敏诊断和能力降级（`01-产品与架构基线.md:337` 至 `:357`）；
- 导入任务、干运行、来源谱系、文件夹配置和监视收件箱（`02-导入与数据入库.md:425` 至 `:445`）；
- OCR 异常、版本、配方、路由、基准、离线和运行检查器（`03-OCR识别与校对数据.md:501` 至 `:559`）；
- 智能整理、智能集合、标签别名、外部目录同步和批量规则（`04-文库组织与文件夹标签.md:378` 至 `:428`）；
- 同步阅读、目录版本、阅读轨迹、异本对读、问题书签、质量热区和批注包（`05-阅读器与版式还原.md:615` 至 `:685`）；
- 高级检索、分面、OCR 感知召回、保存检索监测、证据快照、平行段落和实体检索（`06-全文检索与全库检索.md:588` 至 `:686`）；
- 论点矩阵、研究笔记本、结构化抽取、实体台账、综述矩阵、逐句审计、预算、研究配方和证据收件箱（`07-AI对话与AI研究.md:1074` 至 `:1200`）；
- 工作区 preset、可恢复首页、AI 面板、证据抽屉、多视图、能力中心和快捷工作区（`08-UI视觉系统.md:529` 至 `:585`）；
- 命名工作区、命令中心、可恢复操作、批量影响预览、键盘移动、研究导航和双工作面（`09-交互与工作区.md:484` 至 `:568`）；
- 翻译 QA、引用规范实验室、版本化写作、研究交换包和双语平行语料（`10-翻译引用导出与研究写作.md:603` 至 `:653`）；
- 数据恢复、恢复预演、备份演练和完整性地图（`11-数据库备份安全与兼容性.md:355` 至 `:371`）。
- 合成研究库、Release Candidate 检查器和本地性能趋势（`12-性能稳定性测试与开源发布.md:354` 至 `:372`）。

去重规则：

1. 同一业务状态只有一个 owner；不同页面只能消费投影，不能复制表或状态机。
2. “任务中心”是统一 scheduler 的视图，不为导入、OCR、AI、索引、翻译和备份分别建立队列真相。
3. “证据篮、证据收件箱、问题书签、证据抽屉”共享唯一 `ResearchEvidence` 身份；项目备注和 UI 状态是关系或投影。
4. 健康中心只读各领域的有界 snapshot；打开页面不得触发全库扫描或维护写入。
5. 工作模式、主题、对比度、密度、阅读字体、OCR 配方和隐私策略是正交设置，不用一个 preset 隐式覆盖全部配置。
6. 高级自动化默认“建议 -> 预演 -> 确认 -> 可撤销”，不得直接覆盖人工校对、目录、标签、研究记录或正式报告。
7. 翻译 QA、引用规范和写作画布复用 canonical content、StableReaderLocator、ResearchEvidence 和 output lineage，不建立第二套正文或证据身份。
8. 合成 fixture、RC 清单和性能趋势属于本地质量能力，不上传真实文库，也不自动获得发布权限。

## 3. 统一产品能力

### R13-EP-01 可信任务与恢复中心

**合并来源：** 导入任务中心、OCR 异常队列、索引/AI/翻译 job、系统健康中心、数据恢复中心、可恢复操作中心和能力降级提示。

**MVP：** 一个本地工作中心按任务、健康和恢复三视图展示 `TaskStateEnvelope`、领域 phase、速度、已提交进度、失败项、blockedReason、恢复动作、最近成功时间和 snapshot 版本；独立的操作回执列表展示 operationId、commitState、completionKind、affectedCount、undoUntil 和后端 recoveryAction。任务/回执总量不设上限，列表 cursor 化；toast 只提示，不作为任务或撤销真相。

**前置与数据：** 必须先完成唯一 scheduler、闭合 TaskStatus、lease/cursor/idempotency、CredentialVault、backup manifest v2 和领域 health snapshot。第一阶段复用 `task_jobs/task_items` 与现有 settings/健康投影，不为 UI 建第二套历史表。

**验收与回退：** 导入、OCR、索引、AI、翻译、备份各跑一个可暂停任务，重启后状态和 committed cursor 一致；关闭中心不停止任务，各原页面仍能查看领域状态。中心失败不能阻塞阅读。

### R13-EP-02 导入预演与来源谱系

**合并来源：** 导入前清单、重复审查、文件夹级配置、监视收件箱和外部资料库增量同步。

**MVP：** 用户选择文件/目录后流式看到格式、大小、重复、待转换项、缺失资源、预计 OCR 页数、磁盘空间和目标策略；确认后创建冻结配置的 job。保存 source fingerprint、首次来源、补回来源和 taskId。外部目录第一版只支持用户主动重新扫描。

**前置与数据：** 依赖模块 02 的 staging、fingerprint、幂等导入和有界目录扫描。MOBI/AZW/AZW3 只能进入明确转换提示，不能伪装成直接支持。来源字段 additive 保存并兼容旧文献。

**验收与回退：** 10 万文件可边扫描边预览，取消不复制文件；同内容多路径只生成一篇文献和多条来源候选；关闭预演可走当前导入入口。实时 watcher 属于后续候选，实施前需用户确认。

### R13-EP-03 OCR 质量、版本与实验工作台

**合并来源：** OCR 异常队列、版本对比/回滚、可复现配方、自适应路由、基准实验室、离线模式、运行检查器和阅读器质量热区。

**MVP：** 以 immutable OCR artifact 为核心，分页显示异常页和质量热区；支持旧 OCR/新 OCR/人工校对三方比较、逐块接受、按页切换 active、命名配方预演和 run provenance。引擎路由只给本地可解释建议，默认由用户确认。

**前置与数据：** 必须先完成模块 03 的 canonical page、坐标基准、artifact/proof 优先级和持久任务；run 保存展开后的配置 snapshot。第一版不引入新 OCR 模型、diff 包或外部字库。

**验收与回退：** 回滚只切 active 指针，历史和人工校对不删除；古籍竖排、表格、双栏论文分别有固定金标；离线模式网络外发为零。关闭工作台不改变现有 OCR 结果。

### R13-EP-04 多形态阅读、对读与研究轨迹

**合并来源：** 同步阅读、目录版本、阅读轨迹、异本/修订对读、问题书签和工作区布局记忆。

**MVP：** 最多并排两种阅读投影，通过 `StableReaderLocator` 同步；支持有限容量的后退/前进轨迹、目录候选比较和带状态的问题书签。异本/修订对读先由用户选择两篇文献并生成可审阅对齐候选。

**前置与数据：** 依赖 canonical content、projection mapping、stable locator、目录 active/candidate 保护和有界页面窗口。布局先存 typed settings；长期轨迹或问题状态只在现有结构无法表达时 additive 建旁路表。

**验收与回退：** 古籍原图/校对、论文 PDF/重排正文和正文/译文均能同步；映射不确定时明确降级，不猜页号；关闭并排视图回到现有单视图，不改阅读进度或正文。

### R13-EP-05 高级检索、分面与监测

**合并来源：** 可读 query AST、结果分面、OCR/异体字扩展召回、保存检索监测、智能集合和实体词表投影。

**MVP：** 普通输入保持不变，高级模式提供必须/任一/排除/短语/邻近/字段条件；结果分面绑定同一 SearchSnapshot，并明确 exact/estimated；保存查询可成为只读智能集合。扩展召回默认关闭，候选展示原因且不能自动进入正式证据。

**前置与数据：** 依赖模块 06 的统一 normalizer、query worker、cursor、generation、SearchSnapshot、exactness 和 resolver。保存 AST 版本化，不保存拼接 SQL；实体只消费模块 07 的唯一 ResearchEntity 词表。

**验收与回退：** 简单检索召回不退化；旧保存检索惰性包装；换查询后旧分面/监测结果不能覆盖新页面；关闭高级模式、分面或监测不影响基本检索。

### R13-EP-06 平行段落、异本与实体研究

**合并来源：** 平行段落发现、异本对读、标签别名、人物/地点/时间台账和共现视图。

**MVP：** 用户从一段或已确认实体发起本地候选搜索，用现有 ngram/FTS 和字符 diff 排序；实体维护规范名、别名、时期、说明和 confirmed evidence。所有相似/别名关系先作为候选。

**前置与数据：** `ResearchEntity` 由研究域唯一拥有；标签 alias 与研究实体不能混成一张表。检索只消费版本化词表投影，阅读器消费对齐 artifact。第一版不需要 embedding、NER、地图或外部知识库。

**验收与回退：** 同名不同人/地不自动合并；古籍异体和论文修订分别报告指标；删除候选/实体/对齐不删原文。任何向量模型、NER 或知识服务实施前需用户确认。

### R13-EP-07 证据收件箱与问题驱动研究

**合并来源：** 证据篮、跨专题证据收件箱、阅读问题书签、证据检查抽屉、OCR/检索摘录入口。

**MVP：** 未归入专题的 canonical evidence 进入收件箱；同一 evidence 可关联多个项目，每个项目保存独立 comment/tags/outline/review。详情抽屉显示 locator、source hash、precision/resolution/verificationStatus、coverage 和回跳。

**前置与数据：** 依赖唯一 `ResearchEvidence`、stable locator、resolver 和 project annotation relation。不能复制 excerpt 文本形成多个身份；列表 cursor 化，source mutation 统一标 stale。

**验收与回退：** A 项目改备注不影响 B；解除关系不删 evidence；证据篮快照不冒充当时完整结果集；关闭收件箱/抽屉后旧摘录和导出仍可用。

### R13-EP-08 结构化研究、论点矩阵与可信报告

**合并来源：** 结构化 Schema、论点—证据—反证、综述矩阵、逐句证据审计、研究笔记本和可审阅研究协议。

**MVP：** 用户定义白名单字段和校验规则，抽取结果进入 pending review；confirmed evidence/record 可组成论点矩阵和综述矩阵；正式报告使用 immutable output、input coverage 和 claim manifest。运行页可比较 scope、模型、证据和输出差异。

**前置与数据：** 必须先完成 CredentialVault、operation preview、AI scheduler、canonical evidence、record version/review、aggregate artifact 和 output lineage。recipe 只允许白名单步骤，不能执行 JavaScript/SQL 或跳过人工 gate。

**验收与回退：** source stale 后论点、记录和报告句同步失效；空单元格区分未检索/无证/待确认；删除矩阵、recipe 或 run 不删除 evidence、dataset 或历史 output。第一版无 agent framework。

### R13-EP-09 文库整理与可撤销自动化

**合并来源：** 智能整理收件箱、保存筛选、受控标签合并、外部目录同步、批量范围/影响预览、键盘移动助手和批量整理规则。

**MVP：** 分页展示未分类、重复候选、缺失 metadata、标签别名和 AI 分类建议；`SelectionDescriptor` 明确 explicit/all-matching、scope snapshot、exclusions 和 exact/estimated 总数，所有移动/删除/合并先显示后端影响预览。键盘“移动到”与拖放调用同一 command；规则只使用版本化白名单 AST，再生成可撤销组织 job。人工移动、改名、标签和删除优先。

**前置与数据：** 依赖文件夹无环、标签读取纯化、有界集合查询、统一 scheduler 和后端 operation preview/undo。规则第一版存 typed settings；需要共享/历史时再审批旁路表。

**验收与回退：** 重复执行幂等；撤销不覆盖批次后的人工修改；关闭自动化不删除已确认组织关系。不得执行任意脚本或静默自动合并。

### R13-EP-10 个性化工作区与无障碍外壳

**合并来源：** 内容 preset、显示 preset、命名工作区/last-known-good、可恢复欢迎页、命令面板、快捷键冲突中心、可定制快捷区、多视图、AI 面板停靠和能力降级呈现。

**MVP：** 内容 preset、色彩方案、对比度、密度、阅读字体和隐私策略正交；用户可命名/复制本地工作区并回到 last-known-good，工作区只保存轻量 descriptor；统一命令面板展示作用域、快捷键冲突和恢复默认。首页展示最近工作和任务摘要；文库/研究/摘录支持网格/列表/表格；AI 面板支持停靠、重置、Pointer 和键盘操作。

**前置与数据：** 依赖单一 ThemeDefinition、typed settings、WorkspaceSnapshot、Action/Overlay primitives 和模块 09 的命令/focus/undo 合同。UI 不拥有业务状态或数据库真相。

**验收与回退：** 古籍和论文 fixture 在各组合完成功能等价流程；200% zoom、forced-colors、reduced motion 和纯键盘通过；清除新设置回到当前默认，不迁移用户内容。

### R13-EP-11 本地交换、导出与研究交付

**合并来源：** 本地批注包、证据/矩阵导出、研究输出、引用与可复现诊断包。

**MVP：** 使用版本化 schema 导出目录候选、校对意见、stable locators、摘录、问题书签、证据/矩阵和报告 manifest；资源使用相对路径和 SHA-256，manifest 记录许可证、缺失资源与生成版本，用户明确选择“仅清单”或“包含资源”并看到隐私/体积预览。导入先验证文献指纹、schema、冲突和影响，默认不覆盖人工内容。

**前置与数据：** 依赖模块 10 的 canonical export snapshot、引用 resolver、原子文件写入和模块 11 的完整性/恢复规范。诊断包与研究交换包分开，前者必须脱敏且不含正文、Key、真实路径。

**验收与回退：** 重复导入幂等；不匹配文献进入待绑定；失败事务回滚；删除交换记录不删用户数据。实时协作、账号或云同步实施前需用户确认。

### R13-EP-12 隐私、成本与可复现运行治理

**合并来源：** 离线模式、能力中心、运行检查器、诊断包、AI 成本/隐私预算、OCR 基准、合成研究库、RC 检查器、本地性能趋势和定期恢复演练。

**MVP：** 本地展示每次 OCR/AI/维护 run 的配置 snapshot、provider/model、外传类别、调用量、估算来源、阶段耗时、错误和恢复动作；用户可设置离线、每任务预算和超限暂停。固定 seed 的古籍/论文合成库驱动截图与性能门禁，RC 检查器离线汇总 commit、验收、许可证、产物 hash 和签名状态，但不上传或公开。定期演练只读验证最新备份。

**前置与数据：** usage/provenance 是 job artifact，不含 secret/正文；CredentialVault 只暴露 public state；价格默认用户配置或 provider 返回，不自动访问计费 API。公开截图和测试只消费许可清晰的合成 fixture；RC manifest 只记录脱敏指标与 hash，不具备发布副作用。

**验收与回退：** 达到预算后不发新请求；离线模式抓包零外发；诊断包、截图和 RC manifest 通过 secret/路径/正文扫描；关闭历史保留仍保存正式 output 的最小 lineage。任何 billing API、遥测、外部诊断或云趋势服务需用户确认。

### R13-EP-13 翻译、引用与写作质量工程

**合并来源：** 翻译术语一致性、人工译文保护、引用规范一致性、版本化研究写作、逐论点证据审计和双语平行语料。

**MVP：** 以 canonical source/version 和 StableReaderLocator 建立翻译 QA 清单，显示术语命中、保护符、旧译/人工译/候选差异和 coverage；双语平行语料把句/块 alignment 作为候选，必须人工确认，并可导出带 locator/hash 的版本化 JSON/TSV（TMX-like 仅在另行确认格式/依赖后提供）。引用实验室用古籍与论文合成 fixture 校验 required fields、格式版本和 diagnostics；写作画布只编辑 parent-linked output revision，每条 claim 回指冻结的 evidence/citation snapshot。

**前置与数据：** 依赖模块 10 的 `TranslationContextSnapshot`、统一 `CitationResolver`、`ExportSnapshot/AtomicExportWriter`，以及模块 07 的 evidence/claim/output lineage。旧翻译、引用模板和研究输出只读兼容并标 legacy/unverified；第一版不引入 CSL 引擎、TeX 发行版、翻译模型或同步服务。

**验收与回退：** provider 迟到结果不能覆盖人工译文；缺字段引用不能伪装 verified；正文、样式或证据变化后关联产物标 stale 且历史仍可回读；关闭工作台后原译文、模板、摘录和导出入口继续可用。任何新引文库、字体、模型或服务需逐项确认。

## 4. 优先级与发布波次

| 波次 | 目标 | 允许进入的能力 | 退出条件 |
| --- | --- | --- | --- |
| Gate 0 | 数据、安全和正确性止血 | 不新增用户功能；修复 P0/P1、CredentialVault、备份恢复、canonical content、任务/证据合同 | 所有发布阻断验收通过，旧库备份/恢复演练成功 |
| Wave 1 | 稳定核心工作流 | EP-01、EP-02、EP-03 的异常/版本基础、EP-10 的无障碍外壳 | 导入/OCR/阅读/搜索在大库下可恢复且资源有界 |
| Wave 2 | 研究效率 | EP-04、EP-05、EP-07、EP-09、EP-11、EP-13 的本地基础 | stable locator/evidence/translation/citation/export 全链路通过，双用户本地验收 |
| Wave 3 | 可信研究增强 | EP-06、EP-08、EP-12、EP-13 的质量矩阵与治理能力 | 人工 gate、lineage、coverage、RC 证据和回退完整 |
| Wave 4 | 可选扩展 | watcher、diff/NER/embedding、地图/知识库、云协作、通知、SaaS | 每项独立审批、依赖/隐私/许可证/离线/卸载方案获用户确认 |

同一波次不表示同时修改所有热点。实现仍拆成小切片，每个切片先更新对应成品验收，再做业务实现、本地测试和回退验证。

## 5. 依赖与实施顺序

```text
CredentialVault + backup safety + typed settings
  -> TaskStateEnvelope + single scheduler + operation preview/undo
  -> canonical content + immutable artifacts + StableReaderLocator
  -> SearchSnapshot/resolver + ResearchEvidence/aggregate/output lineage
  -> UI/interaction primitives + bounded page/workspace projections
  -> product epics and optional integrations
```

任何上层功能不得为了提前展示而复制下层合同。例如，证据抽屉不能先保存 renderer 自报 hash；研究矩阵不能绕过 record review；欢迎页任务卡不能建立第二份 task 状态；健康中心不能在打开时同步扫描全库。

## 7. 迁移、依赖与审批

- Gate 0 中已证明必要的 CredentialVault、统一 scheduler、artifact/version/manifest 和备份完整性迁移由模块 14 统一排序；不能由各 epic 重复建表。
- settings 型 MVP 使用模块 01 的 SettingDefinition、原子 typed patch 和版本化 JSON；未知键由旧版本忽略，缺失键沿用当前行为。
- 任何长期旁路表先写 owner、唯一键、外键、备份范围、清理/保留、旧版兼容和降级写入保护；大型旧库使用 cursor 小批，不按规模永久跳过。
- 第一版不新增运行时依赖。可选依赖必须先获得用户对该具体候选和说明范围的确认，不能用一次批准推导出其他模型、服务或库也获授权。
- 公开模板、词典、fixture、图标、字体、模型或二进制资源必须记录来源、版本、许可证、NOTICE、更新和移除方式。

## 8. 本地验收与公开纪律

每个 Wave 完成后先在本地分支运行对应合同、集成、UI、性能、build、smoke 和 Windows unpack/安装包门禁。向用户提供功能清单、验收编号、已知限制、数据库预检、备份位置和回退步骤，并同时使用古籍/扫描史料与普通 PDF/论文测试。

用户未明确确认“本地测试无问题，并批准公开”时，只允许继续本地修改和本地提交；不得 push、创建公开 PR、触发 GitHub Actions、tag 或 Release。路线图排期本身不构成对任何迁移、依赖、模型或外部服务的实施批准。
