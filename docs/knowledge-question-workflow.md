# 直接向文献提问

“知识图谱”默认打开“向文献提问”。标题右侧固定显示“向文献提问 / 资料浏览 / 专题研究”，
三个入口共用标题栏，不随各页操作按钮数量变化而移动。
标题下只有一套专题与选读范围控件，提问和实体提取复用所选范围。资料浏览按当前专题
显示已生成的数据集；专题研究管理该专题的全部证据与写作内容，不将问答的选读子集误作
整个专题。切换专题期间或回答进行中禁止修改共享范围。
提问不要求先建专题或理解字段映射。

1. 点“选择文献”，仍可按文献类型、标签、文件夹筛选和多选。
2. 输入问题，确认当前模型后点击“查找并回答”。选择本身不会调用模型。
3. 页面直接显示回答、原文依据和服务返回的核验提醒。点击引用或“看原文”可回查；
   未选专题时“收藏证据”保存到已有摘录功能；选了专题则“存入专题”直接保存到该专题，
   保留原文、页码、定位和待核验状态。“保存回答”同时保存完整回答及返回的原文依据，
   不额外调用模型。保存后的入口可直接跳转到专题证据。

继续输入问题会携带当前对话上下文。点加号“新问题”开始独立对话，保留文献范围。
重新选择文献会开始新的对话范围，不混入此前对话上下文。历史保存在现有 AI 对话表，
可从“研究历史”重新打开；恢复历史不会重新调用模型。输入草稿及当前选择保存在本机。

问答期间显示真实阶段和用时，不虚构百分比。失败后错误保留，输入不清空，先前保存的
回答仍可从历史恢复。运行时禁止重复提交、修改文献范围或从此页切换模型。
模型调用按服务商计费；目前没有可靠的调用前金额估算，不显示伪造的费用数字。

此入口复用现有带出处的检索问答，不是新增的逐章全文建库。相关片段不足或部分文献
无可用文本时不能将回答视为全库结论。全文逐章检查点、自动实体消歧、自动按问题构图
尚未完成，不应因为入口变简单就宣称这些能力已具备。

“资料浏览”保留材料核验、专题保存、关系图、表格、分析记录及字段设置。
切到提问页后不反复加载浏览数据集。切换入口不会清除回答、草稿或已有材料。

原侧栏“研究”已合并到“专题研究”，保留专题文献、证据摘录、大纲、研究结果和写作导出。
移除嵌入页的重复专题选择、统计概览和说明卡片，默认直接显示证据。研究结果直接列出
回答与报告，支持标题搜索、分页、按需读取全文；结构化资料通过同一工作区查看。
大纲页直接显示论证材料，可回查原文、修改所属大纲；选择大纲后只显示归入该节点的证据。
新保存的证据和报告会刷新对应列表，不必重新打开整个工作区。
每个专题分别保留提问草稿、选读范围和对话，原未归类的问答继续使用旧存储键。
选择文献时可勾选“将所选文献加入当前专题”；只添加成员关系，不删除原有成员或原文。
专题研究与资料浏览共享专题选择；既有专题、笔记和结果仍使用原数据库，不需要重新分析。
旧工作区中的研究标签仍可恢复，打开后进入知识图谱的专题研究页。自定义标签名称不变。
专题研究仅在首次打开时加载，切换后保留当前页面状态。

## 证据排序与阅读预算

问答先从用户选定范围做关键词检索；该范围存在当前模型的向量索引时，再发送一次问题向量请求，
合并两路候选。不逐篇发送向量请求，不自动重新向量化，也不要求旧文献先完成向量化。
检索规划同时考虑问题中的研究方面（如史料来源、方法、材料偏见），不只寻找人名、地名。
这些研究问题还会本地补充少量短检索词（如档案、访谈），避免规划只给出“口述访谈”等复合词而漏掉
“深度访谈”。排序对原文中匹配所问方面的片段加权，并兼顾尚未覆盖的方面，不增加聊天重排请求。
这属于研究场景的启发式排序，不替代语义判断，也不保证任意表述下的完整召回。
小范围选读最多提供 12 篇的题名辅助规划，不发送全文；更大范围只提供数量，不以任意前几篇代表全库。
混合检索使用倒数排名融合（RRF），不直接相加全文分数与余弦相似度。
候选阶段有界，最终按检索排名、文字可读性、出处定位信息、文献多样性及文本冗余选择材料。
这些分数不是历史真实性评分，也不能保证自动找到全部反例。

- 每次回答最多 8 条主出处，证据组内附带前后页上下文，总序列化证据上限 18,000 UTF-8 字节。
  这是确定的文本预算，不是所有模型通用的精确 Token 数；问题、对话历史、指令及输出另占 Token。
- 已在页段中出现的原文不再作为出处正文重复发送；不同证据组不重复附带同一文献的同一页。
  页内截取优先围绕命中位置，而不是总取页首。出处及原页仍完整保存在资料库中。
- 先为各条主出处分配预算，再依次补充命中页和前后页，避免前几个候选的扩展上下文挤掉后续出处。
  同一邻页若已作为另一个证据组的命中页发送，不再重复附带。
- 证据在返回界面前统一选择；界面显示的主出处与模型实际输入一致，不先显示全部再暗中截断。
  超预算的候选可跳过，后续较短候选仍有机会入选；不靠截断最终回答来控制长度。
- 问题向量请求最多等待 15 秒（不含本地扫描耗时）；失败保留关键词证据并显示提醒。
  原有单独向量检索和批量向量化的默认超时不变。
- 全文检索页、入库正文和导出范围不受本次问答预算限制。全面综述仍需逐篇覆盖机制，
  不能把“本次取到 8 条证据”理解为已经分析了全部所选文献。

## 测试

`npm run check:ai-evidence-keyword-first` 包含排序/预算行为测试及隔离 SQLite、模拟向量服务集成测试。
覆盖两路融合、重复候选不加分、相关不同意见保留、长首项不阻塞后项、页尾命中、
主出处与实际输入一致、所选范围隔离、无向量旧文献兼容、一次问题向量请求及服务失败退回关键词。
同时验证主出处优先分配、跨组邻页去重、规划题名范围，以及收到响应头后正文停滞仍能超时退出。
模拟服务不产生费用，不等于真实模型效果或千篇文献完整覆盖验收。

构建后运行 `node scripts/knowledge-question-ui-regression.js`。
隔离配置和虚构 IPC 数据覆盖默认入口、范围确认、阶段显示、重复提交防护、来源分页及
收藏定位、失败输入保留、历史恢复、草稿恢复、专题间数据隔离、完整报告读取、长标签
换行与筛选，以及桌面/窄窗口布局。不调用真实模型。
原工作台回归仍使用 `scripts/research-graph-ui-regression.js` 及 `--large` / `--topic`。
