# 文献库文件夹树形菜单设计

## 背景

文献库文献卡片的“加入文件夹”菜单目前直接遍历全部可用文件夹，只显示名称，没有读取 `parent_id`。因此子文件夹会被展平为普通同级项目；当文件夹数量较多时，菜单还会持续向下增长并超出应用窗口，后面的文件夹无法操作。

## 目标

- “加入文件夹”按真实的父文件夹、子文件夹层级展示。
- 父文件夹本身仍可作为加入目标，不因具有子文件夹而失去选择能力。
- 每一级文件夹子菜单受到视口高度约束，内容过多时可以独立上下滚动。
- 长文件夹名称不撑坏菜单宽度，同时保留查看完整名称的方式。
- 保持现有 `folder_<id>` 点击协议，不影响单篇、批量、右键菜单、更多菜单和项目隔离。

## 交互设计

“加入文件夹”的第一级子菜单仅显示根文件夹。没有子文件夹的文件夹直接显示为可点击菜单项；有子文件夹的父文件夹显示为可展开菜单项，其子菜单结构为：

1. `加入“父文件夹名”`，用于把文献直接加入该父文件夹；
2. 分隔线；
3. 该父文件夹下的子文件夹，继续按相同规则递归展示。

每一级菜单最大高度使用窗口高度的一部分，并设置合理的绝对上限；超过高度后只滚动当前级菜单，不扩大整个弹层。菜单项名称采用单行省略，原始名称写入 `title`，鼠标悬停时可查看完整文本。

## 实现方案

- 复用 `src/renderer/src/utils/folders.ts` 中的 `buildFolderTree` 构建层级，不另外维护一套父子关系算法。
- 增加一个把 `FolderTreeNode` 转换成 Ant Design `MenuProps['items']` 的纯函数。
- 叶子菜单和父级“直接加入”菜单都继续使用 `folder_<id>`，现有点击处理无需改变。
- 给文献卡片右键菜单与更多菜单统一添加专用弹层类名。
- 在全局样式中只约束该专用菜单及其子菜单弹层，避免影响标签页、表格和其他下拉菜单。

## 边界处理

- 没有文件夹时继续显示禁用项“没有可加入的文件夹”。
- `parent_id` 指向不存在文件夹时，现有树工具会将其作为根节点展示，避免文件夹消失。
- 文件夹层级可以递归展开；菜单数据保持稳定 key，避免点击错位。
- 同名文件夹依靠层级位置区分，不修改数据库中的名称或排序规则。

## 验证计划

- 回归脚本验证根文件夹、子文件夹和多级文件夹被转换为嵌套菜单。
- 验证父文件夹具有“直接加入”入口，且 key 仍为 `folder_<id>`。
- 验证叶子节点 key 保持不变，无文件夹时仍显示禁用占位项。
- 验证专用菜单样式包含最大高度、纵向滚动和长名称省略规则。
- 运行类型检查、文件夹管理回归、完整检查、构建和 `git diff --check`。
