# 大批量检索与摘录导出设计

## 背景

当前“导出命中摘录”在主进程中同步完成检索结果整理、段落还原、引用生成和整份文件拼接。全文导出还存在 `1000` 条硬上限，向量检索与导出也有独立上限，导致界面显示的可选数量与后台实际数量不一致。

需求不是把默认值直接改成一个极大的数字，而是：默认使用 **10,000 条**，用户可以手动输入更高数量，也可以选择 **全部**；选择大数量或全部时必须明确提示风险，并且处理过程不能让软件失去响应。

## 目标与非目标

### 目标

- 全文命中摘录、向量证据导出和批量保存完整段落使用统一的数量语义：正整数或 `全部`。
- 默认数量为 10,000；不再使用业务层面的 1,000/5,000 固定导出上限。
- 结果范围严格继承当前项目、筛选条件、标签和收藏条件，不跨项目读取数据。
- 大批量任务后台分批执行，显示进度、已写入数量、估算大小和当前阶段，并支持取消。
- 采用临时文件 + 原子重命名，取消或失败时不覆盖用户已有文件，也不留下看似完整的半成品。
- 预览只展开少量样本，不能因为选择 10,000 或“全部”而把全部内容塞进渲染器。

### 非目标

- 不改变 OCR、向量化、全文索引和文献库数据本身。
- 不把用户的全部文献无条件导出；“全部”只代表当前检索/筛选范围内的全部命中。
- 不把 GitHub Release、安装包或用户数据库放进源码仓库。

## 设计方案

### 1. 数量模型

新增共享类型：

```ts
type SearchExportCount = number | 'all'
```

- `number`：大于 0 的整数，表示最多写入多少条。
- `'all'`：处理当前检索快照中所有符合条件的命中。
- 默认值：`10_000`。
- 前端不再复用向量检索的旧上限作为全文导出上限。
- 主进程只限制为安全整数；不设置 100,000 的业务硬上限，真正的终止条件由用户数量或结果耗尽决定。

界面提供数字输入和“全部”选项。用户选择数量超过 10,000 或“全部”时显示确认提示，提示 CPU、内存、磁盘空间、处理时间和取消方式；用户未确认时不启动任务。

### 2. 检索快照与分页

- 全文检索继续使用现有搜索快照/分页能力。
- 向量检索新增服务端快照和分页返回，不把 10,000 条甚至全部命中一次性通过 IPC 发送到渲染器。
- 搜索页面只保留当前页及少量上下文；总命中数、当前页、快照 ID 和筛选条件单独保存。
- 导出任务读取快照，而不是依赖当前页面已渲染的数组，避免翻页或 UI 刷新导致导出范围改变。
- 项目 ID 在创建快照和执行任务时都校验，项目切换或快照失效时任务安全失败并给出可理解的提示。

### 3. 后台分批导出任务

新增统一的 `search-export` 任务状态，复用现有任务调度和数据库忙重试机制：

- `queued`：等待执行。
- `running`：按批次读取命中、还原段落、生成引用并写入临时文件。
- `completed`：原子替换目标文件并返回统计。
- `canceling` / `canceled`：停止读取，删除临时文件，保留已存在的目标文件。
- `failed`：记录阶段、已处理数量、错误原因和可重试信息。

每批默认 500 条左右，批次之间让出事件循环；实际批次可以根据单条文本大小动态缩小。任务状态至少包含：`processed`、`matched`、`written`、`skipped`、`bytesWritten`、`totalKnown`、`phase`、`projectId` 和 `outputPath`。

### 4. 流式文件格式

- TXT/Markdown：按批次追加文本块。
- CSV：先写表头，之后逐批追加转义后的行。
- JSON：写入 `[`，逐条追加带逗号的记录，完成时写入 `]`；取消/失败删除临时文件。
- 所有格式均写入同目录临时文件，完成后使用原子重命名，避免用户看到半份文件。
- 引用生成和页面/段落还原在后台批次中完成，不在渲染器中逐条调用 IPC。

### 5. 交互与风险控制

- 导出弹窗显示：数量、当前筛选范围、预估命中数（如果已知）、格式和引用方式。
- 数量为 10,000 以内时可直接启动；超过 10,000 或选择“全部”时必须二次确认。
- 导出过程中弹窗变为非阻塞任务面板，用户可以切换项目、阅读文献或继续检索；项目切换不会改变已创建任务的快照范围。
- 任务面板提供“取消任务”；取消后明确显示已取消，不伪装成导出成功。
- 文件写入失败、磁盘空间不足、项目切换和快照失效都要保留诊断信息，但不能破坏已有文件。

## 数据流

```text
检索条件/项目
      ↓
服务端搜索快照（全文或向量）
      ↓
创建 search-export 任务（数量=整数或 all）
      ↓
批量读取命中 → 段落/向量片段还原 → 引用生成 → 临时文件追加
      ↓                         ↘
进度 IPC/任务面板                 取消/失败：删除临时文件
      ↓
完成：原子重命名 → 返回文件路径和统计
```

## 错误处理与兼容

- 旧调用未传数量时使用 10,000 默认值，保持现有 API 调用兼容。
- 旧的 `maxExportRecords: number` 调用仍接受；新增 `'all'` 后由共享类型和主进程统一解析。
- 任务重启时检查临时文件和任务状态；无法安全恢复的任务标记为失败，不自动覆盖用户文件。
- 搜索结果中无法还原的命中继续计入 `skipped`，但不会让整个任务失败。
- 数据库 busy 使用现有重试策略；超过等待预算则任务失败并显示“数据库忙”，不阻塞前台。

## 测试计划

1. 共享数量解析：默认 10,000、数字输入、`all`、非法值、超大安全整数。
2. UI 回归：全文/向量/批量保存都显示统一数量控件；大于 10,000 和“全部”出现风险确认；预览只读取少量样本。
3. 分页回归：向量快照分页不把全部命中发送到渲染器，项目切换不串项目。
4. 流式导出集成：合成 25,000 条命中，验证 TXT/Markdown/CSV/JSON 内容、顺序、数量和原子落盘。
5. “全部”导出：结果耗尽后正确完成；不存在人为 1,000/5,000 截断。
6. 取消与失败：中途取消删除临时文件且保留旧目标文件；模拟磁盘/数据库错误，状态和提示正确。
7. 保留现有 `npm run check`、开源检查、打包烟测和项目隔离回归。

## 风险与取舍

- “全部”可能产生很大的文件，这是用户明确选择后的行为；二次确认和可取消任务是必要保护。
- 任务快照会占用临时磁盘空间，完成/取消/失败都必须清理。
- 向量全量排序和段落还原成本较高，必须在后台执行，并限制单批内存；不能为了表面上的无限上限恢复同步全量数组。
