# 大规模文献研究方案

日期：2026-09-12。状态：设计方案；已落地首条可运行流程，见 [实现与边界](corpus-research-workflow.md)。本文件不是性能实测报告，全部规划及研究质量验收尚未完成。

本次工作包括官方文档、论文、开源脚本和本项目代码审阅。没有试用商业产品后台，没有新增付费模型调用，也没有修改用户文献。本方案中的参数和质量门槛均须通过试验验证，不能视为已经达到。

## 1. 决策摘要

采用“全范围处理台账 + 按问题累计证据 + 有预算的分层综合”，不把单次问答扩容当作千篇文献研究。

- 全文、校对版本和来源定位长期保留；关键词索引与可选向量索引用于找材料。
- 普通事实提问继续走轻量检索；专题综述使用可恢复的逐篇、逐段处理任务。
- 每次调用限制证据数量和总 Token；整个专题累计的证据不能被限制为 8 条。
- 摘要和知识图谱用于组织、定位和比较材料，不代替原文证据，也不证明已经完整阅读。
- 首次全面处理大量文本确有成本。主要节省来自避免重复分析、减少无关上下文、缓存有效中间结果，而不是承诺首次处理免费或无损压缩。
- 用户仍从“选择文献、输入问题”开始；不要求手工配置分块、检索器、图算法和流水线。

优先建设可核查的文献研究表和覆盖记录，再增强图谱。不能先把图画得复杂，然后倒推它有什么研究用途。

## 3. 先划清三种“覆盖”

| 状态 | 含义 | 不能据此声称 |
| --- | --- | --- |
| 已建立检索索引 | 可用文本进入全文索引或向量索引 | 模型已读过全文 |
| 已按本次问题处理 | 对当前文本版本的全部约定处理单元完成分析，异常已列出 | 所有事实均被识别、结论绝对可靠 |
| 回答引用了材料 | 本段结论实际使用且能追溯的来源 | 未引用的文献都无价值，或所有文献都支持该结论 |

“已处理 1000 篇”必须有逐篇、逐块台账支撑；“基于 8 条证据回答”只能说明该回答的直接依据。

完整研究可以得出部分文献与问题无关，但须保留处理依据。低检索分、无关键词命中、缺少摘要都不能直接变成全文排除决定。

## 4. 用户如何使用

继续在统一工作区内使用：标题右侧的提问、资料浏览、专题研究位置固定，共用同一个专题与文献范围。

1. 用户通过现有分类、标签、文件夹或多选确定文献范围，输入研究问题。
2. 简单事实问题直接检索回答；“比较整批文献的观点、分歧、变化”等任务建议专题研究，并在一次确认中显示范围、预计开销和预算上限。
3. 研究在后台执行；用户先看到标明“阶段结果”的发现，可以继续阅读原文。关闭窗口不应丢失任务。
4. 完成后首先展示有出处的结论、重要分歧与研究缺口；展开即可看到全部文献研究表、证据和处理状态。

自动判断任务类型只作建议，不得未经确认启动千篇规模的付费处理。用户可修正系统理解的研究维度，但不必自行编写流程。

示例问题：“这些材料如何解释近代教育政策的变化，主要分歧在哪里？”

默认输出不是一堆通用指标，而是：

- 主要解释与适用时期，分别有哪些材料支持。
- 互相矛盾的观点、例外地区及需要核验的结论。
- 文献研究表：文献、研究对象、时段地区、主要论点、依据、局限、处理状态。
- 点击任一论点返回原文、文件页和已标记的真实页码；可收藏到摘录或加入大纲。
- 资料浏览保留人物、地点、事件、关系和时间线，但从本专题证据中派生，不另起一套孤立数据。

进度固定显示在任务入口附近，至少包括选中文献数、文本可用数、已处理块数、失败数、当前阶段和用量。处理中、部分完成、完整处理结束、报告失败必须分开。预计时间先用区间，取得足够批次耗时后再更新。

## 5. 后台处理流程

### 5.1 固定范围和版本

创建专题运行快照，记录文献列表、正文版本、研究问题、提取字段、模型与提示词版本。总量从数据库完整获取，不受界面分页或检索 top-k 限制。

正文以现有规范文本和校对版本为基础；按段落、章节、表格边界组织块，保存原始定位。跨页段落允许父级上下文，重叠区域不重复计数。脚注、注释和表格不能静默丢弃；无法解析的部分列入待处理清单。

正文哈希用于识别变化，处理单元保留独立 ID。不能依赖可变页码或文本数组下标作为唯一身份。

### 5.2 轻量准备和任务规划

优先使用已有全文索引、元数据、目录与可用向量。没有向量的文献仍可参加研究；是否新增付费向量须纳入费用说明。

将问题整理成少量研究维度和纳入条件。一个块尽量在一次读取中提取多个维度，避免每个维度都把全文重读一遍。不要为每篇文献各调用一次问题规划模型。

通用摘要和旧实体索引只帮助排序；不能因为有旧摘要就将新问题标为处理完成。

### 5.3 两条执行路径

| 路径 | 材料处理范围 | 完成含义 |
| --- | --- | --- |
| 快速问答 | 全范围混合检索，按问题取有限候选和必要邻近原文 | 完成一次有界检索回答，不承诺全文审查 |
| 全范围专题研究 | 遍历快照内每篇文献的所有可用处理单元；高相关材料优先，但未处理材料仍留在队列 | 全部单元有可核查结果；失败或缺文使结果保持部分完成 |

全范围模式先形成每篇文献的研究记录，再按研究维度综合。没有相关发现也是一种结果，但只能表述为“本次处理未识别到”，不能变成“原文绝不存在”。

允许预算用尽时暂停并交付阶段结果，不允许预算用完就把剩余文献自动标为无关。

### 5.4 持久化证据，不只保存摘要

每条候选主张至少包含：主张文本、原文摘句、文献与处理单元 ID、内容版本、定位、研究维度、支持或反对的对象、说话者或作者归属、模型来源和复核状态。

原文匹配失败的摘句不能进入已核验材料。匹配成功仅证明出处存在，不证明模型解释正确；事实支持关系仍需模型检查和人工抽检。

历史材料特别保留：史料成文时间与叙述事件时间、当事人陈述与作者解释、推测与确定语气、同名异人和异名同人、不确定日期及相互矛盾的记载。

同一史料的转引和多个版本可以复用部分计算，但必须保留各自出处，并避免将重复转引当作多个独立见证。

### 5.5 分层综合和原文回查

处理结果按研究维度、时段、地区及观点分组。各组在限定上下文中生成有来源的中间结论，再形成专题回答。每个中间产物保存完整来源清单和依赖关系；不把全部来源正文重复塞进下一轮提示词。

汇总不得仅按出现频次选择观点。明确给反例、分歧、不同来源家族和不确定材料保留位置。关键结论及被压缩后发生含义变化的陈述，需要回取原文确认。

摘要树适合导航，但不是原文替代品。若最终篇幅容纳不了全部发现，应将详细研究表和分项结论作为可展开结果，而不是宣称短回答已经穷尽所有观点。

计数、比例、去重和时间分布使用数据库及固定快照计算；禁止让模型把多个重叠批次的数量自行相加。

## 6. “8 条”应限制哪里

分别控制五个量，不用一个 top-k 兼任所有上限：

| 预算 | 建议规则 |
| --- | --- |
| 研究范围 | 用户选择的全部文献，无隐藏截断 |
| 候选检索 | 独立的有界候选池，可按子问题继续获取；不等于全文覆盖 |
| 单次证据上下文 | 普通问答可沿用最多 8 条核心证据，并限制序列化后的总 Token；提取批次另按文本 Token 预算 |
| 专题累计证据 | 分页持久化，不以 8 条为总上限；每段综合可使用不同证据 |
| 整项研究费用 | 统计所有调用和重试，达到预算停止调度，明确剩余工作 |

例如，1000 篇形成大量逐篇记录，先分别综合若干研究维度；最后一段回答引用 8 条代表性证据，不代表整个研究只读了这 8 条。完整研究表及来源链仍可查看。反过来，只有一次 top-8 检索，就不能用这套说法包装成全面研究。

排序先过出处、范围、文本可用性等硬门槛，再考虑问题相关性、直接支持程度、上下文完整性、来源独立性及信息增量。向量相似度不是证据可信度，不宜伪装成“事实置信度”。

本地关键词和向量融合先筛候选，仅在确实需要时对小候选集重排。不能为了节省 Token 而让每个候选都额外经过昂贵模型判断。

## 7. 降低费用与等待时间

- 默认聊天并发为 1；小样本实测服务商稳定后才考虑 2。按服务商全局限流，不让多个窗口各自并发叠加。
- 按 Token 而非文献篇数组批；留出系统提示、历史、输出和推理预算。先比较约 2k、4k、8k、12k 输入预算，再选质量、耗时、成本合适的范围，不直接用最大上下文。
- 现有字节上限是防膨胀保护，不等于 Token 计费。可用对应 tokenizer 时精算，否则标明估算并以服务商 usage 校正。
- 固定输入、正文版本、问题及提取标准相同时复用结果。换问题或改校对正文后，必须检查适用性，不能只按文献 ID 命中缓存。
- 抽取、文献综合、分组综合和最终报告分别持久化；报告超时只重试报告，不重跑全部抽取。
- 对限流和可重试错误退避；超长或输出截断的批次再拆小。保持失败清单，避免空结果冒充成功。
- 将模型网络请求放在数据库事务外；分批落库、分页读取，CPU 密集的分块或索引在工作线程执行。
- 不在用户上传时默认建立昂贵的全库 LLM 图谱。持续研究的固定资料库可逐步积累结构化结果，偶发问题使用按需检索。

成本示例仅用于说明规模：假设 1000 篇各有 12,000 个输入 Token，一次全文遍历就是约 1200 万输入 Token，还未算提示、输出和复核。之后每篇保留 300 Token 摘要虽仅约 30 万 Token，但摘要有损，不能保证回答未来所有新问题。

实际费用按服务商的未缓存输入、缓存输入、输出计价，再加向量和重排费用；推理 Token 是否已包含输出应按服务商口径处理，避免重复计算。预计时长根据实测批次耗时、并发、重试和汇总阶段估算。现阶段不承诺固定节省比例或千篇任务完成分钟数。

## 8. 现有项目如何接上

代码审阅发现已有适合复用的基础，不需要再搭一个独立研究服务：

| 现有模块 | 可复用基础 | 需要补齐的部分 |
| --- | --- | --- |
| `src/main/task-scheduler.ts` | 持久任务、任务项、尝试记录、暂停恢复、事件和产物 | 专题的范围快照、按块处理适配器、全局模型预算和库隔离校验 |
| `src/main/database.ts` | `research_evidence`、版本、产物和主张关联等表 | 关联本次问题与正文版本的覆盖台账；尽量扩展现有结构 |
| `src/main/canonical-content.ts` | 规范正文入口 | 段落级处理单元与版本失效规则 |
| `src/main/evidence-qa.ts`、`evidence-selection.ts` | 关键词与可选向量混合检索、有界证据 | 明确快速回答边界，接入专题累计结果与来源回查 |
| `src/main/ipc/ai-research.ts` | 研究任务、证据包和提取记录 | 当前单轮记录上限及检索式采样不等于全文任务，需新增按块执行路径 |
| `src/main/research-report-execution.ts` | 有界报告分批综合 | 将中间批次和依赖关系从内存移到持久产物，重试不重复付费 |
| `src/main/research-aggregates.ts`、`research-claim-manifest.ts` | 快照统计、输出与来源关联 | 接通专题研究的确定性统计和失效检查 |
| `src/main/mcp/library-tools.ts` | 文献、检索、原文与图谱的只读工具 | AI 可查询进度和来源；启动付费任务须独立权限、预算与幂等键 |

当前问答的 8 条核心证据和 18,000 字节保护是单次问答设计；研究抽取中仍有单轮 80 条记录上限。现有报告分批处理的是已保存记录，不是自动把全部入选原文读完。不能直接向用户宣称已经支持完整的千篇研究。

不先更换数据库或安装完整 GraphRAG/Python 服务。规模要同时看文献数、正文块数、向量数与设备内存；只有测出瓶颈，再选择近似向量索引或外部服务。

## 9. 稳定性与老版本兼容

- 增量迁移，旧提取结果仍可读，标注旧流程或覆盖未知，不自动补造新流程状态。
- 升级不自动触发付费重建；用户确认后才生成新版本，成功后原子切换，旧结果保留可追溯关系。
- 新接口同时更新共享类型、preload、主进程和调用方，避免再次出现前端按钮存在但 API 未导出的错误。
- 任务项使用幂等键和租约；崩溃恢复避免重复结果。服务商请求已完成但本地未落盘时，无法保证绝无重复计费，应记录不确定尝试，并利用可用的服务商幂等能力。
- 停止调度后仍可能有在途调用产生费用；预算预留覆盖在途请求，界面不能声称取消必然免单。
- 校对文字变化使相关提取失效；仅真实页码映射变化通常更新引注显示，不应强迫重跑全文模型。插删页和正文位置变化另行重新解析定位。
- 删除研究派生结果不删除原始文件、OCR 或向量；共享证据按来源依赖清理，防止误删其他专题结果。
- 不把局部报告成功视为全任务成功；搜索范围、导出出处和已存在的引用行为纳入回归。

## 10. 验收：证明有用，而不仅是能跑

先准备 30–50 篇经人工标注的代表性测试文献，再扩展到 100 篇及 1000 篇压力数据。真实付费千篇测试须另行确认范围和预算，不能沿用小批量授权。

测试集覆盖不同长度、OCR 质量、语言、表格、脚注、跨页段落、同名实体与相反观点。1000 篇压力测试不能只复制少量文本；必须包含仅出现于最后一篇、末页或少数材料中的关键证据。

比较同模型、同问题下的现有 top-8 问答、扩展检索与父级上下文、全范围分层研究。图谱方案作为可选对照，不预设必胜。费用相近和覆盖目标相同的比较分别报告，冷启动与缓存复用分开。

| 验收项 | 建议门槛，尚未达到或验证 |
| --- | --- |
| 范围完整性 | 100% 入选文献和处理单元有状态，零静默截断、零失败冒充完成 |
| 引文定位 | 所有输出引文可解析到对应正文版本；正文不匹配必须显式告警 |
| 研究有效性 | 在标注集上分别测相关文献召回、主张支持率和结论遗漏率；召回及支持率暂以至少 95% 为验收目标，需报告样本数与不确定性 |
| 反证与少数观点 | 预埋关键反证不得遗漏；重复转引不能压过独立反证 |
| 可恢复性 | 中断后续跑、报告单独重试、预算暂停、正文变更失效和重复提交均有自动化测试 |
| 性能与费用 | 记录输入输出、缓存、重试、实际账单口径、总时长、首个可用结果时间、批次 p50/p95、峰值内存 |
| 兼容性 | 原文及校对版本不变；既有全文搜索结果、真实页码、摘录、引注和导出回归通过 |

人工评审重点是：能否回答研究问题、观点是否忠于原文、能否发现分歧、追索出处是否方便。模型评分只能辅助，不能作为唯一裁判。100% 处理台账也不等于 100% 事实召回。

## 11. 落地顺序

1. **范围与状态先行**：接通持久任务、全文处理单元、费用预算、失败列表和进度；杜绝假完成。
2. **完成一条可用流程**：选文献、逐篇提取、文献研究表、原文回查、暂停续跑，先用小样本验证效果。
3. **扩大规模与复用**：分层综合、反证保留、缓存失效、增量文献、报告独立重试，并完成 100/1000 篇测试。
4. **再增强图谱**：从有依据的研究记录派生实体与关系，保留消歧、复核和来源；按性能测量结果决定是否引入新索引组件。

每一阶段都以测试和可用功能为完成条件，而不是以页面数量或图谱节点数量作为成果。最终应让用户少操作，让软件多保存可核查的研究过程。
