# 从专题问题到证据摘录

知识图谱用于整理和追查材料，不负责替研究者判定史实。下面以虚构问题
“某地书院的讲学活动是否促进了跨地交游”为例。

## 当前版本的操作

1. 打开“知识图谱”，切到“资料浏览”，其中“材料核验”显示原文与抽取内容。在顶部选择已有研究专题；
   点加号新建专题，或点编辑图标修改研究问题。三个页面共用同一个专题选择。
2. 选择已有材料集，或用公共栏“选择文献”按书籍、标签、文件夹选择文献，再点“提取人物与关系”。
   选择专题会选中该专题所属的材料集；清除专题选择后可以查看未归属的旧材料集。
   查看旧材料不重新收费，打开 AI 面板也不会自动发起付费分析。
3. 新分析会携带当前专题、研究问题和所选文献范围。当前仍是检索证据抽取，
   不是逐章通读全库；请勿把完成提示理解为所有文献已逐字分析。
4. 在“材料核验”搜索事件、人物或原文措辞。表头支持排序，状态筛选可查看
   待核验、已确认和已排除的材料。没有可映射实体的记录也会显示。
5. 点“原文”回到文献；点“核验 / 修订”在右侧查看完整抽取字段和考证备注。
   确认、退回待核验、修订、排除都针对材料记录，不自动判定跨文献人物是同一个人。
6. 点“存入专题”，分别记录证据用途和研究者按语。可以保存为支持材料、反证、
   背景材料或相互矛盾的记载；未核验材料保存时会保留待核验标记。
   原文、页码、定位信息、抽取字段快照与研究者按语分别保存，不用按语覆盖原文。
7. 切到“专题研究”，直接在“证据摘录”查阅当前专题的材料。在“大纲整理”中
   按论证问题组织摘录，再使用已有的研究导出或写作功能。

## 图与表各自回答什么

- 人物考察：某人在哪些材料中出现？点对象回看相关原文，检查同名、别名和时代。
- 地点考察：同一地点关联了哪些人物与活动？不要直接把地名相同当成古今地理位置相同。
- 事件考察：同一活动有哪些记载？比较时间、参与者和叙述差异。
- 关系考证：一条关系有何原文依据？共同出现在一段材料中不等于师承、亲属或合作。
- 时间线索：检查原始时间表述和先后冲突，不把 AI 推测日期冒充明确纪年。
- 关系网络：用于找到值得回查的路径，不用连线数量证明社会关系强弱。

例如，同在书院讲学只能先作为交往线索；是否存在长期师承，还需书信、传记或
其他独立记载支持。两部文献若互相转抄，也不能直接计为两份独立证据。
搜不到材料不代表历史上没有发生；还需检查范围、异名、OCR 和抽取覆盖。

## 与 AI 史记方法的关系及边界

参考 [shiji-kb 的事件抽取脚本](https://github.com/baojie/shiji-kb/blob/main/kg/events/scripts/extract_events.py)
所采用的来源定位、分单元处理和持久保存原则。当前专题证据入口为独立实现，
未复制该项目的代码或提示词。完整技术差距见 [工作流对照](shiji-workflow-comparison.md)。

当前抽取仍有每次最多 80 条代表证据的限制；图谱一次载入材料和绘制实体也有上限，
超出时显示覆盖提醒。选择器支持加载超过 1000 篇文献，不等于已验证千篇全文抽取质量。
逐章全文建库、持久检查点、实体消歧与跨文献关系审核尚不能宣称完成。

## 回归测试

先 `npm run build`，再执行 `node scripts/research-graph-ui-regression.js --topic`。
测试使用隔离配置与虚构 IPC 数据，不读取用户文献，不调用模型。覆盖来源型记录、
专题问题保存、状态筛选、保存失败后重试、证据与按语分离，以及 1003 篇文献的选择
分页与父子文件夹筛选。真实 SQLite 的摘录保存由 `npm run test:research` 覆盖。
