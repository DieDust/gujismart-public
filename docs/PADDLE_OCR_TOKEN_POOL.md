# PaddleOCR 多 Token 接力

GujiSmart 支持在飞桨云端 OCR 配置中保存多个 API Token。该功能用于长文献和大批量导入：当前账号达到日额度后，任务自动切换到下一个账号继续执行。

## 用户行为

- Token 逐个添加，使用系统安全存储加密保存在本机；设置页只显示名称和末四位。
- 软件默认连续使用当前 Token，不会为了“平均分配”而频繁切换账号。
- 飞桨返回 `429` 时，将当前 Token 标记为“今日额度已用完”，在次日额度重置前跳过。
- 飞桨返回 `403` 或明确的 Token 无效/过期错误时，将当前 Token 标记为“Token 无效”。重新启用或重新添加后可再次尝试。
- 用户可以随时停用、启用或删除 Token。删除原有的单 Token 配置时，如果池中还有其他 Token，软件会自动提升下一个 Token，旧数据库无需迁移。

## 长 PDF 与断点续跑

飞桨官方托管 API 的单文件处理上限为 100 页，超过后只处理前 100 页。GujiSmart 因此按最多 100 页生成任务，避免“任务显示成功但后续页面没有结果”。

成功分段会通过原有 `onChunkComplete` 链路立即写入页面 OCR 结果。若某个分段在提交或轮询阶段因额度失败：

1. 保留此前已经写入的分段；
2. 标记并跳过失败 Token；
3. 使用下一个已启用 Token 重交当前分段；
4. 所有 Token 都不可用时暂停并给出明确错误，用户添加 Token 后可继续 OCR 未完成页。

软件不会按单页切分。正常情况下每段最多 100 页；只有 PDF 单段超过上传大小限制或文件结构异常时，才沿用既有 PDF 裁切逻辑缩小分段。

## 官方限制

根据飞桨 2026-02-10 更新的规则，每个用户针对每个模型每日最多解析 3000 页；超额返回 `429`，Token 错误返回 `403`。官方文档没有公开“查询当前剩余页数”的接口，因此 GujiSmart 不能在请求前准确知道还剩 900 页或 90 页，而是在额度错误出现后仅重试失败分段。
